## 测试步骤（逐步执行，每步留证）

### 第一段：只读侦察（验工具链前半）
1. `tier-of` 算 DB3K_505.db3 的代级（schema 哈希前 12 位），记录输出。
2. `lookup` 反查该库被哪些想定引用（台账为空也是合法结果，如实记录）。
3. `guard-check` 预审：影响平台数填 5（应放行 exit 0）；再填 11（**应拒绝 exit 3**）——两次都跑，验证递归删除上限闸好使。
4. 尝试对 DB3K_505.db3 直接 `copy-for-edit` 之外的写操作不存在于工具——改为验证官方库保护：对 DB3K_505.db3 跑 `guard-check`（**应拒 exit 4**）。

### 第二段：合规复制（验决策树与命名闸）
5. 按决策树：DB3K_505.db3 是官方库+无法判断引用归属 → 必须复制再改。执行：
   `copy-for-edit <源库> --方案 工具链试手 --描述 首测 --owner-approved "owner 2026-09-17 口头批准试手测试"`
   预期产物名形如 `DB3K_505-工具链试手-20260917-首测-1.db3`。
6. 故意违章各试一次，验证闸会拦：
   - 不带 `--owner-approved`（**应拒 exit 5**）；
   - 命名不合规时工具应拒（exit 2）——如果工具允许了不合规命名，记为缺陷。
7. 确认复制产物旁生成了 `.bak_before_*` 备份，用 `tier-of` 对比副本与源库 schema 哈希应一致、文件哈希应一致（刚复制未改时）。

### 第三段：小步试改（验自救路径，只动副本）
8. 用 sqlite3 只读先查副本库结构（`sqlite3 "file:<路径>?immutable=1"` 或 Python sqlite3 只读连接），挑一个**勾选编码类**字段（owner 实测最高发的改坏区）和一张小表。
9. **一次只改一处**：改一个字段值 → 立即用 SQL 读回验证写入生效 → `audit` 写一条审计（操作者写你的对话名）。再改第二处 → 再验证 → 再审计。禁止批量改完再验。
10. 改完后 `tier-of` 重算副本文件哈希（应变，schema 哈希应不变），`ledger-record` 把「本测试想定（虚构路径即可，注明是试手测试）→ 副本库」登记一条台账，`lookup` 副本库应能查到这条。
11. **回退验证**：把第 9 步的改动逐处改回原值，再验读回=原值。这就是 owner 验证过的自救路径（查看器卡死时唯一可靠解法=改回去），本次先在 SQL 层演练。

- **改坏就改回**：任何一步出现意外（写入后读回不对、库打不开、工具报错看不懂），立即停止继续改，先把副本恢复原状，再记录现象。绝不带病前进。
