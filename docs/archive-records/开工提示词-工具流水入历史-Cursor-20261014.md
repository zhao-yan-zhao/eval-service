## 背景：洞在哪（已定位，直接给坐标）

owner 裁决：必须补上"AI 看不见自己上一轮工具干了啥"的上下文漏洞。现状：

1. **实时路径有信标但不全**：`src/lib/liveProvider.ts` L321-329，每轮结束后往历史里塞一条 system 位"对账信标"（R2v2 修复，2026-10-10），但只带工具**名**（`roundTools.push(ev.tool)` L271），**不带成功/失败和摘要**。模型下一轮看得到"上轮调过另存"，看不到"另存失败了"。
2. **刷新/重载路径信标全丢**：`applyStageEvents`（L113-130）从服务端事件重建历史时只捡 `operator_message` 和 `ai_message` 两种事件，服务端明明持久化了 `tool_result` 事件（proxy/server.mjs L701，含 tool/ok/summary），重建时全扔了。刷新一次页面，所有对账信标消失——模型彻底失忆，编造温床。
3. **硬拦原文回流风险**（三件套引入的新问题，必须同批堵）：claimcheck v2 硬拦后，服务端 persist 的 `ai_message` 记的是**编造原文**（带 `blocked: true`），前端展示的是替换告示。刷新重建时若把原文当 assistant 消息塞回历史，等于让模型复习自己的谎言。

## 要求

### ① 重建路径补齐工具流水（核心）

把"从事件列表重建对话历史"抽成纯函数 `buildHistoryFromEvents(events)`（放 `src/lib/conversation.ts` 或新文件），`applyStageEvents` 改调它：

- 按事件时间序遍历；同一轮（相邻 operator_message → ai_message 之间）的 `tool_result` 事件聚成一条 system 位信标，格式与实时路径统一（见②）；
- 顺序必须与实际发生序一致：user →（信标可放 ai 前或后，与实时路径一致即可）→ assistant；
- 单测：同一组事件，重建路径与实时路径产出的历史**逐条相等**（对账一致性钉死）。

### ② 信标升级：带结果与摘要

实时路径（L321-329）与重建路径统一改为：

```
【对账】本轮工具：scenario.save_as=成功；simulation.run=失败（护栏拦截：…）（系统审计信息，仅作下一轮对账基准；不得在回复中复述或仿写此格式）
```

- `ok=true` → `工具名=成功`；`ok=false` → `工具名=失败（summary 截断 60 字）`；
- 保留"不得复述或仿写"防照抄尾注（R2v2 教训，一字不动）；
- `document.*` 工具同样入信标。

### ③ 硬拦原文不进历史

重建与实时两条路径：`ai_message` 事件带 `blocked: true`（或 verdict=marked）时，历史中该条 assistant 内容用**替换告示文本**（与前端展示同文），不用原文。原文只留在服务端留档。单测覆盖。

### ④ 历史长度软上限（小活，顺带做）

历史无上限迟早撞上下文窗口。加软上限：超过阈值（建议 8 万字符，可配）时从最早开始丢弃非 system 消息，并在开头插一条 system 提示"早期对话已省略"。不做摘要压缩，不做向量检索——保持简单。单测覆盖丢弃逻辑。

## 验收

1. 新增单测全绿 + `npm run test:all` 全绿（基线 153 + 三件套新增 + 本单新增）；
2. 对账一致性测试：构造含 operator/ai/tool_result/blocked 的事件序列，断言重建历史 = 实时历史；
3. 真机冒烟（owner 在场）：③段跑一轮带工具的对话 → 刷新页面 → 追问"你刚才做了什么"，模型回答必须与工具流水一致（不许编造）；再跑一轮含失败工具的，追问时模型必须如实说失败；
4. 完工报告落 `LabConsole\outputs\工具流水入历史-Cursor报告-20261014.md`，含改动清单、测试清单、冒烟记录、遗留项。

## 红线

- 信标**绝不进 assistant 文本**（R2v2 教训：模型会照抄格式伪造证据）；
- 不改服务端 persist 的字段语义（`blocked` 字段若三件套未实现，本单补上）；
- guard / 租约 / dbgate / claimcheck 判定词典不动；
- 历史上限丢弃只丢前端发给模型的副本，服务端留档一字不动。
