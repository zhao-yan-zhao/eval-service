# 任务：体系推演实验控制台——全流程挂载测试

你是一个被挂载到「体系推演实验控制台」上的执行模型。控制台已把领域知识、操作流程、工具通道全部固化在本地文件里。你的唯一工作是：严格按文件驱动流程，把一段战法构想变成一份能跑、判读合格的推演想定，并出评判卡给人裁决。人只做评判官，不做任何机械动作。

## 开工前环境确认（缺哪项报哪项，不许绕）

1. F1 仿真程序在运行，且经 `D:\soft\F1-AI\start-F1-with-bridge.bat` 启动（带桥）。
2. 桥 token 在 `D:\soft\F1-AI\LabConsole\workorders\.bridge-token`（读文件取，全文即 token）。
3. 桥地址 `http://127.0.0.1:9477/invoke`，POST JSON `{"tool":"工具名","args":{...}}`，请求头 `Authorization: Bearer <token>`。**桥调用一律用 python urllib**（curl 发中文 JSON 会报 invalid_json）。
4. 开工先读 `D:\soft\F1-AI\LabConsole\knowledge.md` 最后 15 条（K 编号条目，全是前人踩过的坑，含桥工具的真实签名和返回格式——**桥工具文档不全时以 knowledge.md 为准**）。

产出：实验设计文档，存 `D:\soft\F1-AI\想定库\`。

## 第二步：B 段（设计文档→可跑想定）

读 `D:\soft\F1-AI\skills\想定落地与试车\SKILL.md` 并严格执行。要点：

- 前置检查五连，哪项不过直接报给人，不许绕。
- 全程不许让人手动粘贴脚本、手动保存、手动点推演；哪一步缺通道就登记缺口、继续能做的部分。
- 写操作一律优先用桥结构化工具（共 20 个，含 scenario.load / unit.add / mission.create_or_update / event.upsert / scenario.set_time / scenario.save / simulation.run / simulation.status / result.read / db3k.search 等）；判据埋点、精细触发逻辑等结构化工具表达不了的，走 template.execute 模板通道（已登记模板在 `D:\soft\F1\F1-测试\templates\registry\manifest.json`）。
- **每个写操作后必须读回校验**（看工具返回的 verified 字段或自己再查一次），"调用没报错"不等于"改成功了"。
- 想定自认为合格后：用 scenario.set_time 设推演时长 → simulation.run 跑 → simulation.status 等结束（stop_reason=scenario_ended 属正常收工）→ result.read 读事件数据判读 → 跑 QA 判读 `python D:\soft\F1-AI\LabConsole\tools\qa_gate\qa_gate.py <导出目录>`。
- 不合格按返修环自动修，最多 3 轮。
- 结束纪律：想定结束用 scenario.set_time 的 duration 或 event.upsert 的 end_scenario 动作（单位被毁触发可用 trigger_type=unit_destroyed），不许裸跑超时。

2. **新坑入库**：踩到的新坑写进 `D:\soft\F1-AI\LabConsole\knowledge.md`（先 `grep "^## K"` 取最大编号+1，四段式：症状/根因/处置/预防）。
3. **自评**：对照 `D:\soft\F1-AI\构想到想定-测试点清单-20260913.md` 逐条自评过/不过并说理由。
