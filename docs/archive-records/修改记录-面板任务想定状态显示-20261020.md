## 二、数据口径（关键约定）

1. **槽位**：读轮次 `manifest.pooling.slotId`（首次改动类工具调用时由 proxy 落盘，重启后从 manifest 恢复）。未绑定 → `slotId=null`，前端显示「未绑定」。
2. **当前想定**：跟踪表按**槽**（不是按轮次）记录 `title/path`。来源：
   - `scenario.load` / `scenario.save` 成功 → 记录路径（load/save 的 `args.path`；save 空路径=覆盖写保留原路径）与标题（桥返回内层 title 类字段，缺省回落文件名去扩展名）。
3. **落盘（dirty）**：`scenario.load` / `scenario.save` 成功 → `dirty=false`；其余 `tier==='model'` 的写类工具成功（unit.* / mission.* / doctrine.* / event.* / scenario.set_time / referencepoint.add / lua.exec）→ `dirty=true`。`simulation.*`（SIM 级）与 `db.*`（DB 级）**不计**想定内容修改。
4. **代理重启失忆**：跟踪表是内存态，重启后到下一次 load/save 前 `dirty=null`（前端显示「未知」）——这是交接单认可的「纯 proxy 记账」口径；跨重启持久化留作第二阶段。
