## 一、路线变更的核心判断

**v1 假设"必须新写 C# 批量服务"，本轮核实证伪：执行原语已全部存在于 F1 的 AiAssistant 工具面，控制台的主体应当是"Kimi + 技能包"，而不是新 C# 模块。**

已核实的工具面事实（行号证据）：

| 能力 | 工具/实现 | 证据 |
|---|---|---|
| 跑仿真 | `simulation.run` / `stop` / `status` | `ToolRegistry.cs` L193–208 |
| 读结果 | `result.read`（按 RunId 读 CSV 化结果） | `ToolRegistry.cs` L210 |
| 保存想定 | `scenario.save`（走写路径审批门） | `ToolRegistry.cs` L191 |
| 建场（结构化） | `unit.add` / `mission.create_or_update` / `doctrine.set` / `event.upsert` | `ToolRegistry.cs` L117–177 |
| 读态势（只读） | `scenario.get_summary` / `unit.status` / `contact.query` 等 | `ToolRegistry.cs` L63–106 |
| 每轮 CSV 隔离 | `CoreSimulationGateway`：**已实现** `EnableCsvExport(isolatedPath)` 每 RunId 独立目录 + 终态恢复 ExportDir | `CoreSimulationGateway.cs` L14 注释 F.3、L42、L533–536 |
| 后台跑批 | 脉冲循环走 `Task.Run`+取消令牌，成功/失败双信号闩锁，未确认终态**绝不标 Succeeded** | `CoreSimulationGateway.cs` L440–530 |
| 安全层 | 工具白名单 + schema 校验（显式封禁 `lua.execute_free`/`shell.exec` 等）+ 变更恢复 + 备份 | `JsonSchemaAndSecurity.cs` L174/L188 |
| 工作副本重载 | `TryReloadFromFile`（迭代间重置状态用） | `CoreF1AutomationFacade.cs` L581 |

**含义**：v1 的 D-1（批量适配器）、D-2（程序化导出隔离）两项最大工程量，F1 侧**已经做完并且带纪律**（终态恢复、失败不标成功与底稿验收底线同构）。`simulation.run` 按脉冲数跑（`durationPulses`），跑满全场=传足够大的脉冲数，是否遇 `HasEnded` 自止列 D1 验证。

## 二、v2 架构：三层

```
┌─ Layer 3 统筹与流程驱动：Kimi（本端，零 F1 代码）────────────────┐
│  候选管理 / Lua 静态检查+三元组哈希+审批单 / 串行跑批队列          │
│  （逐轮 runbook → simulation.run → status 轮询 → 超时判负）       │
│  manifest 血缘落盘 / 失败记录 / 过夜批 Automation 看门狗           │
├─ Layer 2 工具包：Python 技能包（DeepSeek 写 + Codex 审，手册流水线）┤
│  静态黑名单检查器 / CSV 归一化 / 指标计算 / 图表报告 / 归档工具      │
├─ Layer 1 执行原语：F1 现有 AiAssistant 工具面（零新 C#）───────────┘
│  simulation.run·stop·status / result.read / scenario.save /
│  unit.add / mission.create_or_update / doctrine.set / event.upsert
```

**驱动入口（D1 上午第一件事定型，四选一+组合）**：

- **(a) 主选：F1 助手聊天面板执行 runbook**。我产出 JSON 级确定的工具调用序列，人贴入面板（面板 Provider 即手册已验证的 DeepSeek），面板 LLM 当"执行手"。分工恰好符合章程：我规划+审批+验收证据，面板执行。
- **(b) 待核：任务库注入**。助手有 TaskOrchestrator + `assistant.db`（`AiAssistantPaths.cs` L21），若任务可由文件/DB 注入则免去人工粘贴，D1 花 1 小时核实，可行则升级为（a'）。
- **(c) 备案：7777 Lua socket**。监听 0.0.0.0（`LuaServerManager.cs` L94），底稿原禁用；若启用需 owner 撤销禁令 + Windows 防火墙限 127.0.0.1。仅在（a）（b）均不通时启用。
- **(d) 候选构建补充通道：人把已批 Lua 贴入 F1 Lua 控制台执行**。零新攻击面，本来就是"人工动作"清单内，与审批链天然契合。

## 三、手册机制并入（按 owner 指示，裁剪后适用）

**裁剪原则**：手册是通用模板；F1 主仓有在途 R2B/R2C，不引入 main/dev 全量分支模型。

1. **工具包开发走流水线**：LabConsole 技能包（Python）从 integration `be51696` 拉 `labconsole-dev` 分支，任务分支 `task/lab-*`；DeepSeek(aider) 写 → 项目测试 → **Codex 无头审核**（命令姿势照手册 §2，三个坑已排）→ 通过合并；单任务 3 轮熔断，涉删除/架构升级人工。
2. **审查分级对接章程**：Codex 审 = 中低风险（Python 工具、脚本、文档）的独立审查——满足铁律一"写验不同人"；**高风险项（Lua 审批链设计、7777 启用、任何 F1 侧 C# 改动）仍送 sol[max] 或 owner 裁决**，Codex 不替代章程高风险闸门。
3. **项目文件**：`D:\soft\F1-AI\LabConsole\` 下建 `TASKS.md`（任务+依赖+并行标注）、`LOG.md`（每轮时间/任务/结论/token 成本）、`FEEDBACK.md`（owner 干预通道）、`PAUSE` 文件机制照手册。
4. **定时任务**（批准后创建）：①「LabConsole 工具包开发循环」cron `17 9,11,13,15,17,19 * * *`（Asia/Shanghai，local_conversation，工作目录 `D:\soft\F1-AI`）；②「每日打包」cron `11 20 * * *`——五天窗口内它产出的是**每日演示快照**（LabConsole 工具包 + 当日 runs 归档索引 + CHANGELOG），每晚供 owner 验收，与开发零阻塞。
5. **预算**：DeepSeek 写码 ≤¥10/天，超限停循环并通知（手册 §3.7）；Key 只经 `secrets.env` 读取，不进任何对话/日志/交付物。
6. **并行度**：手册上限 3 并行；本工具包任务小，实际 2–3 个短任务即完成，D1 下午即可开工。
