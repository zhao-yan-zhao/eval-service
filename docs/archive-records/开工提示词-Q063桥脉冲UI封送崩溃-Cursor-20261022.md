## 一、崩溃实锤（两次，同一行号）

两次弹窗截图留档（10-21 20:48 看门狗 popup-text-20261021-204841-279.txt；10-22 09:09 owner 截图）：

```
InvalidOperationException: This operation has already had OperationCompleted
called on it and further calls are illegal.
   at System.Windows.Forms.Control.EndInvoke(IAsyncResult asyncResult)
   at F1.AiAssistant.F1Core.Simulation.CorePulseEngine.RunCore[T](Func`1 action)
     CorePulseEngine.cs:line 446
   at ...CorePulseEngine.AdvancePulses(Int32 n, ...)  CorePulseEngine.cs:line 139
   at ...CoreSimulationGateway.RunPulses(SimulationJobState job, Int32 pulses, ...)
```

诱因高相关：崩溃前 4~8 分钟槽 1 窗口被人工开过模态对话框（加载想定/武器分配/WRA/保存推演——看门狗 popups.jsonl 有时间线）。模态对话框有自己的消息泵，加上窗口句柄重建时 WinForms 会重放封送队列，`ControlThreadAsyncResult` 可能被**重复 Complete**；之后 `EndInvoke` 见到"已 Complete"状态就抛上面这个异常。异常炸在异常处理器里（"Error in Exception Handler!"），模态崩溃弹窗卡死 UI 线程 → 无人值守跑批整局报废，且**作业状态里不留失败原因**（面板侧只能看到"零脉冲 Failed"）。

## 二、根因（监理已定位，直接给结论）

`CorePulseEngine.RunCore<T>`（CorePulseEngine.cs:431-449）用的是 `BeginInvoke` + `WaitOne(AsyncWaitHandle)` + `EndInvoke` 三件套。**EndInvoke 对每个 IAsyncResult 只允许调用一次，且对"已被重复 Complete"零容忍**——这正是崩溃点。UiMarshalTicket 的 Cancel 只保证超时路径不重复执行 action，管不到 WinForms 内部对 AsyncResult 的重复完成。

## 三、修复方向（推荐方案，你有更稳的可以说理后替换）

**去掉 EndInvoke，改用自管理完成源**——BeginInvoke 只当"投递"，结果/异常由我们自己捕获：

```csharp
private T RunCore<T>(Func<T> action)
{
    if (_ui == null || !_ui.InvokeRequired)
        return action();

    var ticket = new UiMarshalTicket();
    var done = new TaskCompletionSource<T>(TaskCreationOptions.RunContinuationsAsynchronously);
    _ui.BeginInvoke(new Action(() =>
    {
        if (!ticket.TryBeginExecution()) return;
        try { done.TrySetResult(action()); }
        catch (Exception ex) { done.TrySetException(ex); }
    }), null);
    // 超时：ticket.Cancel() + throw TimeoutException（语义与现役逐字一致）
    // 等待 done.Task；不再触碰 ar.AsyncWaitHandle / EndInvoke
    ...
}
```

要点：
1. **任何路径都不调用 EndInvoke、不等待 ar.AsyncWaitHandle**——重复 Complete 再也炸不到我们。
2. 超时/取消语义逐字保留（UiInvokeTimeout、ticket.Cancel、TimeoutException 文案）。
3. `action()` 抛的异常原样经 done 传回调用方（现在异常被吞进"Error in Exception Handler"模态框——**这是 II 条的根**）。
4. 顺带防御：BeginInvoke 前查 `_ui.IsHandleCreated`，句柄没了走明确异常（`ui_handle_gone`），别投递进虚空。
5. `AdvanceOnePulse`/`AdvancePulses`/其他 RunCore 调用方**零改动**（签名语义不变）。

## 四、第二件事：作业失败必须留原因

现在起跑即死（零脉冲 Failed）时作业状态里没有失败原因，面板 AI 只能说"没留下失败原因"（10-21 会话实录三次）。要求：

- `CoreSimulationGateway.RunPulses`（及同类作业入口）catch 到异常时，把**异常类型+Message+（截断的）栈首行**写进 SimulationJobState 的失败字段；
- `simulation.status` / `simulation.recover` 的桥响应把该字段透出来（proxy 不动，桥响应多一个字段即可，proxy 现有透传逻辑自动带出）；
- 这样 Q-066 的完局守望者上线后能把"为什么失败"直接推到面板。
