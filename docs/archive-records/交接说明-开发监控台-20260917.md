## 3. 数据契约（monitor-state.json 字段口径）

```json
{
  "project": "体系推演实验控制台",
  "updatedAt": "ISO 本地时间",        // 每次写入必更新
  "heartbeatAt": "ISO 时间",          // 心跳+每次写入都更新；失联判定认它（K28）
  "kimi":     { "state": "dispatching|waiting_review|idle|paused|blocked", "detail": "一句话" },
  "deepseek": { "state": "running|idle", "detail": "...",
                "running": 0, "waitingReview": 0 },
  "codex":    { "state": "running|idle", "detail": "...",
                "reviewing": 0, "rejectedWaiting": 0 },
  "events":  [ { "time":"HH:mm", "actor":"kimi|deepseek|codex",
                 "kind":"dispatch_dev|dispatch_review|decision|dev_done|review_pass|review_fail|escalate|notice",
                 "title":"必填", "detail":"可选" } ],   // ≤20 条，删最旧
  "stats":   { "kimi":{"dispatch":0,"decision":0}, "deepseek":{"devDone":0}, "codex":{"reviews":0 } }
}
```

**计数契约（K154，owner 2026-09-17 界面投诉立的硬规则）**：四个计数字段每轮必写、整数真实值、**0 也要显式写 0**、不许省略、不许一律写 0。口径 = 按 TASKS.md 任务板实时计数：

- `running` = 已点火且日志仍在生长的施工线程数（tasklist/日志大小双验活，K29）
- `waitingReview` = 施工已交付待送审 + 审理结论待领
- `reviewing` = 已送 codex/lj 未出结论
- `rejectedWaiting` = 审理 REJECT 待返修/待二审

**流程图亮灯逻辑**（Widget 内）：Kimi→DeepSeek 段在 `kimi.state=dispatching` 或 `deepseek.state=running` 时亮；DeepSeek→Codex 段在 `kimi.state=waiting_review` 或 `codex.state=running` 时亮。**所以写 state 就是在点灯**——干活时必须把对应方写成 running/dispatching，收班写回 idle（灯只反映真实在跑，"活着"由心跳表达）。

**stats 累加规则**：追加 events 时同步累加——dispatch_dev/dispatch_review→kimi.dispatch；decision→kimi.decision；dev_done→deepseek.devDone；review_pass/review_fail→codex.reviews。
