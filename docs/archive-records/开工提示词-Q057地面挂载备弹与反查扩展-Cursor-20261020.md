## 一、背景（为什么做）

1. 面板①段（构想澄清）实测报："发射阵地单车备弹量无依据，弹药主表无备弹字段，查不到"。
2. Kimi 已实查破案：**数据在库里，桥没开口**。地面单位的待发武器与备弹不在主表，在挂载/弹舱链表：
   - 待发链：`DataGroundUnitMounts(ID=平台ID, ComponentID→DataMount.ID)` → `DataMount(ID, Name, Capacity, ROF, MagazineROF, MagazineCapacity)` → `DataMountWeapons(ID=DataMount.ID, ComponentID→DataWeaponRecord.ID)` → `DataWeaponRecord(ID, ComponentID=武器ID, DefaultLoad, MaxLoad, ROF, Multiple)` → `DataWeapon(ID, Name, …)`
   - 备弹链：`DataGroundUnitMagazines(ID=平台ID, ComponentID→DataMagazine.ID)` → `DataMagazine(ID, Name, Capacity)` → `DataMagazineWeapons(ID=DataMagazine.ID, ComponentID→DataWeaponRecord.ID)` → 同上接 DataWeaponRecord→DataWeapon
   - 舰/潜/设施同构：`DataShipMounts/DataShipMagazines`、`DataSubmarineMounts/DataSubmarineMagazines`、`DataFacilityMounts/DataFacilityMagazines`（表名已核实存在）。
3. 实证数据（DB3K_505.db3，只读，可直接用作单测断言参照）：
   - `M142 HIMARS` groundunit **187**（2x NSM 型）：架"Naval Strike Missile (NSM) Double" Capacity=2 → 武器 RGM-184A NSM Block 1，DefaultLoad=2 MaxLoad=2；**弹舱 0 个**。
   - **189**（GMLR 型）：架"GMLR Pod" Capacity=6 → M31 GMLRS [90kg HE]，DefaultLoad=6 MaxLoad=6；弹舱 0 个。
   - **188**（标 PrSM 实挂 M30A1 GMLRS，DefaultLoad=0 MaxLoad=6 Multiple=6——库条目如此，如实返回即可）。
4. 同时 db3k.relations 现有两个**设计边界**要扩：
   - `relation:'loadouts'` 仅 aircraft（Db3kQueryGateway.cs:591-600，注释明示 DB3K 无舰/地面挂载方案表）——地面/舰的"挂什么"在 mounts 链，不在 loadouts 链，所以本单**新增 `relation:'mounts'`**，不动 loadouts。
   - 武器→平台反查 `R_PLATFORMS_BY_WEAPON`（Db3kSqlTemplates.cs:341）仅走飞机挂载链（DataWeaponRecord→DataLoadoutWeapons→DataAircraftLoadouts→DataAircraft），地面/舰/潜/设施武器反查 0 条误人——本单扩链。

## 三、接口契约（单测要锁死）

### 3.1 `db3k.relations {entity_type, id, relation:'mounts', limit?}`

- entity_type ∈ groundunit / facility / ship / submarine（其余类型 → 既有 `db3k_entity_unsupported` 口径）。
- 返回 JSON 结构：

```json
{
  "ok": true, "entity_type": "groundunit", "id": 187, "relation": "mounts", "readonly": true,
  "mounts": [
    {"mount_id": 3537, "mount_name": "Naval Strike Missile (NSM) Double", "capacity": 2,
     "weapons": [{"weapon_id": <int>, "name": "RGM-184A NSM Block 1", "default_load": 2, "max_load": 2, "rof": 3}]}
  ],
  "magazines": [],
  "note": "magazines 为空=只有架上待发，打光即完"   // 0 条时给显式 note，参照既有 relation_no_match 风格
}
```

- 数量口径：武器数量取 `DataWeaponRecord.DefaultLoad/MaxLoad`；架容量取 `DataMount.Capacity`；弹舱容量取 `DataMagazine.Capacity`。**不回传 BLOB 列**，安全口径与 detail/search 同级。
- 多表缺失保护：requiredTables 按链登记，缺表走既有降级+note。

### 3.2 武器→平台反查扩展

- `db3k.relations {entity_type:'weapon', id, relation:'platforms'}`：在既有飞机链之外，补地面/舰/潜/设施链：
  `DataWeaponRecord(ComponentID=武器ID)` → `DataMountWeapons(ComponentID=wrec.ID)` → `DataMountWeapons.ID` → `Data{GroundUnit|Ship|Submarine|Facility}Mounts(ComponentID=mount.ID)` → 平台表。
- 返回项带 `platform_kind` 字段区分来源链；飞机链结果保持原样不回归。
- 0 条时显式 note（现有"relation_no_match"风格）。
