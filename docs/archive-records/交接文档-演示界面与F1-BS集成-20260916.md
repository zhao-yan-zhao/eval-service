```
 ├─ http://127.0.0.1:8085/             F1-BS 前端（完整编辑器，mode=edit 属主窗口）
 └─ http://127.0.0.1:7177              demo-ui AI 代理（DeepSeek Key 在 demo-ui/proxy/.env）

后端栈（D:\F1BS-run\）
 ├─ nginx-1.24.0        :8085  静态托管 html/（F1 前端 + /demo/）+ /tts/ 反代 Java
 ├─ java (hn-deduction) :9205  后端 API（引擎生命周期管理）
 ├─ emqx-5.3.0          :1883 (MQTT) :8083 (MQTT over WS) :18083 (控制台)
 ├─ Redis-x64-3.0.504   :6379
 └─ 推演引擎 F1.exe      每次"进入模块"拉起一个，Lua WS 端口 10000+ 递增
```

**引擎工作机理（理解 attach 的前提）**：

- 前端 `startEngine`（HTTP GET `/deduction/scenarioSchema/startEngine`）→ 后端拉起 F1.exe，返回 `{runGuid, mqttIp, mqttPort}`
- 引擎启动后通过 MQTT 发布一次 `setWebsocketPort_<runGuid>`（含 Lua WS 地址，ws://局域网IP:100xx），之后持续在 `FrameData_<runGuid>` 主题推帧数据
- 前端以 runGuid 为 serverId 订阅上述主题；Lua WS 用于发 Lua 命令（加载想定等），帧渲染全靠 MQTT 帧数据
- Lua WS 服务是引擎内 TcpListener 每连接一个 Task，**天然多客户端**

## 3. attach 观战模式（③段小窗与完整窗口同引擎同步）

### 3.1 设计

| 角色 | 路由 | 行为 |
|---|---|---|
| 属主窗口（完整界面） | `#/scenario/editor?mode=edit` | 正常 startEngine/复用；引擎参数 + Lua WS 地址写入 localStorage `f1_lastEngine` |
| 观战窗口（demo 小窗） | `#/scenario/editor?mode=attach` | 不启引擎；轮询 localStorage `f1_lastEngine` 挂载；不弹"选择想定"；退出不调 exitEngine |

`f1_lastEngine` JSON 结构：`{runGuid, mqttIp, mqttPort, ts, socketip, socketport}`

### 3.2 改动文件（F1 前端，**工作区副本**，F1-BS 目录源码未动）

源码位置：`D:\soft\F1-AI\_inspect_frontend\extracted\源码\deduce_code\`（来自 `D:\soft\F1-BS\压缩包备份\源码\前端源码.rar`，已验证与 9-14 部署版同源）

- `src/views/scenario/editor/index.ts`
  - `bootstrapEngine()`：attach 分支 → `attachToSharedEngine()`
  - `publishEngineInfo()`：属主把 runGuid/mqtt 写 localStorage（复用分支和新启分支都调）
  - `shareWsAddrToLocal()`：Lua WS `on("open")` 时把 socketip/socketport 并入 localStorage（覆盖所有建连路径）
  - `attachToSharedEngine()`：读 localStorage 直接 `setEngineParams` 复用；没有则 3 秒轮询
  - `startAttachWsWatcher()`：轮询 WS 地址自建 Lua WS；45 秒拿不到则 `showLoading=false` 强制退出加载动画（帧数据走 MQTT 不受影响）
  - `mounted()`：attach 模式跳过会话恢复与"选择想定"弹窗
  - `exitEditor()`：attach 不调 exitEngine；属主退出时清除匹配的 f1_lastEngine
  - `beforeUnmount()`：清理 attachTimer / attachWsTimer
- `src/router/index.ts`：路由守卫 attach 豁免 exitEngine；属主离开编辑器时清除 f1_lastEngine

### 3.3 为什么必须同源（血泪教训，勿走回头路）

1. **EMQX retained 消息本部署存不住**（retained 列表恒为 0）：引擎只发一次 `setWebsocketPort_<runGuid>`，晚订阅的 attach 窗口永远收不到 → 必须由属主窗口经 localStorage 转交 WS 地址。
2. **Chromium 存储分区**：demo-ui 在 5174、iframe 在 8085 时，跨站 iframe 的 localStorage 被分区，读不到顶层 8085 标签写的 `f1_lastEngine`（实测 null）。**所以 demo-ui 必须部署在 8085 同源下**（`/demo/`），iframe 变为 first-party 才能握手。

## 7. 坑位速查（全是踩过的，别再踩）

### 7.1 引擎/后端
- 每点一次"进入模块"后端就起一个 F1.exe（≈1.1GB），退出模块/停栈记得回收（停止 bat 已含）
- EMQX `emqx.cmd stop` 经常无效 → `taskkill /F /IM beam.smp.exe erl.exe epmd.exe`
- EMQX retained 消息不可靠（见 §3.3）
- 引擎 Lua WS 绑局域网 IP 而非 127.0.0.1；端口被占自动 +1（10000→10002…）

### 7.2 前端
- attach 窗口调 exitEngine 会杀掉共享引擎 → 已在守卫和 exitEditor 双重豁免，新增退出路径时保持此约定
- vue-tsc / npm run build（含 type-check）在大项目上偶发静默失败 → 用 `build-only`
- 部署后旧缓存 → index.html 已禁缓存；一次性破解用 `?v=` 查询串

### 7.3 demo-ui
- **必须同源部署**（§3.3），不得回到 5174 跨域 iframe 方案
- fetch 资源一律相对路径（base './' + HashRouter）
- BrowserRouter 勿恢复，否则 /demo/ 下路由重写到 /

### 7.4 Windows 脚本编码（三连坑）
1. Write 工具输出 LF → cmd 批处理必须 CRLF，否则解析全乱（'oto' 不是命令 = goto 被切碎）
2. 本机开了"Beta: UTF-8 全球语言支持"→ PowerShell `Encoding.Default` = UTF-8，"转 GBK"无效；且 `chcp 936` 下 UTF-8 全角冒号（EF BC 9A）的 0x9A 是 GBK 前导字节会吃掉 CR 造成行合并
3. **结论：bat 一律纯 ASCII + CRLF**；PowerShell 脚本含中文路径必须存 UTF-8 **带 BOM**（PS5.1 无 BOM 按 GBK 读会乱码）；cmd 批处理传中文路径也会乱码，尽量用纯英文路径中转

### 7.5 工具链
- Git Bash 里 npm 不在 PATH：`export PATH="/c/Program Files/nodejs:$PATH"`
- PowerShell 调用：`/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -NoProfile -ExecutionPolicy Bypass -File <带BOM的ps1>`
- 不要在 Bash 里 `cmd //c "start ..."` 起长驻进程（会挂住）；用 PowerShell `Start-Process -WindowStyle Minimized`

## 10. 给接手者的三句忠告

1. **同源是命根**：demo-ui 和 F1 前端必须同在 127.0.0.1:8085 下，任何"分开部署更方便"的想法都会撞存储分区。
2. **改完必全链路验证**：F1 前端改动 → build-only → deploy.ps1 → 完整窗口带 `?v=` 刷新 → 看 localStorage → 看 demo 小窗 runGuid → 数 Lua WS 连接。五分钟内全链路可验。
3. **引擎进程是内存黑洞**：演示前后都看一眼任务管理器的 F1.exe 数量，停止就用桌面一键停止 bat。
