# 开工提示词：Q-060 想定路径相对/绝对口径断裂修复（proxy 侧换算）— Cursor — 2026-10-21

## 0. 一句话

`scenario.list`（Q-058 上线）返回**相对路径**，而桥侧 `scenario.load`/`scenario.save` 只认**授权根下的绝对路径**——proxy 中间没人做换算，导致面板新会话"清单读得到、装载必失败"。本单在 proxy 侧把这条链打通，**纯 JS，零 C#，零编译**。

## 1. 背景与证据（先读再动手）

- 真机故障卡（面板 10-21 晚新会话，P1）：「清单读取成功（200 个文件，含三处空白底版）；两次装载分别败于"路径无效"和"文件不存在"；另存想定也报同一错误，添加单位同样被这一条挡住」。
- 病根链：
  1. `demo-ui/proxy/scenario-list.mjs:240` —— list 输出的 `path` 是 `path.relative(rootAbs, full)` 的**相对路径**（如 `AI\空白想定.scen`），根目录单独打印；
  2. 模型拿相对路径调 `scenario.load`；
  3. 桥侧 `CMO-netcore-src/AiAssistant/Infrastructure/CanonicalScenePath.cs:22` —— `Path.GetFullPath(scenePath)` 对相对路径按**桥进程当前工作目录**解析，不是按授权根 → 落出根外报 `path_not_allowed`（"路径无效"），侥幸在根内但文件不在桥工作目录视图中报 `scene_file_missing`（"文件不存在"）；
  4. 装载失败 → 无已装载想定 → save / unit.add 连锁被挡（cascade，非独立 bug）。
- 现成的两个函数直接复用（都在 scenario-list.mjs 已导出）：
  - `resolveAuthorizedScenariosRoot(slotId)` → `{ root, mode, slotId, degraded }`
  - `resolveUnderAuthorizedRoot(root, candidate)` → 绝对路径或 null（已含 `..` 与越界防护）
- 故障时 enrichment 现成：`enrichLoadFailureWithCandidates(result, slotId)`（load 失败附授权根内候选）。

## 2. 改动点（只允许动这三个文件 + 一个新测试文件 + package.json）

### 2.1 server.mjs —— 转发前规范化（核心）

位置：`executeToolInner` 内，`invokeBridge(bridgeName, bridgeArgs, slotId)`（约 line 708）**之前**，Q-048/Q-049 透传块之后。

对 `scenario.load` 与 `scenario.save`（仅当 path 非空）：

1. 取授权根：`resolveAuthorizedScenariosRoot(bound ?? slotId)`（bound 的取法参照 line 728 `guardSlotOf(sessionId)` 已有写法；注意 save 空路径流程 Q-016/Q-055 已在前面 return/处理，**本规范化只作用于 path 非空的情形，空路径确认门一字不动**）。
2. `args.path` 为相对路径 → `resolveUnderAuthorizedRoot(root, path)` 换算成绝对路径后改写进 `bridgeArgs.path`；换算返回 null（含 `..`、越界）→ 直接返回 `{ ok:false, summary:'路径越权或非法', content: 人话 + 候选清单 }`（候选清单走 `enrichLoadFailureWithCandidates` 同款，**不经桥**）。
3. `args.path` 为绝对路径 → 同样过 `resolveUnderAuthorizedRoot` 校验；越界 → 同上 proxy 侧提前拒绝（省一次桥往返）；在根内 → 原样放行。
4. **仅 scenario.load** 多一步：换算/校验通过后 `fs.existsSync` 预检，文件不存在 → 返回 `{ ok:false, summary:'想定文件不存在', content: 人话 + candidates }`，语义与桥 `scene_file_missing` 对齐（`isScenarioLoadPathFailure` 认这个措辞，保持兼容）。
5. 正常放行后，bridgeArgs 里带给桥的永远是**授权根下绝对路径**。

人话文案要求：告诉模型"你给的路径 XXX 不对/不存在，授权根是 YYY，可用底版见下面候选清单，请直接复制候选的完整路径重试"，**禁止**出现让用户手动搬文件/改名的字眼。

### 2.2 scenario-list.mjs —— list 直接给绝对路径

- `formatScenarioListContent`：清单行（`${i+1}. ${f.path} ...`）与 JSON 尾部的 `files[].path` 都改为**绝对路径**（`path.join(result.root, rel)`，统一 `\` 分隔）。
- `LOAD_HINT` / `LIST_HINT` 文案更新为："直接复制清单中的完整路径调 scenario.load，禁止凭记忆猜路径"。
- 注意：`listScenarioFilesUnder` 内部仍用相对路径做越界防护，**只改对外输出层**，内部逻辑不动。
- `enrichLoadFailureWithCandidates` 的 candidates 同步改为绝对路径。

### 2.3 tools.mjs —— 工具描述同步

- `scenario.load`（约 line 371）：描述改为"path 为想定文件路径：推荐直接用 scenario.list 返回的完整路径；相对路径按授权想定根解析；必须在授权根内且文件已存在；仿真运行中拒绝"。
- `scenario.save`（约 line 363）：补一句"path 非空=另存：相对路径按授权想定根解析，必须在授权根内"。

## 3. 测试（新建 demo-ui/proxy/scenario-path-resolve.test.mjs）

用 node:test，参照 scenario-list.test.mjs 的测试注入方式（`setProductionScenariosRootForTest`、slots 注入等）。至少覆盖：

7. save 非空相对路径 → 换算为绝对路径转发。
8. save 空路径 → 不触发本换算，原 Q-016 确认门流程回归（断言挂起行为不变）。
