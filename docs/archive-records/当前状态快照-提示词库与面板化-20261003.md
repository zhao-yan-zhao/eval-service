## 三、暂缓项（用人话，M2 后回看拍板）

### 暂缓 1：③段"想定生成与推演"的执行深度——面板生成的工单，谁来干活？

- **A. 工单模式（推荐）**：面板只负责生成工单，执行仍走现在的 Claude Code / LabConsole 管线（桥 9477 驱动、scen_spec、蒙卡判读）。省事、复用已验证链路、不重造。
- **B. 真执行**：面板背后自己接引擎直接建场推演。体验最爽（浏览器里一条指令直达引擎），但等于把 Claude Code+LabConsole 在 Node 里重写一遍，桥雷区（起跑后零轮询、BRIDGE-HANG）风险重踩，两套执行器并存维护贵。
- **C. 先只做提示词**：面板只让对话"懂规矩"，不执行。半天量，但不解决下达任务的核心痛点。

### 暂缓 2：数据库修改的入口放哪

- **A. 维持命令行 dbtool + skill（推荐）**：许可/台账/审计规矩都已在 dbtool 里，数据库 SKILL 转正 v1.0 挂载即可。改库频率低，值得。
- **B. 面板加只读库况看板**：能查台账/代级/引用关系，改库仍走命令行。零写库风险。
- **C. 面板下改库工单**：体验统一，但最大风险是"面板点了=owner 许可了"的错觉，必须做强隔离（工单生成后 owner 确认才可执行）；为低频高风险动作做最复杂入口，不划算。
