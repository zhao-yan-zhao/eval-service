# 交接说明：AI 协同开发工作流（给 02-弹道生成工具 项目的新对话）

> 2026-09-17 · 整理：Kimi（监理/主线）
> 本文只讲**开发过程的工作流与工具**——怎么派活、怎么审、怎么记、怎么上看板。不涉及任何推演系统本身的内容。
> 适用项目目录：`D:\soft\02-弹道生成工具`

## 1. 角色分工（owner 定的纪律）

| 角色 | 谁 | 干什么 | 不干什么 |
|---|---|---|---|
| 监理/架构 | Kimi（本类对话，你） | 任务拆解、架构设计、复杂推理、验收、派单、簿记 | 不亲手搜代码/读仓库/跑测试/改代码 |
| 开发 | deepseek（经 aider 工具派单） | 搜代码、读仓库、跑测试、执行具体修改 | 不做架构决策 |
| 复杂/重要评审 | codex（gpt-sol，CLI 只审不改） | 审理交付，裁决只有 APPROVE / REJECT（REJECT 必须列必修项+证据） | 不改代码 |
| 简单评审 | gpt-terra | 轻量评审 | — |

**核心纪律**：派改代码的工单不用等 owner 命令，有问题立刻派；单任务审理 3 轮不过即熔断，升级 owner 裁决，不许无限烧额度；验收永远亲手复跑+看磁盘实证，不信"我跑过了"的自述。

## 2. 工具三件（都在 F1-AI 仓里，跨项目直接调用）

```bash
# 派开发单（工单 markdown + 日志名 + 目标文件）
python D:\soft\F1-AI\LabConsole\tools\dispatch_aider.py <工单.md> <日志名> <目标文件...>
# 日志落 <项目>\LabConsole\workorders\<日志名>.engineer.log

# 脱钩跑长任务（超过 90 秒的活必须脱钩，否则被 300 秒前台限制杀掉）
cd <项目> && python D:\soft\F1-AI\LabConsole\tools\run_detached.py <日志名> <命令...>
# 注意：必须在目标目录下跑；子进程工作目录=仓库根，脚本路径给绝对路径

# 监控台状态写入（唯一合法通道，不许手改 json）
python "C:\Users\admin\Documents\kimi\workspace\ai-dev-pipeline\state_writer.py" \
  --project-dir "D:\soft\02-弹道生成工具" \
  --merge '{"kimi":{"state":"...","detail":"..."},"deepseek":{"state":"idle","running":0,"waitingReview":0,"detail":"..."},"codex":{"state":"idle","reviewing":0,"rejectedWaiting":0,"detail":"..."}}' \
  --event '{"actor":"kimi","kind":"dispatch_dev","title":"...","detail":"..."}'
```

**监控台数据契约**（每轮刷新都要带全字段，0 也要显式写 0）：
- kimi 节点：state / detail
- deepseek 节点：state / detail / running（在并行开发的任务数）/ waitingReview（待送审数）
- codex 节点：state / detail / reviewing（在审数）/ rejectedWaiting（审理不通过待二审数）
- 事件 kind=review_fail / escalate 会推 owner 手机，别滥用。

## 3. 项目内要建的四个簿记文件（放在 `<项目>\LabConsole\` 下）

| 文件 | 用途 | 纪律 |
|---|---|---|
| `TASKS.md` | 任务板（表格：编号/内容/依赖/验收判据/状态） | 状态随时更新，验收判据事先写死 |
| `LOG.md` | 每个动作留一行（谁、何时、干了什么、结果） | 防开发循环重复派工的唯一依据 |
| `FEEDBACK.md` | 给 owner 的待裁决事项 | owner 答复后在该条下补 `> ✅ 已消化·…` 标注 |
| `knowledge.md` | 经验库（K 编号条目：症状/根因/解法/证据） | 任何经验当场记，事后补=丢失 |

## 4. 自动化两件（Blueprint 定时任务，每个项目各挂一套）

1. **开发循环**（cron，建议 7,32,57 每小时的三个错峰分钟）：每轮=读任务板→有满足依赖的活就派单→刷监控台→LOG 留行；没活就如实记"维持轮"。
2. **监控台刷新器**（10 分钟 interval）：把 monitor-state.json 推到看板 Widget。

owner 说暂停就要能暂停（轮巡类默认关）。

## 5. 验收与审理流程

```
deepseek 交付 → 监理验收门（编译/测试/手工三验，全一手复跑）
  → 过：收编 commit → 送 codex 审理 → APPROVE 闭合 / REJECT 列必修返修
  → 不过：打回返修（同一问题 2 轮修不掉就带证据报 owner）
```

收编 commit 要写清：改了什么、验收证据、审理锚点。监理对有据笔误可直接勘误（代码注释+LOG+knowledge 三处留痕）。

## 6. 监控台分页

本项目在看板上有独立一页"02-弹道生成工具 · 协同监控"（由监理侧建）。你的职责只有一条：**每个动作后用 state_writer 刷状态**（--project-dir 指向本项目），页面自动亮。

## 7. 反面教材（别踩）

- 让 owner 手工贴脚本/手工操作 = 工作流有缺口，停下来登记，不绕着走；
- 汇报里出现内部编号/错误码/文件路径 = 不合格（留给留档文件，正文说人话）；
- 交付说明里写"实跑 X passed"但日志里没有 = 编造，审理必打回；
- 长任务跑在前台被 300 秒杀掉 = 没用 run_detached；
- 过程刷屏 = 不合格；只有三种情况跟 owner 说话：要他操作/定夺、自认为合格（评判卡）、熔断（简短报告+选项）。
