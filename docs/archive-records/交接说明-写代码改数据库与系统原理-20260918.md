## 第一部分：系统代码原理

### 1.1 一句话架构

F1 是一套 CMO（Command: Modern Operations）血统的战役级推演系统：**.NET C# 引擎 + Lua 脚本层 + AI 助手桥插件 + SQLite 装备数据库 + XML 想定文件**。AI 能力全部走"桥"注入，引擎本体基本不改。

### 1.2 代码树地图（源码在 `D:\soft\F1-AI\CMO-netcore-src\`）

| 目录 | 是什么 | 改它的风险 |
|---|---|---|
| `Command_Core\` | 仿真核心：单位、武器、传感器、通信、任务、推演脉冲 | **最高危**，owner 窗口+codex 审理双闸 |
| `Command_Core\Lua\` | Lua API 层：`ScenEdit_*` 全系函数在这里（`PrivateMethods.cs` + `LuaWrapper_*.cs`） | 高，但纯新增函数相对安全 |
| `Command\` | WinForms 界面（MainForm、查看器、选项） | 高 |
| `AiAssistant\` | AI 助手插件层：桥 HTTP 接口、任务编排、推演自动化 | 中，咱们的主战场 |
| `Mod\` | 联机/服务端模块 | 低 |
| `F1-AllInOne.csproj` / `F1-AllInOne.sln` | 主工程（net5.0-windows，dotnet SDK 8.0 编译） | — |

编译产物部署到运行目录 `D:\soft\F1\F1\`（正式）/ `D:\soft\F1\F1-测试\`（试验）。**改 C# 必须重新编译+拷贝 dll+重启 F1 才生效**；配置（ini）也只在 F1 启动时读取。

### 1.3 必须知道的五个机制

1. **Lua API 入口**：想定里能用的 `ScenEdit_*` 函数全部定义在 `Command_Core\Lua\PrivateMethods.cs`（静态方法，函数名即 Lua 名）。例：给单位加通信设备=`ScenEdit_UpdateUnit({guid=..., mode='ADD_COMMS', dbid=...})`（2026-09-18 实证）。要新增 Lua 能力=在这里加方法。
2. **AI 桥（Bridge）**：`AiAssistant\F1Integration\` 暴露 HTTP 接口给外部脚本（建场、跑推演、查状态）。**已知雷区**：推演高速运转时调状态查询会把接口层拖死且不可逆（BRIDGE-HANG/K100 族）——试车脚本纪律=**起跑后零轮询，只盯磁盘导出**；长推后下一局前重启 F1。修过 BF-01/02/04 三轮，现状=挂起会 10 秒超时优雅报错而非死等，但核心线程捕获不可逆。
3. **事件导出**：推演数据落盘由 `Config\EventExportExtra.ini` 控制（每个运行目录一份）。**高流量记录（每秒位置等）必须关**，否则 37 单位 2 小时写二十多万行堵死导出队列，任务被判失败+程序保护性锁死。开火/弹着/损伤/沉没类保留。
4. **想定文件 .scen**：XML 格式（内含压缩段），想定里记"用哪个数据库"，库上没有反查标识——这是改库要台账的原因。
5. **推演驱动姿势**：外部脚本走桥发 `simulation.run`，然后**只看磁盘导出目录判读**，不看 GUI、不轮询接口。

## 第三部分：改数据库的规矩

> 完整规矩在 `D:\soft\F1-AI\skills\数据库修改与管理\SKILL.md`（v0.2），这里是操作版摘要。**每次改库必须经 owner 明确许可，一次许可只覆盖当次范围。**

### 3.1 工具：dbtool（`LabConsole\tools\dbtool\dbtool.py`，六子命令）

```
tier-of <db>                      代级判定（schema 哈希，不靠文件名猜）
ledger-record <db> <想定>          台账登记（想定→库 引用关系）
lookup <db>                       反查哪些想定在用这个库
copy-for-edit <db> --方案 X --描述 Y --owner-approved "许可原文"   合规复制出副本
guard-check <db> --影响平台数 n     守卫预审（n>10 拒 exit3；官方命名库拒 exit4）
audit "<动作>"                    审计日志
```

### 3.2 铁律速记

- **官方库禁改**（`DB3K_505.db3` 这种无后缀名的）：只能 copy-for-edit 出副本改；
- **决策树**：查台账→引用者全是可删测试想定才可直改；拿不准=复制再改；
- **副本命名**：`DB3K_<代号>-<方案名>-<日期YYYYMMDD>-<描述>-<序号>.db3`，不合规工具拒绝创建；
- **递归删除>10 个平台直接拒绝**，报 owner；
- **小步快走**：一次改一处→立即载入验证→再改下一处；改坏就改回（owner 实测唯一可靠自救路径）；
- 台账目录 `D:\soft\F1\F1-测试\DB\_使用台账\` 由系统写，人不许手改。

### 3.3 已知机理（DB-DIAG-01 实证结论）

- SQLite **外键默认不强制**、枚举码字段**无 CHECK 约束**→写非法值不报错，但查看器打开时联表/查码表卡死；
- 高发区：**勾选编码类字段**、部分参数；
- 现象=库能切换但查看器一打开卡死；**改回即恢复**；
- 完整版：`LabConsole\workorders\DB-DIAG-01-排查报告.md`（v1）；预检工具设计草案 `LabConsole\tools\dbtool\VALIDATE-PROPOSAL.md`（未实现）。
