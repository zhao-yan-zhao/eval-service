## 任务一句话

把面板后台现在的"一人跑推演、全员冻结"升级为**作业租约排队**：③段作业（建想定/跑推演等会改动推演的操作）按会话排队独占；①②④段的对话、文档读写、离线统计永远并行可用。**前端一行不动**——排队信息通过 AI 回复文字传达（"当前有人正在跑推演，您的作业排在第 1 位"）。

## 具体改动

### A1 租约队列（核心）

- `guard.mjs`：全局单槽冻结改为"租约持有者检查" + FIFO 队列；
- **租约工具集合按 mutating 属性判定，不许写死工具名清单**（白名单漂移有前科 K121；桥的 ToolRegistry 有 MutatesScenario 元数据可查，或在 proxy 侧按工具定义统一标注，方案选定后写进报告说明理由）；
- 非持有者发起租约工具 → 不冻结、不报错，**返回排队位置**（"前面有 N 个作业"），AI 把这个信息自然转告用户；
- 持有者推演终局 → 租约自动释放 → 队列头自动接续并通知。**本包的死锁修复（Failed 终态确认）已在上一个工单完成，租约释放逻辑必须与 Failed 终态兼容**（A5 验收场景：推演失败→租约照样释放→队列自动接续，全程无重启）；
- stop/recover 收窄为仅租约持有者可用；
- "推演进行中禁止桥查询"红线**完整保留**：租约运行期，非持有者的桥只读查询仍冻结并明确文案（A4 验收钉死）。

### A2 改库门串行化

- `dbgate.mjs`：改库确认门纳入租约串行——B 的 present_plan 不得覆写 A 已呈现/已确认的方案（现状是无条件覆写，方案设计 §2.1 已实证）。两人同时改库 → 第二人收到排队/占用提示（A6 验收）。

### A3 顺手修（并行后暴露频率会上升，方案 §六 风险 #9）

- `dbexec.mjs` 的秒级时间戳命名（快照目录、任务存档目录）改毫秒或加随机后缀，消灭同秒碰撞；
- 三个固定名审计文件（m6-claim-audit.jsonl、m5-stats-audit.jsonl、dbtool-audit.log 的 proxy 侧写入点）每行加会话标识——**会话推导逻辑复用刚落地的 `archive.mjs` 的 resolveSession**（T3 已完工，直接 import，别重写一套）。
