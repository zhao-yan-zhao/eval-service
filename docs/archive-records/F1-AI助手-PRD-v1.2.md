# F1 推演系统 AI 助手 产品需求文档（PRD）

- 版本：V1.2（需求确认完成，可进入设计阶段）
- 关联系统：F1 推演系统（Master_Public 源码）、CMOLua 工具（参考）
- 变更记录：V1.0 草案 → V1.1 根据 owner 对 13 项待确认问题的答复更新 → V1.2 Q9 按推荐方案确认；R1 明确"不接受降级方案，全自动闭环为硬性要求"，风险保留

---

## 1. 项目背景

F1 推演系统（基于 Master_Public 源码的 C# .NET 桌面应用）目前缺少 AI 辅助能力。场景制作、场景测试、场景调整是高频且繁琐的工作：编写 CMO Lua 脚本门槛高、改完要手动跑推演、看结果要人工翻事件导出文件，整个"改→跑→看→再改"循环全靠人力。

目前已有替代方案（用 Cursor 等外部 AI 工具读写场景文件和 Lua 文件），但无法满足需求——外部工具无法驱动推演系统本身，无法自动完成测试闭环。

因此需要在 F1 系统内部内置一个 AI 助手面板，以对话形式交互，让大模型直接驱动系统完成场景制作、测试、调整的全自动闭环。

**现状关键事实（owner 已确认）**：F1 当前没有任何成熟的可编程驱动接口，所有操作均为人工手动完成。现有工作流是：AI（外部工具）帮忙写 Lua、创建基本场景文件 → 人在 F1 里手动打开场景 → 手动运行 → 另存一套想定。因此"系统驱动能力"（模块 M3）需要从零新开发，是本项目的最大工作量与风险点。**owner 已明确：不接受降级方案（即"AI 只生成文件、人手动执行"的半自动形态不算完成），全自动闭环是必须交付的硬性要求**（见第 13 节 R1）。

模型资源情况：
- 本地部署的大模型在另一台电脑上，通过局域网 HTTP 访问，接口兼容 OpenAI 格式；
- 同时要求支持外网大模型，至少包括 DeepSeek 官方 API 和量界智算 API（均按 OpenAI 兼容格式接入；量界智算兼容性细节待联调验证）。

参考对象：CMOLua 工具，其"让模型查询 DB3K 数据库、按 CMO Lua 规范生成脚本"的做法将被吸收。

## 2. 目标用户

- **主要用户**：F1 推演系统的场景制作者 / 推演分析人员，具备推演业务知识，但不一定精通 Lua 编程。
- 使用环境：Windows 桌面，单机使用，无外网依赖（使用外网模型时除外）。

## 3. 核心业务目标

1. **闭环自动化（硬性要求）**：用户用一句自然语言描述目标，AI 助手自主连续完成"生成/修改场景与 Lua → 保存 → 启动推演 → 读取结果 → 分析 → 继续调整"，直到任务完成或无法继续时向用户汇报。任何"AI 只做一半、人来执行另一半"的形态都不视为达成该目标。
2. **降低门槛**：场景制作者无需手写 Lua，通过对话即可完成场景制作与调整。
3. **过程可追溯**：模型的思考、决策、执行全程留痕，事后可审查。
4. **改动可反悔**：任何改动前自动备份，提供回滚入口（第一版按任务整体回滚，架构上预留单步撤销的扩展能力）。
5. **模型可切换**：本地模型与多个外网模型可随时切换，不锁定单一供应商。

## 4. 用户角色和权限

| 角色 | 说明 | 权限 |
|---|---|---|
| 使用者（唯一角色） | 本机操作用户，无需登录、无账号体系 | 全部功能：对话、切换模型、触发/暂停/中断自动闭环、查看日志、回滚改动、管理历史会话 |

- 系统**不做**账号、登录、角色分级。
- 模型的"权限"通过工具白名单约束：只能调用系统提供的一组内置工具，不能执行任意系统命令（设计约束，非用户权限）。

## 5. 核心业务流程

### 5.1 主流程：AI 自动闭环

```
用户在对话面板输入任务（自然语言）
        │
        ▼
AI 分析任务，制定计划（思考过程记录到日志）
        │
        ▼
锁定当前场景（AI 工作期间禁止手动修改）
        │
        ▼
循环执行（全自动，无需逐步确认）：
  ├─ 需要改动场景/脚本？ → 先自动备份当前场景文件 → 执行改动
  ├─ 生成/注入 Lua 脚本
  ├─ 保存场景
  ├─ 启动推演测试
  ├─ 读取事件导出结果（CSV）并分析
  └─ 结果符合预期？ → 否：回到循环开头继续调整（受循环上限约束）
        │ 是 / 达到上限 / 遇到无法解决的问题 / 用户暂停或中断
        ▼
解锁场景，向用户输出总结汇报
（做了什么、结果如何、改动清单、备份位置）
```

### 5.2 场景占用与暂停规则（owner 已确认）

- AI 任务工作期间，**不允许用户手动修改同一场景**。
- 用户有两个选择：等 AI 改完再手动改；或**暂停 AI** → 手动修改 → 恢复 AI（恢复时 AI 重新读取当前场景状态再继续，避免基于旧状态操作）。

### 5.3 辅助流程

- **切换模型**：设置面板中选择 本地 / DeepSeek / 量界智算，填写地址与密钥，即时生效。首次切换到外网模型时弹出一次数据外发提醒（已确认）。
- **查看日志**：打开日志视图，按会话/任务查看思考、决策、执行记录。
- **回滚**：在任务改动记录中选择某个任务的备份点，一键把场景恢复到该任务开始前的状态。
- **历史会话**：打开会话列表，查看/继续/删除历史会话。

## 7. 每个功能的用户故事

**M1 对话面板**
- 作为使用者，我可以在 F1 界面内打开一个对话窗口，直接用中文和模型交流，不用切换到其他软件。
- 作为使用者，我可以看到模型回复逐字流出（流式输出），长回复不用干等。
- 作为使用者，我可以同时维护多个会话（如"场景A制作"、"场景B调参"），互不干扰。

**M2 模型接入层**
- 作为使用者，我可以在设置里配置三类模型源（本地局域网模型、DeepSeek、量界智算），各填地址、密钥、模型名。
- 作为使用者，我可以在对话前/对话中切换当前使用的模型，程序自动用新模型继续。
- 作为使用者，当某个模型源不可达时，我能看到明确报错并切换到其他源。
- 作为使用者，我第一次切换到外网模型时会看到一次提醒：对话内容（含场景数据）将发送到第三方服务器。

**M3 系统驱动工具集**
- 作为使用者，我可以让模型读取当前场景内容并告诉我场景里有什么。
- 作为使用者，我可以让模型生成 Lua 脚本并直接注入当前场景，不用我手工复制粘贴。
- 作为使用者，我可以让模型启动一次推演、等待结束、读取事件导出结果并分析给我听——全程不需要我手动打开场景、手动点运行。
- 作为使用者，我可以让模型查询装备数据库（DB3K）来选取合适的装备和参数。

**M4 自动闭环引擎**
- 作为使用者，我只用说清目标（如"测试红方对 XX 目标的拦截率，不理想就调整部署再测"），模型自动完成多轮"改→跑→看→再改"，完成后给我总结。
- 作为使用者，当模型判断任务无法完成（如反复失败、信息不足）时，它会主动停下来向我说明情况，而不是无限循环。
- 作为使用者，我可以随时**暂停**任务（去手动改场景，然后恢复继续），也可以随时**中断**任务。

**M5 全程日志**
- 作为使用者，我可以查看模型每一次任务的完整记录：它的思考、决策依据、执行了哪些动作、每次推演的结果摘要。
- 作为使用者，日志保存在本地文件中，不依赖网络，事后随时可以翻查。

**M6 备份与回滚**
- 作为使用者，模型每次任务开始前/改动前会自动备份，我不担心场景被改坏。
- 作为使用者，我可以按任务选择备份点，一键把场景恢复到该任务开始前的状态。

**M7 历史会话管理**
- 作为使用者，我的所有对话自动保存在本地，下次打开 F1 还能看到。
- 作为使用者，我可以打开一个旧会话继续提问，模型记得之前的上下文（超长部分自动压缩为摘要）。

**M8 CMO 知识注入**
- 作为使用者，模型生成的 Lua 脚本符合 CMO 的 API 规范、避开已知坑（如中文路径问题、触发器性能问题），很少需要我手工修。

**M9 设置面板**
- 作为使用者，我可以集中管理模型源配置、循环上限、备份保留策略等参数，改完即时生效。

## 8. 输入输出说明

### 8.1 用户侧输入输出

| 项目 | 输入 | 输出 |
|---|---|---|
| 对话 | 自然语言文本（中文） | 模型流式文本回复、任务总结汇报 |
| 模型配置 | 模型源名称、API 地址、端口、密钥、模型名 | 连接测试结果（成功/失败提示） |
| 任务控制 | 启动任务、暂停/继续、中断指令 | 任务状态（运行中/已暂停/已完成/已中断/失败） |
| 日志查看 | 选择会话/任务 | 思考、决策、执行记录列表 |
| 回滚 | 选择任务备份点 | 恢复结果提示 |

### 8.2 系统侧（模型可调用的工具）输入输出

| 工具 | 输入 | 输出 |
|---|---|---|
| 读场景 | 场景文件路径/当前场景标识 | 场景结构化内容（阵营、单元、事件等） |
| 写场景 | 场景内容/修改指令 | 写入结果（先自动备份） |
| 生成/注入 Lua | 脚本内容、注入目标 | 注入结果与校验信息 |
| 启动/停止推演 | 场景标识、运行参数（时长、倍速等） | 运行状态、结束原因 |
| 读推演结果 | 事件导出目录/结果文件标识 | 事件 CSV 解析后的结构化摘要 |
| 查 DB3K | 查询条件（装备名/类型/ID 等） | 装备参数表 |

### 8.3 模型服务接口

- 三类模型源统一走 OpenAI 兼容 HTTP API（`POST {base_url}/chat/completions` 风格），支持流式（SSE）。
- 输入：消息序列（含系统提示、历史上下文、工具定义）；输出：模型回复文本/工具调用指令。

## 9. 边界情况

1. **自动循环上限（已确认默认值，可在设置中修改）**：
   - 最大调整轮数：默认 **5 轮**（一轮 = 改→跑→看一次），可配置范围 1–20；
   - 单轮推演等待超时：默认 **60 分钟**（推演本身耗时长，超时视为该轮失败）；
   - 单任务总时长：默认 **3 小时**，到限自动停止并汇报；
   - 同一错误连续自动重试上限：**3 次**，仍失败则中断任务并说明原因。
2. **会话长度（已确认策略）**：采用"滑动窗口 + 自动摘要"——保留最近若干轮对话原文，更早内容自动压缩成"任务进展摘要"（已完成动作、当前场景状态、关键结果数据）带入上下文；大型工具结果（如整份 CSV）不直接进入上下文，只进摘要，模型需要时再用工具读取。
3. **存储与清理策略（已确认默认值，可在设置中修改）**：
   - 会话与日志：文本体积小，**永久保留**，不自动删除，提供手动删除；
   - 场景备份：保留**最近 50 个备份点**或**最近 30 天**（以先到者为准），总容量上限 **5 GB**，超出自动清理最旧备份。
4. **场景修改冲突（已确认规则）**：AI 工作期间锁定场景，禁止用户手动修改同一场景；用户可暂停 AI 后手动修改，恢复时 AI 重新读取场景状态再继续。
5. **推演耗时**：单次推演可能很长，AI 采用异步等待/轮询机制，不阻塞界面（具体机制设计阶段确定）。
6. **空场景/未加载场景**：用户在未加载任何场景时发起任务，AI 应能识别并提示先加载或新建场景。
7. **多实例（已确认）**：第一版只支持单实例串行，不考虑并行推演。
8. **备份累积**：按第 3 条策略自动清理。

## 10. 异常情况

| 异常 | 处理方式 |
|---|---|
| 本地模型服务器不可达 | 明确报错（地址/端口/网络原因），允许切换模型源 |
| 外网模型 API 失败（网络、密钥无效、额度耗尽、限流） | 区分错误类型给出提示；限流时自动退避重试（有次数上限） |
| 模型返回格式异常/工具调用参数错误 | 捕获并记录，让模型自我纠正重试（上限 3 次），仍失败则中断任务并汇报 |
| 模型生成的 Lua 语法错误/运行报错 | 捕获 Lua 控制台错误输出，反馈给模型自动修复重试（上限 3 次） |
| 推演进程崩溃/卡死 | 单轮等待超时（默认 60 分钟）检测，终止进程，记录现场，向用户汇报 |
| 场景文件损坏或写入失败 | 停止任务，从最近备份恢复或提示用户选择备份点 |
| 事件导出文件缺失/格式不符 | 记录并告知模型改用可用数据源，或中断汇报 |
| 日志/备份写入失败（磁盘满、权限不足） | 阻断继续改动（安全优先），提示用户处理 |
| 用户手动中断任务 | 立即停止后续动作，保留已完成记录与备份，输出阶段性总结 |
| 用户暂停后手动改了场景 | 恢复任务时 AI 重新读取场景当前状态，再继续规划 |
| 密钥泄露风险 | 密钥本地加密存储或至少不明文展示；日志中不落密钥明文 |

## 11. 非功能需求

### 11.1 性能
- 对话面板流式输出，模型调用与推演监控在后台线程执行，不阻塞 F1 主界面。
- 单次推演耗时由推演本身决定，AI 异步等待不占用界面线程。
- 事件导出 CSV 可能上万行，结果解析须过滤核心事件，避免全量加载导致卡顿。

### 11.2 安全
- 无账号体系；所有数据（会话、日志、备份、密钥）仅存本机。
- API 密钥安全存储，界面不明文回显，日志不落密钥。
- 模型动作受工具白名单约束，不开放任意命令执行。
- 改动场景前强制自动备份，回滚入口可用。
- 外网模型数据外发提示（已确认方案）：设置面板固定写明"使用外网模型时对话内容（含场景数据）将发送到第三方服务器"，且用户首次切换到外网模型时弹窗提醒一次；不做每次发送前提醒。

### 11.3 可用性
- 界面语言：**仅中文**（已确认）。
- 面板嵌入 F1 主界面，布局与现有 DarkUI 风格一致。
- 任务运行中有明确状态指示（当前在第几轮、正在做什么）。
- 报错信息用普通人能懂的语言，附建议操作（如"检查本地模型服务器是否启动"）。

### 11.4 扩展性
- 模型接入层按 OpenAI 兼容协议抽象，新增模型源只需加配置，不改代码。
- 系统驱动工具集设计为可注册的工具列表，后续新增工具（如批量蒙特卡洛、报告生成）不改主框架。
- 备份与回滚模块按"任务整体回滚"实现，但数据结构上记录每一次单独改动，为后续单步撤销预留扩展（已确认）。
- 知识注入（CMO Lua 规范、常见坑）以外部文件形式维护，可更新不改代码。

| A4 | 自动闭环 | 给定一个场景测试任务，模型无需人工干预完成至少一轮完整的"改→跑→看→汇报" |
| A5 | 多轮调整 | 结果不符合目标时，模型能自主进行第二轮调整（在循环上限内） |
| A6 | 暂停/中断 | 任务运行中可暂停（场景解锁可手动改）并恢复（AI 重新读取场景继续）；可随时中断，中断后无残留进程 |
| A7 | 日志完整 | 任一任务的思考、决策、执行动作、结果摘要均可在日志中完整查看 |
| A8 | 自动备份 | 每次任务改动前生成备份文件，备份内容可正常加载 |
| A9 | 任务级回滚 | 选择任务备份点可成功恢复到该任务开始前的场景状态 |
| A10 | 历史会话 | 重启 F1 后历史会话完整可见，可继续对话且上下文不丢失（超长部分以摘要形式保留） |
| A11 | 无登录 | 全流程无任何账号/登录要求 |
| A12 | 异常提示 | 断开本地模型服务器后，报错信息明确，且可切换其他模型源继续使用 |
| A13 | 上限保护 | 构造一个无法完成的任务，模型到达循环上限（默认 5 轮）后自动停止并汇报，不死循环 |
| A14 | 知识有效 | 模型生成的 Lua 脚本符合 CMO 规范，可直接在系统中运行（允许 3 次以内自动修复重试） |
| A15 | 场景锁定 | AI 工作期间手动修改同一场景被阻止并提示；暂停后可修改 |
| A16 | 外发提醒 | 首次切换到外网模型时弹出数据外发提醒；设置面板有固定提示文案 |
