# 开工提示词 · db3k.detail 装备详情工具（Q-048）· Cursor · 20261019

> 工单性质：桥侧 C# 新增只读工具 + proxy 接线 + 单测。**不碰 demo-ui 前端**。
> 纪律照旧：只读源码→最小改动→编译+单测交付，部署归 Kimi F1 窗口。完工报告落 `LabConsole\outputs\`。

## 背景（根因已实锤，不用复查）

- 问题台账 Q-048：①②段面板 AI 做装备辨析时，db3k.search 只返回 `ID/Name/platform_kind` 三列
  （`CMO-netcore-src/AiAssistant/F1Integration/Db3k/Db3kSqlTemplates.cs`，48 条模板全是三列），
  读不出任何性能属性，"两条装备差在哪"无法回答。
- owner 原话转述面板 AI 自述："两条到底差在哪本轮我无法判定。要给出确切差异，必须逐条打开装备详情比对。"
- 本单开**详情通道**，不改 search 现有契约（Q-041/042 刚改过，别碰）。

## 要做的

### 1. 桥侧新增 `db3k.detail`（只读，与 search 同安全等级）

- 位置：`Db3kQueryGateway` 加 `Detail(absoluteDbPath, entityType, id, dbUsedHash)`；
  SQL 模板进 `Db3kSqlTemplates.cs`。
- 入参：`entity_type`（沿用 search 的实体枚举：aircraft/ship/submarine/facility/groundunit/weapon/sensor 等，
  以现有 IsKnownEntity 全集为准）、`id`（整数，必填）。
- 行为：
  - 主表按 ID 取**单行全列**（`SELECT * FROM DataXxx WHERE ID=@id`），但剔除 BLOB/二进制列
    （按列的 DbType/声明类型过滤，不要硬编码列名清单）；
  - 数值/文本列原样返回；空表/无此行 → 显式 note（参照 Q-042 的 0 条 note 口径）；
  - 安全口径与 search 完全一致：只读连接串校验、T0 身份快照、5s 超时、路径绑定校验一个不少
    （直接复用 Search 的既有防护结构，别新造）。
- 返回：`{ ok, item: { 列名: 值, ... }, columns_meta?: 可选, note? }`——列名保持库内原名，不做中文化。

### 2. proxy 接线（`demo-ui/proxy`）

- tools.mjs 注册 `db3k.detail`（schema：entity_type+id），tier 与 db3k.search 同级；
  ①②③段可用（④段门禁沿用现状）。
- dbexec.mjs 透传到桥，错误码沿用既有映射。
- **描述文案写清楚用途**："按 ID 读取单条装备/平台条目的全部性能属性列。装备对比、选型辨析时，
  先用 db3k.search 拿到候选 ID，再用本工具逐条取详情比对。"——这句话是给模型看的，要写进 description。

### 3. 测试

- C# 侧：沿用现有 Db3k 单测结构（ExecuteReaderOverride 测试缝），覆盖：
  正常单行返回 / 无此 ID 的 note / BLOB 列剔除 / 只读连接校验缺失时抛错 / 非法 entity_type。
- proxy 侧：dbexec 透传 + 阶段门（④段不可用）+ 参数缺 id 拒绝。

## 红线

- 不改 search 的任何 SQL 模板与返回结构（Q-041/042 刚验收完）；
- 不引入对 DataAircraft 等表结构的硬编码假设（列裁剪按类型不按名字）；
- 不碰 Lua、不碰 F1 引擎目录、不连真桥；
- 完工报告写清：改了哪些文件、单测计数、BLOB 剔除的判定依据、存疑清单。
