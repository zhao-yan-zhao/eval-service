## 一、一句话版本

**五天内，让我（Kimi）当你的"推演实验员"：你批准战法改法，我驱动 F1 自动跑一批真实推演，用程序算出胜率、战损、效费比，再帮你解读"为什么赢/为什么输"、提出下一轮改法——屏幕上的每个数字都能一键翻回原始记录。**

## 二、最终效果（演示那天，观众看到什么）

1. **一个对抗场景**：红方 3 艘地平线级驱逐舰三角编队（有防空、会机动、有电子战），蓝方 3 亿美元无人体系（≥85% 无人装备），战法骨架"正诱奇袭"——佯攻耗防空通道、水下预置伏击、末段 USV 贴海狼群同步收网。
2. **至少两套战法候选打擂台**：每套候选 × 多种不确定性变体（敌航路 ±100km、时间 ±8h、航向 ±15°、航速 ±5 节）× 每个变体至少 3 局，全部是真跑出来的，不是编的。
3. **一屏对比图**（每个数字都能点回原始 CSV）：
   - 任务成功率对比（带置信区间——赢 62% 和赢 62%±3% 是两回事）；
   - 红蓝战损交换；导弹发射/命中/消耗；
   - 首次关键事件发生时间（多快接敌）；交战周期（多久解决战斗）；
   - 效费比（打出去的弹药值多少钱 vs 换掉的目标值多少钱）。
4. **一次完整的"迭代进化"现场**：第一轮数据 → AI 归因（"败因是佯攻波次与收网时机错开 20 分钟"）→ 调参数 → 对照组重跑 → 结论更新。从假设到结论的血缘全程可查。
5. **可信度的三个硬证据**：每个候选想定的"脚本+参数+基准"三件套哈希与人工批准记录；基准想定原件未被改动；失败局（脚本错、超时、崩溃）如实出现在统计里，没有被藏起来。
6. **诚实标注**：哪些动作是人做的（启动 F1、贴脚本、批准哈希、目视检查）——演示的是"人机协同的战法开发流程"，不伪装成全自动化。

## 三、关键点怎么实现（白话版）

### 1. 谁来跑批量？——F1 里已经造好的"助手工具"，不用新写程序

F1 内部有一套给 AI 助手用的工具（叫 `simulation.run` 等十几个），是项目之前就已经开发好的：能跑仿真、能自动把每一轮的事件流水存进**以轮次编号命名的独立文件夹**、跑砸了会如实标记失败。我核实过源码，这套东西自带我们需要的全部纪律。**所以原计划里最大的工程量（新写一个 C# 批量服务）直接砍掉，五天窗口的风险降了一个数量级。**

### 2. 我隔着 F1 怎么指挥它？——"作业单"模式

我不当司机，我当调度员：把每一步操作写成一张**JSON 级别的作业单（runbook）**，由人贴进 F1 的助手聊天框，框里的 DeepSeek 逐条照做；我随后读取执行结果逐条核对。万一这条通道不顺，还有三条备路（任务库注入、人工贴脚本到 F1 控制台、7777 端口——默认维持禁用）。**D1 上午第一件事就是把主通道定死。**

### 3. 候选想定怎么生出来？——"先安检、再批准、后执行、回读钉死"

复制基准想定 → 用 Lua 脚本做战法变更（加单位、改任务、设条令）→ **安检**：程序自动扫黑名单（禁文件读写、禁执行外部程序、禁二次加载未审脚本）+ 生成差异预览 → **你批准**：批准的是"脚本全文+参数表+基准想定"三件套的哈希 → 执行 → 存成候选 .scen → **重新读回来核对内容，并算哈希钉死**——之后谁手工改了文件，跑批前比对哈希就会发现，拒绝运行。

**为什么搞得这么严**：我审查源码时发现，这个 F1 版本的 Lua 沙盒"围墙"代码整段被注释掉了——脚本理论上能读写你机器上任意文件。围墙没了，安检门就必须由我们自己站。这是全方案最重要的一个发现。

### 4. 怎么保证第 2 局不受第 1 局影响？——每局"重新投胎"

每一局都从想定文件重新完整装载（全新内存对象）、换一个新的时间线编号（GUID）、跑完即销毁；数据导出器每局重启。这些我都在源码里逐项核对过，并给了双重验证手段：两局的时间线编号必然不同、事件序列必然不同——不同就证明隔离和随机性都是真的。

### 5. 指标怎么算？——程序算数，AI 只动嘴

事件流水 CSV 直接给出：谁被摧毁、谁发射/命中/耗弹、每个事件的精确时刻、交战周期。两个指标需要自定义：**成功率**（在 Lua 里埋"任务达成判据"的记录点）和**效费比**（弹药消耗量 × 外挂的装备单价表）。**所有数字由 Python 程序计算，我（LLM）只负责解读统计结果、提下一轮建议，绝不自己拍脑袋算胜率**——这是演示可信度的底线设计。

### 6. 配套小工具谁写？——DeepSeek 写、Codex 审、我派单验收

需要 6 个 Python 小工具（Lua 安检器、CSV 归一化、指标计算、归档、报告模板、作业单生成器），全部走你定的流水线：DeepSeek 经 aider 写码 → Codex 无头审核 → 通过后合并。单任务最多返工 3 轮，不收敛就停下来上报你。**每晚 20:11 自动打一个"当日演示快照"包供你验收，验收和开发互不阻塞。**

### 7. 你怎么监控我们三个？——日志即数据源

我的每个动作、DeepSeek 的每次写码、Codex 的每次审核结论，全部落进 `TASKS.md` / `LOG.md` / `knowledge.md` 三个文件（含时间、结论、token 成本）。你另开对话做的监控界面直接读这些文件即可——**我这边保证记录完整、格式稳定、随时可消费**。

## 四、五天排期

| 天 | 干什么 | 当天收工的硬判据 |
|---|---|---|
| **D1** | 上午：零写码验证五件事——指挥通道定型、真跑一轮、结果能读回、单局耗时实测、验证想定能开。下午：派单流水线写工具 + 装备映射表开工 | 五件事全部有证据；两局时间线编号不同且事件序列不同；第 2 局不带第 1 局的任何残留 |
| **D2** | 候选生成链全通：安检→批准→执行→保存→回读钉死；成功率埋点和单价表定稿 | 候选由"批准后的脚本"生成；基准原件没被动过；黑名单拦截测试通过 |
| **D3** | 批量开跑：2 候选 × 多变体 × ≥3 局；夜里跑大批次，定时看门狗巡检 | 每局独立文件夹+血缘记录；失败局如实记录；矩阵规模按 D1 实测耗时定死 |
| **D4** | 出统计摘要和图表；AI 归因报告；**晚上第一次完整彩排** | 每个指标能翻回原始记录；图表进 PPT |
| **D5** | 一次真实迭代（改参数→重跑对照→更新结论）；冻结演示版；第二次彩排；PPT 定稿 | 迭代血缘完整可查 |

**熔断规矩（你定的新规矩，已写入准则）**：任何关键效果到验收点没达标，我**立即汇报、跳过它继续下一部分**，降级方案顶上，绝不在一个卡点上空转耽误整体。

**五个里程碑验收**（每次给你"看什么、怎么看、合格线"三件套）：

| 时点 | 你看什么 | 合格线 |
|---|---|---|
| D1 晚 | 两局推演的原始 CSV + 时间线编号对比 + 单局耗时数 + 工具包首批合并记录 | 两局数据各自独立、编号不同、事件不同；耗时数支持矩阵规模决策 |
| D2 晚 | 候选 .scen 的批准记录（三件套哈希）+ 回读比对结果 + 黑名单拦截演示 | 批准记录完整；回读一致；违规脚本被拦 |
| D3 晚 | 批量运行矩阵的逐局归档 + 失败记录 | ≥2 候选 × ≥3 局真实完成；失败局如实标注 |

| D5 晚 | 迭代血缘链 + **第二次彩排** + PPT 定稿 | 假设→参数→结论链条完整；演示冻结 |

**每晚 20:11**：自动快照（当日代码+数据+变更日志）推送通知，你饭桌上就能验收。

## 六、风险：哪些功能可能闭不了合（诚实清单）

| # | 可能闭不了合的功能 | 什么算"没闭合" | 不闭合怎么办 |
|---|---|---|---|
| 1 | **作业单通道的忠实执行**：F1 面板里的 DeepSeek 可能不严格按我的作业单逐条执行 | D1 上午连发 3 条指令，出现执行偏差且纠正无效 | 降级：人照着作业单手动点（走 MonteCarloForm 窗体，已验证路径）——**功能还在，只是自动化程度降一档**，我当看门狗+记录员 |
| 2 | **`simulation.run` 可能跑不到想定自然结束**（它按脉冲数跑，不一定认识"想定已终结"） | D1 实测不结束或提前结束 | 先给超大脉冲数兜底；还不行就降级 MonteCarloForm。D1 中午前见分晓 |
| 3 | **效费比**：装备单价没有可信来源 | D2 拿不到单价表 | 指标降级为"弹药消耗量对比"，PPT 如实标注"成本数据缺源"——指标降级但不消失 |
| 4 | **红方强度校准**：这是判断题不是计算题，可能反复调 | D3 结束仍未收敛 | 用当前最佳值跑正式矩阵，报告标注"校准中"；预留的 2–3 次试跑窗口就是给它的 |
| 5 | **别队想定不兼容**（0813v1.scen 是拿来做链路验证的） | D1 打不开或行为异常 | 立即换自建最小想定，验证目的不变 |
| 6 | **Lua 安检被绕过**（理论上存在混淆写法） | 静态黑名单被构造样本绕过 | 人工差异预览兜底（每个候选你都过目）；五天内不追求完美沙盒，追求"人批准的每一步都可追溯" |

**五天窗口内主动放弃、不会闭合的（进 PPT 演进路线页，不算失败）**：无头独立进程 runner、MCP 服务、无人工审批的全自动闭环、多实例并行跑批、OKF RAG 深度接入、通用平台化。

**整体风险的兜底逻辑**：这条链路是"一节一节"的——指挥通道断了有人工通道，自动跑批断了有手动窗体，效费比断了有消耗量对比，候选生成断了有手工候选。**每一节都有降级，整体演示在任何单点失败下都保得住**，区别只是叙事里"自动"二字的使用范围。
