# 方案：BS 侧态势播报 + 实时推演控制（2026-10-22）

> 需求（owner 23:0x 口述）：③段用户点"开始播放"后，右侧加一个**实时战场态势文字播报**小模块
> （足球解说式）；顺带把"AI 直接读态势 + 灵活控制场上单元（推一分钟→暂停→评估→再推）"
> 一并考虑。面板 UI 不归我们（关那边做），我们出**信息通道 + 后端管线**。
> 本文所有通道结论均带源码出处，不是猜测。

---

## 一、先说结论

**BS 引擎和前后端之间本来就跑着一条 MQTT 消息总线，态势数据和 Lua 控制指令全在上面。
我们不用"截取"，直接作为一个新的订阅者挂上去就行——只读零侵入，发布有回执。**

| 需求 | 答案 | 通道 |
|---|---|---|
| 如何获取态势信息 | 订阅 MQTT 的 `FrameData_*` 等主题，引擎每帧主动推全量快照 | MQTT 读 |
| 如何控制推演/单元 | 向 `server_zhs_*` 主题发 `{type:"LuaScripts", content:"任意Lua"}`，引擎原样执行 | MQTT 写 |
| 回执 | `ResponseResult_*` 主题按调用方隔离回传 | MQTT 读 |

前后端之间的 HTTP 接口（RuoYi 后端）只有"启动引擎/退出引擎/想定文件管理"，**没有态势查询口**
（EngineController.java 仅 startEngine/exitEngine 两个端点）——所以走 HTTP 后端这条路本身就不通，
MQTT 才是引擎设计的一等公民通道。

---

## 二、通道实锤（源码证据）

BS 侧构成：RuoYi-Cloud Java 后端（hn-deduction 模块，9205 口）+ Vue 前端（8085，iframe 嵌进我们面板）
+ **F1-Console.exe 无头引擎**（后端用 `cmd /c start` 拉起，启动参数带 `-MqttHost -MqttPort -AutoRun 1`）。

出处：EngineServiceImpl.java buildCommand()（约 205-235 行）；application.yml 79 行
（broker 默认 `127.0.0.1:1883`，引擎 `C:\BS_Pulish\F1-Console.exe`）。

### 读通道（引擎 → 订阅者）

前端 MQTT worker 的订阅清单（`deduce_code/src/workers/mqtt.worker.js:172-185`）：

| 主题 | 内容 | 对播报的价值 |
|---|---|---|
| `FrameData_${serverId}` | **每帧全量快照**：`{Scenario:{Time, Sides, ActiveUnits, NonActiveUnits, GlobalWeather, ...}}`，含事件/触发器/动作推送 | 核心数据源 |
| `scenarioTime` | 场景时钟 | 播报打时间戳 |
| `process_${serverId}` | 推演进度/状态/倍速 | 判"在跑/暂停/完局" |
| `victory_${serverId}` | 胜负/终止判定 | 播报收官结论 |
| `ReceiveLog_${serverId}` | 引擎日志 | 排障 |

FrameData 传输格式（mqtt.worker.js:38-42 注释）：一帧拆多条消息，
每条带 `Time/Identifying/Count/Content`，**按 Time 分组收齐 Count 条 → 拼接 → Base64+gzip 解压 → 完整 JSON**。
这套重组逻辑前端写了 2043 行 worker 里的约 100 行，我们 Node 侧照抄即可（`mqtt` + `pako` 两个 npm 包）。

### 写通道（订阅者 → 引擎）

前端所有控制都走一个口（mqtt.worker.js:395-413、1770-1773）：

```
publish 主题：server_zhs_${serverId}
消息体：{ type:"LuaScripts", content:"<任意 Lua>", ... }
```

实锤样例（编辑器源码）：
- 播放/暂停：`VP_RunSimulation()` / `VP_PauseSimulation()`（PlayControl.vue:190-195）
- 倍速：`VP_SetTimeCompression(n)`（PlayControl.vue:148）
- 加载想定：`ScenEdit_LoadScenario("...")`、另存 `ScenEdit_SaveAsScenario(...)`、建方 `ScenEdit_AddSide(...)`
  （editor/index.ts:776、1168、2186 等）

**即：BS 引擎对 MQTT 上来的 Lua 是全量执行的，没有白名单**——我们 AI 侧正在建的 R24/R25 安检纪律
（Q-073）以后可以平移到这条写通道上。

### serverId 从哪来

前端从后端接口拿到 `mqttIp/mqttPort/runMode` 后连同 `runGuid` 存 store（editor/index.ts:860-906）。
我们 proxy 侧两条路任选：调 hn 后端接口查，或面板启动播放时把 serverId 顺手传给我们的接口（更稳）。

## 三、方案分层（三层可独立交付、独立验收）

### 层 1：MQTT 旁路监听器（只读，对现有系统零影响）—— 一切的地基

proxy 里加一个 `bs-listener.mjs`：

- 连接 broker（地址从配置/面板传入，默认 127.0.0.1:1883）；
- 订阅 FrameData/process/scenarioTime/victory，重组分片、解压、缓存最新帧；
- 对外暴露 `bs.frame_snapshot` / `bs.playback_status` 两个 proxy 内部接口；
- 断线自动重连、引擎没起时明确报"未在播放"。

MQTT 是发布订阅制，多我们一个订阅者对前后端和引擎**零侵入、零性能影响**（broker 转发一份而已）。

**工作量：3–4 人日**（含单测：用假 broker 放录制的分片流回放）。

### 层 2：态势播报管线（解说员）

```
FrameData 帧流 → 帧差分器 → 事件流 → 攒批节流 → LLM 概括 → SSE 推到面板小模块
```

- **帧差分器**（核心工作量）：相邻帧对比 ActiveUnits——新出现=入列/发现、消失=被摧毁、
  挂载数减少=发射、位置/航向突变=机动；直接产出"事件卡"（时刻、主体、动作、对象）。
  FrameData 里引擎本来也推事件/触发器/动作变更（worker 1886-1910 行），能撞上就直接用，
  差分只做兜底——**真机采一段数据才能定两者配比**。
- **攒批节流**：10–15 秒或攒够 N 条事件喂一次 LLM（DeepSeek/MiniMax 都够），
  提示词模板按"足球解说"风格写死，输出 1–3 句人话。
- **SSE 推送**：proxy 出 `GET /api/bs/commentary?taskId=...` 流式接口；
  面板小模块 UI 由关做，我们只保证接口契约（事件 JSON + 解说文本两种消息）。
- 全程落盘（jsonl），播报内容可回放、可对账。

**工作量：5–7 人日**（差分器 2–3、管线+接口 1–2、提示词调优与真机联调 2）。

### 层 3：实时推演控制（copilot，需求方说不急但同路）

- proxy 出 `bs.lua_exec` 内部通道：封装 publish `server_zhs_*` + 等 `ResponseResult_*` 回执（超时/报错归一化）；
- 播放控制三件套先做：`VP_RunSimulation / VP_PauseSimulation / VP_SetTimeCompression`；
- 单元控制走 ScenEdit Lua（设航线/改任务等），**套用 Q-073 的 R24 白名单纪律**，
  默认只放行"机动/任务/传感器"类，毁伤类（KillUnit 等）进黑名单；
- "推一分钟→暂停→评估→再推"的 copilot 循环 = proxy 侧一个状态机：
  起跑→盯 scenarioTime→到点 VP_PauseSimulation→读 FrameData 出评估卡→（可选调参）→VP_RunSimulation；
- **安全闸**：控制模式默认关，面板显式开启；速率限制（每秒最多 1 条写）；
  所有写指令进审计流水（复用我们现有 claimcheck/留档）。

**工作量：6–9 人日**（写通道封装 1–2、copilot 状态机 2–3、安全闸+审计 1–2、真机联调 2）。

## 五、需要 owner/关 拍板的三件事 → **已拍板（2026-10-23 00:09）**

1. **推送方式：SSE 流式**（与聊天通道同款，直播感；轮询方案否决——延迟+空刷）。
2. **serverId 获取：面板点"开始播放"时顺手传给 proxy**（前端加一行转发，永不错台；
   需关配合，接口契约监理出）。
3. **播报节奏：两档**——大事（命中/击沉/发现敌机）立即插播，小事攒 10–15 秒一段。
