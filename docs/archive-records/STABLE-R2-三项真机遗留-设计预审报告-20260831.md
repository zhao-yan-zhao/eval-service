## 审查项 A：飞机创建带 course 不生效

### 1. 定性

**只定位到接缝 + 必须真机确认。**

磁盘可确认：助手**没有**在 `UnitAdd` 成功后再执行独立的二次设航线步骤；但 F1 的 `ScenEdit_AddUnit` 在创建成功后会**内部**调用 `ScenEdit_SetUnit` 并传入含 `COURSE` 的字典。因此不能定性为「代码完全没设航线」，也不能定性为「参数形状错误」——需真机对比「一次 AddUnit 内嵌 course」与「创建后单独 SetUnit（update_position 路径）」的行为差异。

### 2. 必须回答问题

#### Q1：是参数、类型限制、时序，还是未执行二次设航线？

| 维度 | 磁盘结论 |
|---|---|
| 参数形状 | `course` 经 `LuaCourseTemplate` 转为 `course={{latitude=…,longitude=…,TypeOf="ManualPlottedCourseWaypoint"},…}`，与 `unit.update_position` **共用同一片段**。 |
| 传给 Lua 的方式 | `unit.add`：**一次** `ScenEdit_AddUnit({…,course={…}})`，无创建后第二条助手脚本。 |
| F1 内核时序 | `ScenEdit_AddUnit` 创建单元后 **3744–3746 行** 会 `ScenEdit_SetUnit(table2, …)`，字典含 `COURSE`。 |
| 助手二次设航线 | **`CoreF1AutomationFacade.UnitAdd` 无**；`UnitUpdatePosition` 在带 course 时**显式** `ScenEdit_SetUnit`。 |
| 读回 | `UnitAdd` 只读 lat/lon/name；**不读** `PlottedCourse`/`course_waypoints`。`UnitUpdatePosition` 带 course 时返回 `course_waypoints` 计数。 |
| 类型限制 | Schema/`AllowedUnitTypes` 含 Aircraft；Aircraft 强制 `loadout_id`；脚本写 `loadoutid`+`altitude='10000'`（`ParseUnitDict` 会把键转大写）。 |
| L1 证据 | 仅 **Ship** 的 `UnitAdd_script_includes_course_when_present`；**无 Aircraft 脚本/真机测试**。 |
| runs/ 真机证据 | **未找到**「飞机带 course 打转、舰船正常」日志。 |

**不能从磁盘单独解释「为何飞机打转」**；可能方向（待探针）：飞机创建后需 throttle/任务才沿航线移动；或 AddUnit 内嵌 SetUnit 与单独 SetUnit 对 Aircraft 行为不同；或首航点与 spawn 点重合导致原地转向。

#### Q2：本机能否确认二次设航线 API？

**已确认**：`ScenEdit_SetUnit({guid=…, latitude=…, longitude=…, course={…}})` — 见 `CoreF1AutomationFacade.BuildSetUnitPositionCourseScript`（927–941 行）及 `PrivateMethods.ScenEdit_SetUnit` 的 `COURSE` 分支（6149–6176 行）。COURSE 处理对单元类型**无显式分支**（与 Ship/Aircraft 共用 `Navigator.AddWaypoint`）。

#### Q3：owner 选项

| 选项 | 用户看到的行为 | 优点 | 缺点 |
|---|---|---|---|
| **A1（推荐）自动二次 SetUnit + 读回** | 一次 `unit.add`；成功则含航点数；航线失败 → 「已创建 unit_id=…，航线未完成：…」 | 一步完成；与 update_position 已验证路径对齐；可审计部分成功 | 需定义清理/重试；真机仍要验飞机是否真动 |
| **A2 拆两步** | 飞机带 course 时 `unit.add` **拒绝**或警告，要求再调 `unit.update_position` | 语义清晰；无部分成功 | 模型多一步；易漏第二步 |
| **A3 文档降级** | 创建成功但注明「Aircraft course 不保证」 | 改动最小 | **违反** fail-closed；用户仍见打转 |

## 审查项 C：unit.status 分页

### 1. 定性

**已确认。** 实现就是「取前 N 条」；无续页；排序未冻结。

### 2. owner 选项

| 选项 | 用户看到的行为 | 优点 | 缺点 |
|---|---|---|---|
| **C1 offset + limit** | `offset=200` 取下一页 | 模型易理解 | 推演中增删单位 → 重复/漏项 |
| **C2（推荐）cursor + has_more** | 首屏 `max_items=50`；响应 `has_more=true, next_cursor=…` | 连续扫全表更稳；与 T08.5 审计分页哲学一致 | 合同稍复杂；需稳定排序 |
| **C3 仅提高 max_items** | 单次最多 200 | 零分页开发 | 超 200 仍截断；大场景 token 重 |

### 3. 证据表

| # | 文件 | 行号 | 逐字要点 |
|---|---|---|---|
| C-E1 | `ToolRegistry.cs` | 85–94 | `required: [max_items]`，1–200 |
| C-E2 | `CoreF1AutomationFacade.cs` | 903–912 | 默认 50，clamp 1–200 |
| C-E3 | 同上 | 246–328 | `unit_id` 分支字典 lookup；否则 `ActiveUnits_List` 遍历；`units.Count >= maxItems` break |
| C-E4 | `Scenario.cs` | 1335–1369 | `ActiveUnits_List` = `ActiveUnits` 字典枚举顺序，**无排序** |
| C-E5 | `InMemoryF1AutomationFacade.cs` | 259–296 | 镜像截断语义 |
| C-E6 | 返回字段 | — | 仅有 `count/units/sim_phase/note`，**无** `has_more`/`total_count` |

### 4. 合同草案（推荐 C2，供 owner 拍板）

| 字段 | 推荐值 | 理由 |
|---|---|---|
| 最大页大小 | **200** | 与现有 `max_items` 上限一致 |
| 稳定排序键 | **`unit_id` 升序（Ordinal）** | ObjectID 稳定；实现简单 |
| `has_more` | bool | 本页满且仍存在 `unit_id > last_id`（同 side 过滤下） |
| 下一页字段 | **`next_cursor`** = 本页最后一条 `unit_id` | 不透明字符串；请求时用 `cursor=<next_cursor>` |
| 非法游标 | `pagination_cursor_invalid` | cursor 不在当前快照 |
| 过期游标 | `pagination_cursor_stale`（可选） | 单位已删 |
| 单 `unit_id` 查询 | **忽略 `cursor`/`max_items`**；返回 0 或 1 条；`has_more=false` | 精确查不应分页 |
| 兼容 | 旧客户端只传 `max_items` → 视为首页 | 无 cursor 时从最小 id 起 |

**正常返回示例（side=Blue, max_items=50）**

```json
{
  "count": 50,
  "units": [ "...\" ],
  "has_more": true,
  "next_cursor": "last-unit-id-in-page",
  "sim_phase": "...",
  "note": "unit_status_readonly"
}
```

### 5. 施工范围与红线

- Touch：`ToolRegistry`（新增 `cursor` optional）、`CoreF1AutomationFacade.UnitStatus`、`InMemoryF1AutomationFacade.UnitStatus`、L1 分页测试。
- **红线**：独立 commit；分页前**必须先**排序；禁止 OFFSET 扫 `ActiveUnits_List` 无序列表；与 A/B 分开。
