## 一、赵（③④段 + 演示闭环）——问题与方案

### P0-1 对地打击任务不可达（整个演示的命门）

- **事实**：桥源码 `LuaMissionTemplate.cs` 的子类映射写死为 patrol→海军巡逻、strike→海上打击，**没有陆地打击类通道**。今天 v3 局实证：无人机探测、识别全部达成，然后全程零发射——不是 AI 设计错，是工具面建不出对地任务。我已逐行复核源码，属实。
- **后果**：演示场景（打地面发射车）在当前工具面下**永远打不起来**。
- **方案**：改桥源码，任务类型增加陆地对打击子类（同时评估开火条令是否支持按目标类型触发）。属于代码主线，需要进编译窗口。
- **负责**：代码主线写码（Claude/C），主持人验收（验收标准：同一 v3 想定复跑，出现对地开火事件）。

### P0-2 代理"终局死锁"（演示现场卡死红线）

- **事实**：推演若失败收场（Failed），代理的终局确认口径不认这个状态，结果是永久锁死——之后一切起跑指令都被拦截，只能重启。今天实证发生过一次。
- **方案**：代理侧把 Failed 纳入终态口径并加自动恢复兜底。半天级代码量。

### P0-3 F1 白色弹窗阻塞（演示杀手）

- **事实**：AI 操控过程中 F1 弹白色弹窗后流程卡死，无法自动检测，需人工点掉。
- **方案（两线并行）**：短期做一个外部"看门狗"小程序，定时检测并自动关闭弹窗（演示前必须有）；中期从引擎侧定位弹窗源头消除（我们已有引擎源码，可排期）。

### P0-4 ④段统计从未真跑

- **事实**：演示要展示"跑批→统计→对比"的闭环，但统计通道一次都没开过。
- **方案**：对地任务修好后，用同一个想定连跑小批量（3–5 局），走通统计脚本全流程。这是主持人的验收动作，提前排进日程。

### P1-5 ③段 skill 内容缺口（三个方法论空洞）

今天两轮测试暴露的③段问题，大头是 skill 没教到位：

1. **弹药—任务—高度—条令匹配核查清单缺失**：导致选了打不出去的弹药、开火前还要先手动降高度。→ skill 增加"开火可行性自检"章节，落地前逐项核查。
2. **动作编排方法论缺失**：AI 两轮只建了一个"发送特殊消息"的无用动作。→ skill 增加动作设计模板库（条件触发、事件驱动、机动指令的常用范式）。
3. **机动单元行为模板缺失**：蓝方"跑位→发射→撤收"循环做不到。→ skill 给出"巡逻路线 + 定时转移事件"的标准范式（今天考试里模板通道已验证可行，沉淀成范式即可）。

### P1-6 自由开火默认值

- skill 里钉死：默认"谨慎开火"（识别后才开火）；仅用户明确说"探测到立刻打"才用自由开火。半天工作量，纯文字。

### P2-7 引擎起跑即死（sim_failed）

- 今天实证：重启可恢复，但机理未查明。方案：演示前做一次长时稳定性摸底（连续 10 局）；现场预案 = 重启脚本 + 快速恢复操作流程卡。

### 演示材料（主持人自己）

- Word 闭环截图文档、录屏。等第一轮回归修复完成后开始取素材，避免截图返工。

### 关（界面）

- **面板 AI 无法读写本地文件（根源性大问题，10-10 实证）**：面板里的 AI 没有任何"读/写本地文件"的通道。已实证的两个后果：①用户在对话里发文档路径，AI 打不开，只能靠人把全文复制粘贴进去才能续接上下文；②AI 声称"文档已存到某某路径"，实际上它根本没有写文件的能力，盘上什么都没有——构成轻度"空口报功"。**会议纪要里"各对话框直接承接、无需手动指定文件位置"这条需求，根子就在这里**：不是界面没做按钮，是 AI 够不到文件。方案：在面板后台（面板自带的本地配套程序）增加受控的文件读写功能（限定白名单目录，如设计文档库、想定目录），AI 才能"读上次的设计文档、存这次的产出"。**此项完全不动推演程序、接口程序和系统底层代码，整体归关同志负责**（界面设计先行，代码可由 AI 起草）。
- 任务管理界面（分任务、按轮次看历史、状态保存可找回）；
- 对话框直接承接上下文（依赖上面的文件工具；工具到位前的过渡方案=复制粘贴全文，已验证可行）；
- 阶段间自由跳转；顶部全屏键。

## 四、合作方式与迭代效率建议

### 1. 问题台账制度化（最重要的一条）

今天的教训是：问题散在会议纪要、考试报告、口头反馈三处。建议立一个**唯一台账**（一个共享 md 或看板）：

- 任何人发现任何问题，**24 小时内登记**：编号 / 一句话现象 / 证据链接 / 初判责任域；
- 2–3 天的碰头会**只做分诊**（定责任人和优先级），不当场讨论技术细节——细节异步书面进行；
- 每条问题关闭时必须附"回归证据"（截图/日志/测试记录），不许口头关闭。

### 2. 内容迭代和代码迭代分开跑

- **skill / 提示词 / 模板**：分钟级见效，改完重启代理即生效——随时改、小步快跑；
- **桥 / 代理 / 引擎代码**：需要审查 + 编译，成本高——**攒批进固定编译窗口**（比如每天一次或隔天一次），不零敲碎打。
- 两条线互不阻塞：等内容的人不卡代码，等代码的人先改内容。

### 3. 标准回归场景包

把"地狱景观单机精确打击 v3"这类已验证想定固化成**回归测试包**：每次任何改动后，用同一组场景跑一遍，结果对比基线。演示前每轮迭代以此为准入——这能防止"修一个坑、挖出三个新坑"。

### 4. 人定标准、AI 起草、人验收

三个人都不必从零手写任何东西：

- **李**：提需求（要什么样的澄清问题、什么样的设计文档）→ AI 起草 skill/模板 → 李用领域判断验收 → 进回归包验证；
- **关**：描述界面行为 → AI 出代码 → 关验证交互效果；
- **主持人**：定验收标准 + 判读推演结果 + 裁决争议。

人的核心价值是**判断和验收**，不是产出文字量。AI 干粗活，人干裁判。

### 5. 让内容工作的产出"看得见"

李的产出形式是文字和判断，天然不如代码可见。用指标显形：

- ①段一次通过率（设计文档首轮合格比例）；
- 澄清平均耗时 / 轮次（极速版上线后对比）；
- 编造拦截数（审计日志自动出）；
- 知识缺口登记数（OKF 工具上线后应显著下降）。

每轮迭代会上报这四个数，内容工作的进步就有账可查。

### 6. 异步书面日报代替部分碰头

每人每天 5 行字（干了啥 / 卡在哪 / 明天干啥）落共享文档；2–3 天碰头只做分诊和裁决。等任务管理界面做出来，这套直接搬进系统里自己用自己（狗粮测试）。

## 五、关于"李同学那部分没什么大头"——我的不同看法

**表面薄，实则重。**今天两轮测试暴露的质量问题，大头恰恰在①②段：臆想约束、漏检物理矛盾、澄清一小时、设计文档造假、设计输入不清。①②段决定的是演示的**观感上限**——客户第一轮对话的体验全在这里。

之所以感觉"没大头"，是因为①②的活是**内容和判断**，不是代码，产出物是几页 skill 文字，看着薄。但如果把下面这个增量包给李，这部分立刻变得饱满且直接决定演示成败：

1. **极速版 skill 设计**（演示要用，核心交付物）；
2. **设计输入表单**（把"用户必须交代什么"结构化，直接解决需求侧认账的那部分问题）；
3. **OKF 工具的需求定义与验收**（李最懂该从知识库里取什么，代码由主线写）；
4. **测试用例库 + 评分卡**（标准化考官：每轮迭代用同一组考题和评分标准，演示前的质量守门员）；
5. **①②段断言校验的规则需求**（什么样的话算"吹牛"，李来定义，代码主线实现拦截）。

这五件事没有一件是代码，但每一件都需要推演领域判断，且都直接进演示。李的角色从"①②段负责人"重新定义为**"质量守门员 + 内容工程师"**，产出用第四节的四个指标记账，就不会显得薄了。
