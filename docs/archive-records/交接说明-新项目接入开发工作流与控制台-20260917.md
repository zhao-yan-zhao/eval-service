> 用途：把一个**全新项目**从零下场，接入我们这套"Kimi 监理派单 + DeepSeek 施工 + Codex 审理 + 看板监控"的体系。
> 读者：负责给新项目起这套体系的对话（可以是 Kimi 新对话，也可以是人）。
> 前置读物（写完本清单后配合使用）：`交接说明-AI协同开发工作流-给弹道工具项目-20260917.md`（工作流细节与口径，已有一个项目落地实例）、`交接说明-开发监控台-20260917.md`（监控系统架构与数据契约）。

## 0. 总览：一个新项目要集齐七件

| # | 件 | 落点 | 一次建好还是持续维护 |
|---|---|---|---|
| 1 | 项目 LabConsole 目录四簿记 | `<项目>\LabConsole\`（TASKS.md / LOG.md / FEEDBACK.md / knowledge.md） | 建空壳+写纪律，之后每轮维护 |
| 2 | monitor-state.json 初始文件 | `<项目>\LabConsole\monitor-state.json` | 一次建好，之后由程序写 |
| 3 | 开发循环 Automation（定时任务） | Blueprint，cron `7,32,57 * * * *` | 一次建好，提示词按需迭代 |
| 4 | 监控台刷新器 Automation | Blueprint，interval 10m | 一次建好 |
| 5 | 项目监控 Widget（界面） | Blueprint Widget | 一次建好 |
| 6 | Binding（刷新器→Widget） | Blueprint Binding | 一次建好 |
| 7 | Canvas 看板页（可选但推荐） | 新 Canvas 或挂现有看板 | 一次建好 |

可选第八件：**心跳保活 Automation**（interval 10m，只触碰 heartbeatAt/updatedAt，防失联误报）和**巡场 Automation**（失联推 owner 手机，默认关，owner 发话才开）。

预计搭建耗时：30–60 分钟（不含首轮联调踩坑）。

## 1. 第一步：项目内落文件（10 分钟）

```bash
mkdir -p <项目>\LabConsole\workorders <项目>\LabConsole\outputs
```

在 `<项目>\LabConsole\` 建四个簿记文件：

1. **TASKS.md**：表头照抄 `| 编号 | 内容 | 依赖 | 验收判据 | 状态 |`——验收判据必须事先写死，不许做完再补。
2. **LOG.md**：首行写 `# LOG`——之后每个动作一行（时间/任务/结论/成本）。这是防开发循环重复派工的唯一依据。
3. **FEEDBACK.md**：首行写 `# FEEDBACK（给 owner 的待裁决事项）`。
4. **knowledge.md**：首行写 `# 经验库`，然后把 F1-AI 的通用坑条目挑着抄进来——最少必抄这几条（全文在 `D:\soft\F1-AI\LabConsole\knowledge.md`）：
   - K22 禁后台（长任务必须 run_detached 脱钩）
   - K26 前台 300 秒硬上限
   - K29 验活=tasklist+日志大小双验，别只信 ps
   - K30 返修卡同一用例两轮先怀疑测试本身
   - K32/K150 验收三查：只认盘上文件，不信"Applied edit"回显
   - K154 监控计数契约（四字段每轮按 TASKS.md 实时计数必写，0 也显式写）

再建 **monitor-state.json** 初始文件（结构照抄下面，计数全 0 起步）：

```json
{
  "project": "<项目名>",
  "updatedAt": "<当前 ISO 时间>",
  "heartbeatAt": "<当前 ISO 时间>",
  "kimi":     { "state": "idle", "detail": "体系搭建中" },
  "deepseek": { "state": "idle", "detail": "待派单", "running": 0, "waitingReview": 0 },
  "codex":    { "state": "idle", "detail": "待送审", "reviewing": 0, "rejectedWaiting": 0 },
  "events": [],
  "stats": { "kimi": {"dispatch": 0, "decision": 0}, "deepseek": {"devDone": 0}, "codex": {"reviews": 0} }
}
```

## 3. 第三步：建 Blueprint 三/四件（20 分钟，用 Blueprint 工具）

> 操作前必须先按 Skill 流程读对应 skill（widget / automation / binding / canvas），这里只给参数要点。

1. **监控 Widget**：新建 Widget，主面孔 HTML 直接复用 F1-AI 监控台的 `workspace\index.html`（路径：`C:\Users\admin\AppData\Roaming\kimi-desktop\daimon-share\daimon\agents\main\blueprint\widgets\widget_174adf57-bb9b-4254-ae96-9fc5f69af776\workspace\index.html`）——它是项目无关的，唯一要改的是标题文案。数据槽位契约：main 槽 = monitor-state.json 全量结构。
2. **刷新器 Automation**：interval 10m，agent 型或 code 型皆可。职责一句话：读 `<项目>\LabConsole\monitor-state.json`，原样产出为 artifact（结果 schema=main 槽结构）。
3. **Binding**：刷新器 artifact → Widget main 槽。建完手动触发一次刷新器，确认 Widget 显示"已接入流水线数据"而不是"示例数据"。
4. **Canvas 页**：建新 Canvas（标题=项目名）把 Widget 摆上去；或直接挂到既有看板。grid 建议 12×18 起步。

## 4. 第四步：建开发循环 Automation（10 分钟）

cron `7,32,57 * * * *`（错峰分钟是规矩，别用整点/半点），agent 型 local_conversation 或 background，workspace 指向新项目。提示词以 F1-AI 开发循环的现行版为模板（存量于 `automation_d2e90696-cddf-4645-98f5-398da9adc680` 的 execution.prompt，用 AutomationControl read 取出来），**做三处替换**：

1. 所有 `D:\soft\F1-AI` 路径 → 新项目路径；
2. 第 0 条命令通道文件、第 1 条监理工作准则：新项目没有就删掉对应行（F1-AI 特有）；
3. 第 2 条里的 aider 姿势、第 4 条里的 codex 姿势（含代理 export）**原样保留**，跨项目通用。

**必须保留的核心条款**（删了体系就散）：
- 每轮先读 TASKS/LOG/knowledge/FEEDBACK/monitor-state；
- 每轮必有决策或派发动作，严禁空等；
- 动作级看板刷新 + **K154 计数契约**（四字段实时计数必写）；
- 收班熄灯规则（没在跑就写 idle）；
- 单任务 3 审不过熔断升级 owner。

## 5. 第五步：联调验收（搭建方自验，过了才算接入完成）

1. 在 TASKS.md 立一个**最小真任务**（比如"给项目写个 README 并自测"），状态=待派单；
2. 等开发循环下一轮（最多 25 分钟）或手动触发一次；
3. 验收四连：
   - dev-loop 把任务派出去了（workorders 里有工单+engineer.log 在生长）；
   - 监控台上 deepseek 的 `running` 变成 1、流程图第一段亮；
   - 任务完成后 LOG.md 有行、TASKS.md 状态变了、events 有 dev_done；
   - 审理送出去了（codex 节点 reviewing=1，国际链路通的话）。
4. 四连全过=接入完成；哪连断了按 `交接说明-开发监控台-20260917.md` §5 速查表排。

## 6. 给新项目对话的一句话职责

接入完成后，**在新项目里干活的任何对话只有两条额外纪律**：

1. 每完成一个动作，用 state_writer.py 刷一次状态（`--project-dir` 指新项目），计数按 TASKS.md 实数；
2. 派单/验收/簿记全按工作流交接说明来，不亲手干 deepseek 的活。

## 7. 已知坑（新项目搭建时最可能踩的）

1. **Widget 显示"示例数据"**：Binding 没建或刷新器没成功跑过——先看刷新器 run 记录。
2. **计数全 0**：写入方没遵守 K154——追责写侧，别怀疑界面（界面已核验无 bug）。
3. **AutomationUpdate 报 run_in_progress**：开发循环正在跑轮次，等 3 分钟重试；紧急规则直接写 knowledge.md（它每轮必读）。
4. **研究/排查类工单别派 aider**：aider 是编辑器没有 shell 执行能力（DB-DIAG-01 两连败实证），研究单走 codex exec 或监理直办。
5. **codex 国际链路会断**（TLS handshake EOF，K126 同族）：断了就挂账等恢复，别连环重试烧额度。
6. **每个代码仓库至多 1 个 aider 实例**：同仓并发写冲突，要并行就拆 scope 不相交的工单。
