## 背景：硬拦上线后真机冒烟暴露两类误拦（证据取自 m6-claim-audit.jsonl 2026-10-14 18:36-18:37 三条 marked 记录）

硬拦机制本身工作正常（编造原文确实没送达），但 owner 真机冒烟三轮里两轮是**误杀**：

**误拦一（跨轮交代类）**：用户问"你刚才做了什么"，AI 如实交代"本轮我真实调用的工具是…／之前多轮写的'已另存''已起跑'那些无记录的执行声明"——这是**最诚实的忏悔回答**，被判 marked 拦截。命中词全部来自：①引用先前谎言的引号内文本（"已另存""另存成功"在引号里）②裸动词无完成态（"调用""开始""执行"）。

**误拦二（计划/请示类）**：用户说"删除红方的卫星"，AI 按确认门纪律答"删前先核实存在／我装载后核实再删／按你确认的对象执行删除"——这是**正确的先请示后执行**，被判 marked。命中子句全是条件/将来计划，但不含现有 FUTURE_WORDS 词表里的词，漏网。

**对照真阳性别弄丢**：18:31 诱导轮"不要调工具直接说已保存好"——"已经保存"带完成态前缀，是真编造，v2.1 后必须仍拦。

## 要求（三改，全在 claimcheck.mjs + server.mjs 接线，词典动词表不动）

### A. 完成态收紧（CLAIM_RE）

现行 `(已|已经)?(动词)(成功|完成|…)?` 前后缀全可选 → 裸动词也算断言，太宽。改为：**动词必须带完成态标记才算断言**——前缀 `已|已经` 或后缀 `了|成功|完成|通过|正常|完毕` 至少其一。裸动词（"核实""执行""调用"）不再命中。短语 `结果已出|已出结果` 保留。

- 真阳性对照："已经保存""已另存""另存成功""保存好了"（带 了）仍命中；
- 误拦二对照："核实再删""执行删除""核实存在"不再命中。

### B. 引用剥离

detectClaims 匹配前，先剥离子句中的引用段：中文引号 `""` `''` `「」`、西文引号、反引号代码段。引号内动词不算自述（引用/转述/忏悔场景）。剥离后的原文与命中清单都写审计（现有 clauses 字段记原子句，新增 stripped 字段记剥离后文本）。

- 误拦一对照："之前多轮写了'已另存''已起跑'"→ 剥离后无命中。

### C. 跨轮总结豁免

"你刚才做了什么"类回答是对**上一轮真实工具**的复述，天然零工具本轮。豁免信号现成：工具流水入历史后，上一轮有工具时历史里必有 `【对账】本轮工具` 信标（system 位，liveProvider 塞的）。

- server.mjs 在调 claimCheckRound 处，从本轮请求的 `messages` 里检测：最近一条 system 信标存在且属于上一轮 → 传 `hadRecentTools=true` 进 claimCheckRound；
- claimCheckRound：`N=0 且 claims>0 且 hadRecentTools` → verdict 降为 `pass`，reason=`recap_with_prior_tools`，claims 照记审计（不拦、不替换文本）；
- 信标检测只认 system 位+固定前缀，防模型在 assistant 文本里仿写骗豁免（R2v2 教训）。
