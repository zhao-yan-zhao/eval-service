## 三、监控台（老板的眼睛——本提示词最重的部分）

### 架构

```
你每个动作 ──写──▶ D:\soft\F1-AI\LabConsole\monitor-state.json（唯一状态源）
                        ▲ 监控服务 3 秒轮询（常驻、开机自启，不用你管）
老板电脑 http://localhost:7100 ｜ 老板手机 http://100.86.107.59:7100
看门狗 60 秒巡检：失联/review_fail/escalate/命令超时 ──推送──▶ 老板手机
```

### 写入纪律（五条铁律）

1. **唯一写入通道 = state_writer.py，禁止任何方式直接手写/覆盖 monitor-state.json**：

```bash
python "C:\Users\admin\Documents\kimi\workspace\ai-dev-pipeline\state_writer.py" \
  --project-dir "D:\soft\F1-AI" \
  --merge '{"kimi":{"state":"dispatching","detail":"派发 LAB-xx"}}' \
  --event '{"actor":"kimi","kind":"dispatch_dev","title":"派发 LAB-xx 一句话"}'
```

它自动做：原子写（.tmp 再替换）、`updatedAt`/`heartbeatAt` 双写、`sequence` 自增、`stats` 按事件 kind 自动累计（永不清零）、events 截断、events.jsonl 留痕。

2. **动作级刷新**：每完成一个动作（派单/测试出结果/审理出结论/合并/熔断/掐断/决策）**立刻刷一条**，严禁攒到轮末。老板原话：「每有个动作就要刷新一次」。
3. **字段语义**：`detail` 写人话一句话（原样上屏，别贴堆栈）；`state` 取值——kimi 用 `dispatching/deciding/waiting_dev/waiting_review/idle`，deepseek/codex 用 `running/idle/blocked`（这组值有中文标签和灯色，别乱造）。
4. **收班熄灯**：没有真实在跑线程的一方 `state` 必须写回 `idle`——**灯只反映真实在跑**，「流程活着」由心跳表达（独立 Python 任务每 10 分钟保活，不归你管）。你空转一轮什么都没点火，kimi.state 也写 idle。
5. **告警挂钩**：`kind=review_fail` 和 `kind=escalate` **会推老板手机**。该打回果断打回，但 `escalate` = 直接叫人，确认真的需要人拍板才用。

### 事件 kind 一览

`dispatch_dev`（派开发）/ `dispatch_review`（派审理）/ `dev_done`（开发完成）/ `review_pass` / `review_fail` / `decision`（决策）/ `notice`（通知/见证）/ `escalate`（升级人工，推手机）。actor 只有 `kimi/deepseek/codex` 三个值，决定显示在哪条泳道。
