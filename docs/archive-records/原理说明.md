# 原理说明

更新时间：2026-08-13（T08.3：面板内已有流式聊天+设置；S2-FIX2 注入快照改由运行时持有；S1≠F04.2）  
读者：非程序员也能看懂的「这东西打算怎么转起来」
准绳 PRD：`F1-AI助手-PRD-v1.3.md`

## 一句话目标
在 F1 推演软件里面装一个中文 AI 助手：你说目标，它自己完成「改场景 → 保存 → 跑推演 → 看结果 → 再调整」，尽量不让你手工点菜单。  
**全自动闭环是硬要求**，不能偷换成「AI 只写文件、人去点运行」。

## F04.2-R 之后多了什么（当前实现边界）

- F1 启动时会尝试创建 **生产 AI 运行时**（失败则 AI 关掉，游戏照常开）。
- 改场景必须走 **工具服务**（备份→哨兵→内核→审计）；不能让模型直接摸内核对象。
- 备份恢复后的 **重新加载** 走正式加载完成接口，并在弹出「选边」之类交互前先拦下来。
- 解除「恢复阻断」前，必须先把授权审计写进数据库并核对，再清哨兵文件。
- 专机冒烟测试要开 **两个环境变量** 才会跑，而且只动工作副本——**默认不会自动跑**。
- **失败注入门控（S2 编码中）**：启动时把六个相关环境变量**读成一份不可改的快照**，交给 AI 运行时；冒烟编排只用这份快照，**没有**「全局重置开关」可被随便清掉重读。真实专机失败注入冒烟仍未授权。
- **S1（2026-08-13 FIX + RERUN）**：真实专机已跑通「复制工作副本→去掉编辑器残留标志→加载→建任务→经工具改坐标→保存→重载→核对」，并写 `smoke-complete.marker`。资源补齐后 **RERUN**（`runs/F04.2-R-S1-RERUN/`）再次 PASS，证明可复现。AI 可写目录用第三个环境变量指定（不改系统 WritableRoot 文件）。**S1 PASS ≠ F04.2 PASS**；失败注入（S2）真实 Smoke 仍未授权。
- **启动注意**：可写根下需要 Symbols / DB / 地图缓存等资源；缺 Symbols 时，启动会在 `InitDelegates` 创建主窗时失败并被吞掉，随后误入「等地形」——进程还在、标题像开了窗，其实没进主窗口 Load。阶段探针**默认关闭**；只有同时设置 `F1_ENTRY_PROBE=1` 和可写的 `F1_ENTRY_PROBE_ROOT` 才会写诊断日志（与冒烟测试环境变量无关，也不是修复）。
- **T08.1～T08.3**：主菜单「AI 助手」打开 DarkUI 面板；上方可中文流式聊天（发送/取消、会话本地保存可重启恢复），下方为模型源与循环参数设置。工具闭环与任务控制区仍未接。

## 用户说一句话之后，系统大概会怎样（设计目标）

1. **对话面板**收到你的话（T08.3 已可流式对话；任务状态区在后续 T08.4）
2. **模型**（本地或外网大模型）想办法，决定调用哪些「工具」（工具执行仍待 T07）
3. **工具**只能做白名单里的事：读场景摘要、改参数、保存、开跑、读结果、查装备库等——不能随便执行系统命令
4. 动场景前先 **备份**；失败或你不满意可以 **回滚**
5. 跑推演时 **锁住场景**，避免你和 AI 同时改乱
6. 全过程写 **日志**，事后能翻

## 几个关键词（先解释）

| 词 | 意思 |
|---|---|
| **场景 / .scen** | F1 的一局想定文件（谁打谁、有哪些单位） |
| **工作副本** | 测试时把原始场景复制一份再动；原始文件当「金样」不动 |
| **hash** | 文件的数字指纹；指纹变了就说明文件被改过 |
| **PoC** | 可行性试探：先用最小例子证明「能不能」，再正式开发 |
| **SSE** | 模型一边想一边往外吐字的传输方式（流式对话） |
| **SQLite** | 一种本地小数据库文件，用来存会话、任务、备份记录等 |
| **知识包** | 随安装带的说明/示例文件包（有版本号）；第一版不做“智能搜索知识库” |
| **状态机** | 程序按固定步骤自己推进任务（规划→改→跑→看→再改），不用 Python 工作流框架 |

## 信息大概怎么流动（设计图，用人话）

```text
你（中文）
  → 对话面板
    → 模型（本地 / DeepSeek / 量界智算）
      → 受控工具（改/存/跑/读）
        → F1 内核（场景、推演、导出）
      ← 结果摘要
    ← 流式中文回复 + 任务状态
  ← 日志 / 备份 / 历史会话
```

## 为什么要这样设计
- **工具白名单**：防止模型乱跑危险操作
- **备份 + 回滚**：改坏了能撤回
- **先 PoC 再开发**：F1 原先几乎没有「程序代你点运行」的成熟接口，必须先证明能自动加载、改、存、跑、停、读结果，否则后面全白做
- **C# 原生编排（PRD V1.3）**：闭环在 F1 同进程用 C# 状态机实现；不用 LangGraph；第一版也不上 Semantic Kernel
- **静态知识包（PRD V1.3）**：先带版本化文件说明；预留以后可换成检索式知识库的接口，但 V1 不做向量搜索
