# ③段规矩文件增补草案：动作设计模板（事件动作库）

> 草案，待主持人审。审议通过后将并入 `skills\想定落地与试车\SKILL.md`（建议位置：紧随"开火可行性自检"之后，作为独立章节；版本号升 1.10）。
> 缘起：问题台账 Q-011——2026-10-10 两轮实测，AI 建想定时只会建"发送特殊消息"一个无用动作。源码摸底结论（《事件动作能力摸底-20261013》）：桥侧事件动作白名单实际有 4 种（发送消息/改条令/激活任务/结束想定），但工具 schema 里动作清单不可见、知识包示例只有"发送消息"一种、面板工具描述又写错了动作名——能力存在但模型不知道。本章把"能用什么动作、参数怎么填、什么不能建"写成模板卡，并钉死"桥能直接建 / 只能留档提醒人工建"的边界。

## 动作设计模板（事件动作库）

### 一、能力总表（建任何事件前先看这张）

桥 9477 的 event.upsert 只接受以下组合，**表外的一切都不存在**：

| 类别 | 可用值 | 关键参数 | 是否桥能直接建 |
|---|---|---|---|
| 触发条件 | `time`（到点触发） | trigger_minutes：想定开始后第几分钟（整数，≥1） | ✅ 能 |
| 触发条件 | `unit_destroyed`（单位被毁触发） | trigger_unit（单位名/编号）**或** trigger_side[+trigger_unit_type+trigger_dbid] | ✅ 能 |
| 动作 | `send_message`（发送消息） | side（阵营）、message（消息文本） | ✅ 能 |
| 动作 | `set_doctrine`（改条令） | scope=side/unit、side、unit_id/unit_name、emcon_radar=on/off、weapons_control=weapons_free/weapons_tight/weapons_hold | ✅ 能 |
| 动作 | `activate_mission`（激活任务） | side、mission_name（**只有激活，没有停用**） | ✅ 能 |
| 动作 | `end_scenario`（结束想定） | 无参数 | ✅ 能 |
| 其余 12 种触发条件（进区域/被探测/受损/周期/随机时间…） | 引擎有、桥未透传 | — | ❌ 只能留档提醒人工建 |
| 改高度速度/改航线/WRA/转隶/进退场/键值埋点 | 引擎 Lua 有、桥白名单无 | — | ❌ 只能留档提醒人工建（模板通道登记或离线注入） |

**红线（Q-011 教训）**：实现不了的战术意图，**不许用 send_message 充数**——消息不产生任何推演效果。要么降级近似并在评判卡声明，要么留档提醒人工建。

### 二、模板卡

每张卡固定四段：**战术意图 → 用哪个动作 → 参数怎么填 → 常见坑**。卡名后的括号 = 边界（✅桥能直接建 / ⚠️只能留档提醒人工建）。

#### 卡 A：雷达定时开机 / 电磁静默窗口（诱敌开机、照射窗口）——✅桥能直接建

- **战术意图**：全程雷达静默，到某时刻（诱敌进入杀伤区、末段照射、转场搜索）才开机；或打完关雷达撤出。
- **用哪个动作**：time 触发 + set_doctrine（emcon_radar 键）。
- **参数怎么填**：
  - 开机：`{event_name:"<中文简述>-雷达开机", enabled:true, trigger_type:"time", trigger_minutes:<第几分钟>, actions:[{type:"set_doctrine", scope:"unit", side:"<阵营>", unit_id:"<单位编号>", emcon_radar:"on"}]}`；
  - 关机同理 emcon_radar:"off"；整方切换用 scope:"side"（不带 unit_id/unit_name）。
- **常见坑**：
  - unit 级必须带 unit_id 或 unit_name（单位建成后从 unit.status 回读编号，不要手编）；
  - 默认状态沿用既有纪律（雷达默认关）——开机必须有设计依据，对应自检 5 的识别链推演；
  - 时间触发事件只执行一次（引擎语义），"开关循环"要建两个事件或分多个时刻。

#### 卡 B：开火权限窗口（发射前解禁 / 交战后转慎开）——✅桥能直接建

- **战术意图**：平时谨慎开火，进入发射窗口（目标进入射程、时间到点）才放开开火；或先自由开火速决、达成后转 hold 停火。
- **用哪个动作**：time 触发 + set_doctrine（weapons_control 键）。
- **参数怎么填**：同卡 A 结构，emcon_radar 换成 weapons_control，取值 weapons_free（自由）/weapons_tight（谨慎）/weapons_hold（禁止）。逐波放行见卡 C。
- **常见坑**：
  - 条令切换不替代"识别链闭合"——自由开火只能"探测即打"，目标识别不出照样打不准，与自检 4/5 联动核查；
  - 切 hold 后已在途的弹药不会追回，窗口设计要留余量；
  - 与 doctrine.set（建模工具）区别：doctrine.set 是起跑前一次性设置，set_doctrine 动作是推演中到点切换——两者配合用，不许互相替代。

#### 卡 C：分批投入 / 梯次放行——✅桥能直接建（条令分批；任务级分批不可用）

- **战术意图**：多波次单位不同时刻投入（第一波牵制、第二波主攻），或按时刻逐批放行发射。
- **用哪个动作**：全部单位建模时编入任务 + 起跑前对每波设 weapons_hold + 各波时刻的 time 触发 + set_doctrine 把该波改成 weapons_free。
- **参数怎么填**：建模阶段 doctrine.set 逐单位设 hold（scope:"unit"）；事件按波次建：波 1 在 trigger_minutes=T1 对该波单位 set_doctrine weapons_free，波 2 在 T2……每波一个事件或一个事件多动作（多动作按数组顺序执行，可一个事件内放行多波）。
- **常见坑**：
  - **任务级分批做不到**：桥没有"停用任务"动作，mission.create_or_update 建出的任务默认激活——"预建未激活任务、到点激活"这条路不通，老老实实走条令分批；
  - 单位编号逐个回读，批量拼 actions 时不许手编编号；
  - 波次时刻必须落在想定时长内，且留出武器飞行时间（对照自检与结束充分性校验）。

#### 卡 D：关键单位被毁即终局 / 即触发判据——✅桥能直接建

- **战术意图**：某关键单位（指挥舰、雷达站、靶标）被击毁立刻结束想定，或触发撤收/转阶段。
- **用哪个动作**：unit_destroyed 触发 + end_scenario（或 set_doctrine 等其他动作）。
- **参数怎么填**：
  - 指定单位：`{trigger_type:"unit_destroyed", trigger_unit:"<单位名或编号>", actions:[{type:"end_scenario"}]}`；
  - 指定类别：`trigger_side:"<阵营>"` + 可选 trigger_unit_type（Aircraft/Ship/Submarine/Facility/Satellite/Weapon）+ 可选 trigger_dbid（装备库编号，**必须配 trigger_unit_type**）——该阵营任一同类单位被毁即触发。
- **常见坑**：
  - trigger_unit 必须是场景内真实单位名/编号，写错 = 触发永远不来；
  - trigger_side 写不存在的阵营 → 桥报 event_upsert_no_effect:trigger（建后读回，别只看 Ok）；
  - trigger_dbid 不带 trigger_unit_type → 直接拒绝（event_trigger_dbid_needs_type）；
  - 击毁判据与事件数据互证（判读口径三律：撞击/接触起爆不进 WeaponEndgame，从 UnitDestroyed 计数）；
  - 本触发"单位真被击毁"路径的完整真机闭环先短局验证再上全量（见摸底存疑 6）。

#### 卡 E：撤退转移 / 机动撤收（降级范式）——⚠️部分只能留档提醒人工建

- **战术意图**：单位打完撤出、转移阵位、再次接战（蓝方"跑位→发射→撤收"循环的简化版）。
- **桥能直接建的部分（降级近似，评判卡必须声明为偏差）**：
  - **航线预设**：建模时 unit.add 的 course 参数预设航点，按巡航速度推算各腿时刻——到点自然转移，不是事件驱动；
  - **巡逻任务**：referencepoint.add 建围区 + mission.create_or_update 建 patrol，任务驱动单位在区内机动。
- **只能留档提醒人工建的部分**：
  - "到点改位置/改航线/改高度速度"这类**事件级转移动作，桥白名单里没有**（引擎 Lua 有 ScenEdit_SetUnit 可做，但桥刻意禁止任意 Lua）——想真正实现只能在 F1 编辑器人工建事件，或在模板通道登记新模板（需离线审批），或离线注入（K68 通道）；
  - 留档格式：写进规格书"人工补充动作"清单 + 评判卡"依据与诚实声明"栏明示。
- **常见坑**：
  - 地面机动单元的完整标准做法见第三章（Q-012 专项），本章不展开、不与之冲突；
  - 巡逻近似会导致"后半程巡逻强度下降"（既有 skill 已收录），判读时不得按真实撤收严判。

#### 卡 F：发射前降高降速（发射包线管理）——⚠️只能留档提醒人工建

- **战术意图**：弹药要求发射点满足高度/速度包线，任务巡航高度不满足时，到发射点前先降高/降速。
- **现状**：桥没有改高度/速度的事件动作（引擎 Lua 有 ALTITUDE/SPEED 参数，PrivateMethods.cs:6205-6251；桥白名单无）。**不许用 send_message 假装降高。**
- **处置**：
  - 首选：任务/航线在设计时就满足发射包线（与自检 3 联动，对照弹药库发射条件核对巡航高度）；
  - 包线确实与巡航高度冲突时：留档提醒人工建（F1 编辑器 LuaScript 动作调 ScenEdit_SetUnit 降高降速），或登记模板通道缺口；
  - 想定备注和评判卡必须写明"发射点高度由人工动作保障/或已按包线设计"，判读时不得把零发射误判为设计失败。
- **常见坑**：别指望试车时人工补救（自检 3 教训原文）；航线巡航高度≠发射高度的问题在规格书编译阶段就要暴露。

#### 卡 G：判据埋点（键值写入）——⚠️只能留档提醒人工建（当前无可用通道）

- **战术意图**：想定内埋"达成标志"键值，试车后回读判据（双通道判读的第二通道）。
- **现状**：桥白名单**没有 set_keyvalue 动作**——面板工具描述里写的 set_keyvalue 是虚标，传了会被桥拒（event_action_not_whitelisted）。已登记模板 labb2.smoke.mission_trigger_keyvalue 的阵营枚举锁死 ["Blue"]，不能当通用埋点用。
- **处置**：
  - 埋点不可用 → 显式声明跳过，判读全走事件数据层（QA 门通道一）——**声明跳过优于硬凑**（既有纪律）；
  - 确需埋点：离线注入（K68 通道，模板脚本可写 SetKeyValue）或向代码线提"event.upsert 增加 set_keyvalue 白名单动作"（K69 早已立项推荐，尚未落地）；
  - 每次使用前先看本卡是否已更新为"✅能直接建"（代码线修复后本章同步改）。

### 三、通用坑（所有卡共用，建模前必读）

1. **actions 数组必填且非空**，每个动作对象必须带 `type` 字段（缺 → event_action_missing_type；空数组 → event_actions_empty）；enabled 必填；trigger_type=time 时 trigger_minutes 必填且 ≥1。
2. **send_message 的字段名是 `message`，不是 `text`**（2026-10-10 考试实测踩过：event_action_missing_message）。
3. **event.upsert 是真 upsert**：同名 event_name 重复调用 = 更新原事件，不是新建；桥**没有事件删除/查询工具**，建错了只能靠重载锚点重来。
4. **事件只在起跑前建**：推演进行中一切建模工具被护栏冻结（含 event.upsert），到点想改事件 = 违规。
5. **Ok ≠ 成功**：桥有读回三重校验（事件存在/触发器挂接/动作数，失败报 event_upsert_no_effect:…），但历史上有过"报 Ok 但 save 不落盘"（K106）——依赖时序触发判据的想定，另存后 .scen 解包回读确认事件落盘再试车。
6. **时间事件一次性**：Time 触发后事件停用（引擎语义），"每隔 N 分钟做一次"要建多个事件。
7. **一个事件多动作按数组顺序执行**：依赖先后关系的动作放同一个事件里排好序，别拆成两个同刻事件赌调度顺序。
8. **命名规矩沿用建场纪律第 8 条**：事件名 = 中文简述（≤12 字）+ 标识；桥自动生成的触发器/动作描述是 `<事件名>_trigger` / `_action_N`，想定内名字对账时按这个格式找。
9. **工具描述与实现漂移**：面板 AI 可见的工具描述动作清单与桥实现不一致（set_keyvalue 不存在、end_scenario 漏列）——**一切以本章能力总表为准**，遇 event_action_not_whitelisted 先对照总表，别照着工具描述猜。
10. **边界声明纪律**：凡用了卡 E/F/G 的"留档提醒"路径，规格书和评判卡必须显式声明（哪项动作缺、怎么近似、判读口径怎么放宽）；试车判读不得把"缺动作导致的做不到"记为实现失败，也不得把近似方案当真实实现报功。
