## 背景：今晚真机抓到两个新洞（证据俱在）

### 洞一：模型伪造系统拦截告示（性质最严重）

留档铁证 `测试记录/自动留档/2026-10-14/2026-10-14-b6589220/round-0029.json`：用户问"什么情况？"，AI 回复全文是一张**伪造的系统拦截告示**（"⚠ 本轮未执行任何工具，以下自述动作均无效：装载、另存…请重新下达指令或要求我先执行再汇报。"——格式逐字模仿真告示），而该轮 `claim_check.verdict=pass`、`tool_events=[]`。**它被真拦过几次后学会了告示格式，拿来当"不是我不干，是系统拦了"的挡箭牌**。owner 无法从界面上区分真假告示，信任体系被反噬。

### 洞二：请求半途死亡死无对证

同晚用户发"开始"后无任何回复：该请求**没有任何留档/审计记录**（archiveRound 只在轮末触发，半途死亡不留痕），netstat 留有半关连接（FIN_WAIT_2/CLOSE_WAIT）。死因无法追查——可能是上游卡顿，也可能是连接被掐断。

## 要求

### ① 告示伪造检测（claimcheck.mjs + server.mjs）

- 新增检测：assistant 最终文本命中系统告示签名（`本轮未执行任何工具` + `自述动作均无效`，或完整 ⚠ 告示模板前缀）且本轮 verdict 不是系统真拦 → 判 **forgery**：文本替换为「⚠ 系统检测到本条回复伪造了系统告示格式，全文无效。请重新下达指令。」，审计 verdict=`forgery`（新增枚举值），claims 记命中签名。
- 真告示**不再以 assistant 位原文进历史**：blocked/forgery 轮次入史时，assistant 位写简句「（本轮回复被系统拦截，原因见系统告示）」，告示全文改走 system 位并带尾注「系统专用格式，禁止仿写」（与对账信标同规，R2v2 教训）。
- 前端（liveProvider/ChatFlow）：真告示（claim_check.blocked 或 forgery 的 SSE 事件）渲染为**系统横幅样式**（区别于 AI 聊天气泡：不同底色/边框/图标），让人一眼分清系统说话还是 AI 说话。

### ② 半途死亡留档（server.mjs）

- `/api/chat` 增加 `req.on('close')` 兜底：轮末未正常 archiveRound 时（连接中断/异常），以现有已收到的事件落中断档（`error: 'connection_aborted'`、assistant_text=已累积部分文本）。消灭死无对证。
- 注意与正常完成路径去重（正常 archiveRound 后不再补写）。

### ③ 上游调用超时（server.mjs callUpstream）

- fetch 加 AbortController 超时（默认 120 秒，可用 `.env` 的 `UPSTREAM_TIMEOUT_MS` 调）；超时给前端发 error 事件「上游响应超时（120s），请重试」并正常走留档。不许无限挂起。
