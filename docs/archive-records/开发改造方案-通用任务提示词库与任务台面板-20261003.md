# 开发改造方案：通用任务提示词库 + demo-ui 任务台（2026-10-03，v0.1）

> 起草背景：新开任意 AI 对话框无法直接下达"改数据库/做场景/跑矩阵"等任务，每次要靠统筹 AI 现写提示词。
> 根因（2026-10-03 查明）：提示词其实已存在（`F1-AI\skills\` 三个 SKILL.md），但没挂到任何入口；demo-ui live 模式每段只有一句话 system prompt。
> 本方案未动工，先评审。

---

## 0. 一句话方案

demo-ui 在**保留四段剧本演示**的同时，新增「任务台」页：按任务模板一键生成**自包含工单（纯文本提示词）**，可复制贴给任意 AI 基座（Claude/GPT/Kimi/其他）执行，或落盘 `LabConsole\workorders\` 并回显进度。提示词库按"总纲当目录、拆份当正文、公共约束拼接"分层组织，事实源在 `F1-AI\skills\`。

## 2. 总体架构

```
demo-ui（8085 同源，/demo/ 与 /demo-dev/）
 ├─ 演示模式（现状不动）：四段剧本 + live 聊天（proxy /api/chat）
 └─ 任务台模式（新增）：
      ├─ 任务列表 ──读── public/data/tasks.manifest.json
      ├─ 参数表单 ──由── 各 SKILL.md 的 params 字段生成
      ├─ 工单预览 ──拼── _公共约束 + SKILL.md 正文 + 本次参数 + 验收条款
      └─ 状态看板 ──读── workorders 状态文件

proxy server.mjs（新增 3 个接口，/api/chat 不动）
 ├─ GET  /api/tasks               → 任务清单
 ├─ POST /api/workorder           → 组装工单 → 落盘 + 状态登记 → 返回全文与路径
 └─ GET  /api/workorder/status    → 看板数据

提示词库（事实源）F1-AI\skills\
 ├─ _index.md                      总纲：任务目录与地图
 ├─ _公共约束.md                   表达规范/汇报纪律/桥雷区/验收三查（从各 SKILL 抽取）
 ├─ 构想澄清与实验设计/SKILL.md    （已有 v1.2）
 ├─ 想定落地与试车/SKILL.md        （已有 v1.6）
 ├─ 数据库修改与管理/SKILL.md      （v0.2 初稿，转正 v1.0 列入待办，不阻塞面板）
 └─ 矩阵跑批与统计/SKILL.md        （新建 v0.1，从 LabConsole 沉淀）
```

## 3. 改造明细

### 3.1 提示词库整理（F1-AI\skills\，半天~1 天）

1. **抽公共约束**：从三个 SKILL.md 抽取重叠段（表达规范、汇报纪律、owner 许可铁律、桥雷区、验收三查 K150），合并为 `_公共约束.md`；各 SKILL.md 删除重复段，改为一行引用"见 _公共约束.md"。
2. **总纲 `_index.md`**：任务目录表（任务名/适用场景/输入/输出/SKILL 路径/版本/状态），新对话或人一读就懂拿哪份。
3. **补 params 字段**：每个 SKILL.md frontmatter 增加 `params:`（表单字段清单，含类型/必填/默认值/说明），面板据此自动生成表单。例：
   - 想定落地与试车：`实验设计文档`（下拉，列 `实验设计文档库\`）、`想定命名`、`蒙卡批数`、`判据口径`
   - 数据库修改与管理：`数据库路径`、`修改范围说明`、`方案名`、`owner 许可原文`（必填，许可门在表单层拦截）
   - 矩阵跑批与统计：`场景矩阵 spec`、`蒙卡次数`、`统计口径`
4. **新建《矩阵跑批与统计》SKILL v0.1**：沉淀来源=LabConsole\knowledge.md 矩阵相关 K 条目、probes\gen_geometry_v2.py、mc_stats_muteam.py、自愈监管器纪律。
5. **数据库 SKILL 转正 v1.0**：68 行规格扩成可执行步骤（决策树→许可→copy-for-edit→guard-check→小步快走验证→台账校验→审计），单独排期，不阻塞面板。

### 3.2 proxy 扩展（demo-ui\proxy\server.mjs，1 天）

- `GET /api/tasks`：返回 `public/data/tasks.manifest.json`。
- `POST /api/workorder`：body `{taskId, params}`。服务端读 `_公共约束.md` + 对应 `SKILL.md` + params → 按固定模板组装工单（标题/背景/自举段/任务步骤/本次参数/交付与验收/汇报纪律）→ 写 `LabConsole\workorders\_panel\<taskId>-<时间戳>.md` → 在 `_panel\status.json` 登记（id/状态=已下发/时间/路径）→ 返回工单全文+路径。
- `GET /api/workorder/status`：读 status.json 回看板。
- 开发期落盘只用 `_panel\` 隔离目录，验收后切正式 workorders 根目录（开关放 demo.config.json）。
- `/api/chat` 与 `prompts.js` 不动（演示 live 不受影响）。

### 3.3 前端任务台（demo-ui\src\，2~3 天）

- 新增 `pages/WorkbenchPage.tsx`：左=任务列表，中=参数表单，右=工单预览（含【复制】【下发】按钮），下=状态看板。
- 新增组件：`TaskForm.tsx`（按 manifest 渲染）、`PromptPreview.tsx`、`TaskBoard.tsx`。
- `FullPage.tsx` 顶部加「演示｜任务台」切换（新增切换条，**四段面板组件零改动**）。
- `config/demo.config.json` 增加 `workbench` 配置段；新增 `public/data/tasks.manifest.json`（任务目录，首期手工维护，与 _index.md 同源）。
- 风格沿用暗色监控台（底 #06080f，玻璃拟态）。

- **验收后**：按《交接文档-演示界面与F1-BS集成-20260916.md》§4.2 部署到 /demo/，`f1bsEmbedUrl` 的 `?v=` 递增。

## 5. 并行使用答复（开发期间能否同步用现有工具改库等）

**可以，互不干扰。** 隔离线：

- **开发只动**：`F1-AI\demo-ui\`、`F1-AI\skills\` 增量文件、`LabConsole\workorders\_panel\`（隔离目录）。
- **改库走现有链**：`LabConsole\tools\dbtool\dbtool.py` 六子命令 + `D:\soft\F1\F1-测试\DB\`（copy-for-edit 出副本、台账、guard-check、审计），与 demo-ui 开发零交集；数据库 SKILL v0.2 现规程即可用。
- **开发验证不碰生产想定/库**；面板开发期不下发到正式 workorders 根目录；任务台开发不启动 F1.exe 推演引擎。
- 唯一共享点=workorders 目录，已用 `_panel\` 子目录物理隔离。

## 6. 验收标准

1. 任务台选「想定落地与试车」填参数 → 生成工单全文 → 复制到**任意新对话**（任何基座）可照单执行，执行方不再需要统筹 AI 补提示词。
2. 工单下发后看板可见状态，执行完成可回显。
3. 演示模式四段剧本 + attach 观战回归通过（交接文档 §6 清单）。
4. 开发期间并行完成至少一次真实改库操作，与开发互不干扰。
