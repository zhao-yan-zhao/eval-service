## 开火可行性自检（落地必查，五项缺一不许进试车）

建完想定、起跑试车**之前**，必须逐项完成以下五项自检。任何一项答不上来或答"否"，先修再想定起跑——**零发射的局跑出来不计入试车轮次，纯属浪费**。

### 自检 1：任务类型与目标类型匹配

- 打地面目标（车辆、阵地、设施）→ 必须建**对地打击**类任务；打舰艇 → 对海打击类。
- 查法：建任务时明确指定目标域；建完回读任务摘要确认任务类型与设计意图一致。
- **当前缺口（修好前按下执行）**：接口程序的"对地打击任务种类"正在修复（问题台账 Q-001）。修好之前，对地目标只能用"巡逻任务 + 谨慎开火"近似替代，且必须在想定备注和评判卡上**明示这是降级方案**，判读时不得把"零发射"记为设计失败。

### 自检 2：弹药真实挂在平台上、且打得动这类目标

- 挂载要**回读确认**：单位建成后查载荷状态，载荷为空 = 挂载没成功，不许起跑；
- 弹药用途要与目标匹配：空地弹药打地面、反舰弹药打舰艇——逐弹药查装备库的用途属性，**禁止凭印象认定**；
- 巡飞弹、诱饵等有特殊发射机制的弹药，选型时先核实"本平台能不能正常发射它"（查挂载方案与发射记录类战例），核实不了就换常规弹药并在缺口清单登记。

### 自检 3：发射包线（高度、速度）可达

- 实证教训（10-10）：飞行高度过高时弹药无法投放，手动降高后才能开火。
- 查法：设计航线时，把**发射点的高度和速度**对照弹药发射条件核查（库里有发射包线数据的逐项对；没有的按同类弹药的通用包线粗核，并登记知识缺口）；
- 任务航线的巡航高度 ≠ 发射高度时，要在任务或事件里设计"发射前降高/降速"动作，不许指望试车时人工补救。

### 自检 4：开火权限与条令正确

- **默认"谨慎开火"**（识别确认目标后才开火）——这是默认值，不用用户说；
- **"自由开火"（探测到即打）只在用户明确说了"发现就立刻打"时才允许用**，且要在评判卡上明示；
- 电磁管控与雷达默认状态沿用既有纪律（默认严控、雷达默认关，需要开机必须在设计文档里有依据）；
- 查法：设置后回读条令状态，确认与意图一致。

### 自检 5：识别链路能闭合

- 谨慎开火的前提是"能识别"：平台传感器（雷达/光电）的开机状态、探测距离、目标信号特征三者要能凑出一条识别链；
- 目标全程处于传感器探测距离之外，或传感器全程不开机 → 识别链断裂 → 必然零发射；
- 查法：在纸上（或文档里）推一遍"探测→识别→开火"的完整链条，每个环节写明靠什么实现；推不通就改设计。

### 自检结果的记录与判读联动

- 五项自检结果（过/不过+理由）写入留档文件，不向用户逐项播报；
- 试车判读时：**出现开火类事件记录 = 开火链路通的唯一证据**；零发射一律按不合格进返修环，返修第一步就是回查这五项哪项失守；
- 返修环满 3 轮仍零发射 → 熔断报告，把五项自查表带给用户定夺。
