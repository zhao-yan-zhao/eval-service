# 交接提示词：演示界面开发（2026-09-15）

> 你是界面开发工程师。任务：为一套"AI 辅助作战实验系统"开发一个**演示用界面**，目的是让听众在汇报演示时一眼看懂系统的工作流程。本提示词包含你需要知道的一切；没提到的一律不用关心。工作目录 `D:\soft\F1-AI`，界面项目放 `D:\soft\F1-AI\demo-ui\`（新建子目录，别动其他任何目录）。

## 一、系统是什么（理解背景，够写文案即可）

这套系统把"一句战法构想"变成"有统计结论的推演实验"，全流程四段：

1. **构想澄清**：操作员把战法/场景构想用自然语言告诉 AI；AI 调用实战案例知识库（2388 篇真实战例与文献），产出装备选型、部署方案、编成建议——并指出构想里的问题，不是照单全收。
2. **实验设计**：AI 把澄清后的构想写成一份严谨的实验设计文档（实验目的、变量、合格判据、想定要素）；操作员可以提改进意见，AI 修改，直到操作员认可。
3. **想定生成与推演**：AI 按文档在专业推演系统里自动建场（部署单位、设任务、配规则、埋判据），自动运行推演、自动判读结果；不合格自动返修（最多 3 轮）。
4. **统计评估**：AI 对想定做蒙特卡洛批量推演（粗筛每场景 20 局、细筛 50 局），统计成功率、战损、消耗，产出带置信区间的结论和评判卡。

**演示文案纪律（重要）**：界面给观众看，一律用人话——四段叫"构想澄清 / 实验设计 / 想定生成与推演 / 统计评估"；**禁止出现** K 编号、LAB 编号、TP 编号、错误码、内部文件名、函数名这类内部代号。

## 二、界面需求（owner 原话的结构化，照做）

### 整体布局：上下两区

- **上区：流程进度条**。四个节点对应上述四段，**完成一段亮一段**（未开始=灰，进行中=闪烁/高亮边框，已完成=点亮+对勾）。进度状态全局共享，切换页面不丢。
- **下区：主体**，四段每段一个面板。每个面板统一布局：**上部=AI 输出区，下部=输入框**（操作员在此输入需求/改进意见）。

### 四个面板的内容定义

| 面板 | AI 输出区显示什么 | 输入框干什么 |
|---|---|---|
| ① 构想澄清 | AI 基于实战案例库给出的装备、部署、方案（对话流形式） | 操作员输入战法构想、追问、调整 |
| ② 实验设计 | AI 生成的实验设计文档**内容**（渲染成可读文档，不是文件下载链接） | 操作员输入改进需求，AI 改稿 |
| ③ 想定生成与推演 | 见下面"待定项"——两种方案 | 操作员输入改进需求 |
| ④ 统计评估 | 统计结果：成功率+置信区间、双方战损对比、弹药消耗、结论一句话（图表化） | 操作员输入改进需求 |

### 四个面板还要能拆成独立界面

四段可以各自独立成页（单独打开、单独演示）。架构建议：一个共享的顶部流程条组件 + 四个可独立访问的路由页面 + 状态持久化（localStorage 或本地 JSON 文件），这样"整页全流程演示"和"单页分段演示"两种用法都支持。
