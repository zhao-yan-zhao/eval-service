`AiAssistantCompositionRoot.CreateProductionRuntime` 中 `orchestrator.RecoverOnStartup()` 为裸调用（原 best-effort try/catch 在 5d07372 中被删，owner 已拍板认可删除方向）。现状问题：RecoverOnStartup 抛出的异常会**直接上抛穿出装配流程**，而不是走"返回 disabled runtime、宿主存活"的初始化失败模式。这违反批5 冻结合同 3 末段："生产 runtime 可按现有初始化失败模式返回 disabled runtime，但不得使整个 F1 宿主退出。"

4. 正常路径（RecoverOnStartup 不抛）行为零变化；验链失败提前 return 的路径零变化。
