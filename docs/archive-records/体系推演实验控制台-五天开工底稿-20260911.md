## 一、目标与非目标

**目标**：跑通一条真实、可演示、可复验的推演实验闭环——

```
战法假设（人+LLM，OKF 知识支撑）
  → 候选想定生成（基准复制 + 审批后的 Lua 变更）
  → 多变体 × 多轮次蒙特卡洛批量推演（进程内、串行、无人值守）
  → 数据归一化与指标统计（程序计算）
  → LLM 归因解读、提出下一轮候选（人批准后迭代）
```

**非目标（五天内不做，进 PPT 演进路线页）**：无头独立进程 runner、MCP 服务、OKF RAG 深度接入、自动闭环（无人工审批的全自动迭代）、多实例并行跑批、通用平台化。

## 三、架构（已核实的关键事实为依据）

```
外部 AI / 操作人员（API/CLI，五天内不做 MCP）
   ↓
实验控制台（新建独立模块：候选管理、Lua 审批、实验队列、指标与报告）
   ↓ 本机调用
F1 进程内批量实验服务（新建适配器，挂在已初始化的 F1 内）
   ├─ 基准想定复制 → 执行已批准 Lua → 保存候选 .scen → 回读验证
   └─ 候选 × 变体 × 轮次 蒙特卡洛串行跑批
   ↓
事件 CSV / 日志 / 自定义 Lua 输出（按 RunID 归档）
   ↓
数据归一化 → 指标计算（Python/控制台内）→ 统计摘要 → LLM 归因
OKF：只读消费已发布成果包；知识缺口走异步"更新请求单"，不驱动同事 Claude Code 工作流。
```

已核实事实：

- 蒙特卡洛核心循环**本就无头**：`MonteCarloForm.cs` L500–581，`ScenContainer.LoadFromFile` → `RunningHeadless=true` → `GameGeneral.MainGameLoop` 至 `HasEnded`，输出走 `EventExporterManager`（带 MonteCarloID/迭代号）。进程内批量服务复用此模式，无需解决独立进程的许可/数据库/初始化适配。
- Lua 沙盒建场 API 完整：`ScenEdit_AddSide/AddUnit/AddMission/AssignUnitToMission/SetSidePosture/SetDoctrine`（`LuaSandBox.cs` L390–605）。
- **保存路径**：Lua 无 `ScenEdit_SaveScenario`；用 `Command_Core\LoadSave\LoadSave.SaveScenario()`，项目自有 `ProductionSmokeHarness.cs:1298` 已有 `SaveToFile` 先例。**无头场景对象的保存与回读列为 D2 必验点。**
- 7777 裸 Lua 端口监听所有网卡，禁止作为系统接口；外部 AI 只能走审批链。

## 四、组件与五天排期

### 组件

1. **想定内容包**（人工+Lua 构建脚本）：装备映射表（比赛装备→数据库条目→参数核对→差异记录）、红方编队（含基本反应能力：防空交战/机动/电子战，强度需校准）、蓝方体系。
2. **候选生成链**：基准想定复制 → Lua 草稿上传 → 静态检查与差异预览 → **人工批准脚本哈希** → 候选副本执行 → `LoadSave.SaveScenario` 保存候选 .scen → 回读验证。
3. **批量执行器**：进程内串行队列；每轮独立 RunID/TimelineID/输出目录；重新从 .scen 加载（不串状态）；超时/取消/失败记录；基准想定只读不覆盖。
4. **结果管线与指标层**：CSV 归一化（字段映射显式登记：TimelineID 变体、Side/UnitSide 差异、跨目录重复 ID——已知坑）；程序计算：任务成功率及置信区间、红蓝战损、发射/命中/消耗、首次关键事件时间、交战周期、效费比；LLM 只解释统计摘要，不自算胜率。
5. **演示证据层**：报告引用可回溯到指标编号与原始 CSV；版本与审批记录留档。
