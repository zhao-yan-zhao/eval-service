# 方案：面板 AI 编造根治（2026-10-14）

## 一、发生了什么（事实层）

T0 试车期间，面板 AI（DeepSeek）两次整轮编造：

1. 变体案 1「另存成功/跑局成功/读结果成功」——实际零工具调用，目录里没有任何文件，被你戳穿；
2. 变体案 2 又原样来了一遍。

claimcheck（声明校验器）每轮都挂了「零工具调用」警告牌，但**警告牌和编造的原文一起发出来了**——它只标记、不拦截。所以你的体验是：牌子挂了十几轮，它照编不误。

## 二、根因（四层，按贡献排序）

1. **代理层只标记不拦截（主因，本次修）**
   设计时定的是「标注档」：命中编造就前置一句警告，原文照发。当时的假设是"挂了牌子模型会收敛"。DeepSeek 不收敛——这就是你看到的"警告挂满了还在编"。
   代码事实：server.mjs:721，`verdict='marked'` 时 `marker + 原文` 一起发给前端。

2. **基座纪律性弱（真实存在，但不是全部）**
   Claude 时代也挂过牌子，但 Claude 被挂后会改口；DeepSeek 被挂后照编。这是基座差异，没法靠提示词根治——所以本次同步把 MiMo 接进来做 A/B 对比，数据说话。
   **诚实结论：换基座只能降低编造频率，不能根治。根治靠第 1 条的硬拦截——不依赖模型自觉。**

3. **"有工具调用就全过"的洞（v2 欠账，本次补一半）**
   现行规则：本轮只要有 ≥1 次工具调用，文本里的断言一律放行（v1 批复时定的，说"出现带工具调用的编造实例再升级"）。这次是零工具调用所以被抓到了；如果它先随便查个库再编"跑局成功"，现在拦不住。逐断言对账（声称另存 → 必须真有另存工具事件）是大活，本次先做硬拦截，逐断言对账登记为后续工单。

4. **计划轮误报风险（顺带核）**
   提示词要求 AI 先报计划等确认，计划文本里的"执行/验证"等词可能误命中。这次记录里计划轮没误挂（将来时过滤起作用了），但要在本次单测里补回归用例钉死。

## 三、修复方案（三件事，一个 Cursor 窗口）

### ① claimcheck 升 v2：marked = 硬拦，原文不进前端

- 命中编造时，前端收到的不再是"警告牌+原文"，而是固定告示：
  「本轮未执行任何工具，以下自述动作均无效：{命中断言清单}。请重新下达指令。」
- 原文只进审计日志（m6-claim-audit.jsonl）和会话留档，**不落前端聊天框**。
- 选配项：自动重试一次（把"你声称完成但没有工具记录，请如实重写"喂回模型重说一遍，重试仍命中才替换告示）。能救回"总结上一轮真实结果"的合法场景。工作量让 Cursor 先报，超 2 小时就砍，只做替换。

### ② proxy 多模型配置：DeepSeek 与 MiMo 并存，一行切换

- Key 存哪：`demo-ui/proxy/.env`（已核实：该文件在 .gitignore 里，不会进仓库；proxy 只监听 127.0.0.1，key 不出本机）。
- .env 里并存两套：

  ```
  DEEPSEEK_API_KEY=（现有，不动）
  MIMO_API_KEY=（你的 MiMo key，sk- 开头）
  MIMO_BASE_URL=https://api.xiaomimimo.com/v1/chat/completions
  MIMO_MODEL=mimo-v2.6-pro
  ACTIVE_PROVIDER=deepseek   ← 想切就改这一行，重启 proxy 生效
  ```

- `/health` 显示当前在用哪家、哪个模型、key 是否就位——切没切上一眼可查。
- 热切换接口（不重启切模型）：让 Cursor 评估工作量后报，再决定做不做。

### ③ MiMo 适配：reasoning_content 回传

- MiMo 开思考模式 + 工具调用时，后续请求必须原样回传上一轮的 `reasoning_content`，否则直接 400。
- proxy 有两条把 assistant 消息塞回对话历史的路径，一条天然带得回，一条会丢（文本工单兜底模式重建了消息对象）。两条都修。
- 另留一个 `.env` 开关 `MIMO_THINKING=off`：关掉思考模式就不需要回传（字段名以 MiMo 官方文档为准，Cursor 实现前先核实，核实不到就留透传扩展点）。

## 四、验收口径

- `npm test:all` 全绿（基线 153 pass）+ 新增用例覆盖：硬拦触发、计划轮不误拦、reasoning_content 回传、双模型配置加载；
- 真机冒烟两轮：DeepSeek 回归一轮（确认没改坏）+ MiMo 冒烟一轮（带工具调用的对话，确认不 400）；
- 冒烟通过后再跑基座 A/B：同一道 ③ 段建场考题，DeepSeek 和 MiMo 各跑一遍，对比编造率/纪律性，再定默认基座。

## 五、不做的事（本次明确排除）

- 逐断言对账（声称另存 ↔ 真有另存事件）：登记为后续工单，等硬拦上线后看审计数据再定；
- 换基座替代硬拦截：两件事独立，互不替代；
- guard / 租约 / dbgate 语义：本次一律不动。
