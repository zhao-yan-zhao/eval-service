## 1. 开发篇

### 1.1 架构总览

```
用户/AI 对话
   │  读 skills（流程）+ knowledge.md（坑）+ OKF（领域知识）
   ▼
桥（HTTP 127.0.0.1:9477/invoke，Bearer token）
   │  POST {"tool":"...","args":{...}}  ← 一律 python urllib（curl 发中文 JSON 必炸）
   ▼
F1 仿真程序（D:\soft\F1-AI\F1\F1.exe，经 start-F1-with-bridge.bat 启动才带桥）
   │  C#：CMO-netcore-src（Command_Core 改造）+ AiAssistant（桥/工具层）
   ▼
想定文件（.scen = XML 头 + AES 加密压缩本体，不能直接 grep）
   │
   ▼ 推演 → 事件 CSV 导出（EventExport/ai/{task}/{run}/）
qa_gate 判读 + 判据编译器 + 蒙特卡洛跑批 → 评判卡 → 人裁决
```

**环境三要素**（缺一个全链就断）：
1. F1 单实例运行，且经 `D:\soft\F1-AI\start-F1-with-bridge.bat` 启动（直接双击 F1.exe 不带桥）；
2. token 在 `LabConsole\workorders\.bridge-token`（全文即 token）；
3. F1 的 AI 助手面板点开过一次（历史遗留，新构建未验证是否仍需）。

### 1.2 桥 20 工具（2026-09-14 现状）

| 类别 | 工具 | 要点 |
|---|---|---|
| 想定 | scenario.load / .save / .get_summary / **.set_time** | set_time 设开始时刻+推演时长（分钟），带读回校验；无 scenario.create（从零建场走模板通道） |
| 单位 | unit.add / .update_position / .status | 支持 Aircraft/Ship/Facility/Submarine；Aircraft 必须 loadout_id；**陆基 Facility 放水面会被地形检查拒**（K88） |
| 任务/条令 | mission.create_or_update / doctrine.set | 任务类型只 patrol/strike 可用；patrol 需参考点（K85） |
| 事件 | event.upsert | 触发器：time（绝对时刻，K89）/ **unit_destroyed**（按单位或阵营+类型+dbid 过滤）；动作：send_message/set_doctrine/activate_mission/**end_scenario**；带三重读回校验 |
| 推演 | simulation.run / .stop / .status / **.recover** | run 是异步 job；想定自然结束自动收工（stop_reason=scenario_ended）；recover 治 stop_unconfirmed 卡死（K86，待真机验证） |
| 结果 | result.read | 读 run 的 CSV 事件数据，支持聚合 |
| 模板 | template.execute | 执行已登记的审核 Lua 模板（registry 在 `D:\soft\F1\F1-测试\templates\registry\`），哈希防替换；判据埋点/精细逻辑的唯一通道 |
| 数据 | db3k.search / contact.query / referencepoint.list / area.query | db3k 查装备数据库（dbid/载荷查证用） |

**铁律：每个写操作必须读回校验**。沙箱非交互模式吞 Lua 异常，"没报错"≠"改成功"（K88/K89/K90 三连教训）。新写工具一律带 C# 侧读回。

### 1.3 F1 源码侧关键事实（改了会踩坑的地方）

- **Lua API 以 `Command_Core/Lua/PrivateMethods.cs` 为准，CMO 官方文档不可信**（K84：文档示例的字符串调用会静默空操作）。
- 事件名存在 `SimEvent.Description` 不是 Name（K90）；SetStartTime 的 DATE 必须带 `:` 分隔、DURATION 是 `days:hour:min`（K90）；Time 触发器是绝对 DateTime，裸数字会被解析成 DateTime 二进制 1 立即触发（K89）。
- 沙箱 wrapper 家族（LUA_ScenEdit_*）非交互模式全吞异常；目前只有 AddUnit 修了透出，其余同症（K88 预防条）。
- `Scenario.EndScenario()` 无 UI 弹窗，headless 安全；MainGameLoop 每脉冲跑事件引擎并检查 `Time > StartTime+Duration` 自动结束（K89）。
- scen 本体：`<Scenario_Compressed>`，CompressVersion=5 = [4 字节 IV 长][IV][AES(LZ(XML))]，密码在 GameGeneral.cs:718（K90）。

## 2. Skill 使用篇

### 2.1 两个 skill（归设计链维护，流水线不许直改）

| skill | 路径 | 干什么 |
|---|---|---|
| A 段：构想澄清与实验设计 | `skills\构想澄清与实验设计\SKILL.md` | 用户口述构想 → 实验设计文档（存想定库\） |
| B 段：想定落地与试车 | `skills\想定落地与试车\SKILL.md` | 设计文档 → 可跑 .scen + 自动返修 ≤3 轮 + 评判卡 |

- 修改需求报 owner 转设计对话，或记 knowledge.md 由设计对话吸收（两个 skill 开工都强制读 knowledge.md 尾部，坑知识由此回流）。
- **OKF 是一等知识源**（`LabConsole\okf\` 与 owner 指定 OKF 目录），控制台做内容判断时优先甚至只用 OKF；大赛文件不作依据（除非用户明确参赛）。
- owner 钦定建场纪律七条：分层控制/条令优先/数据表优先/轻量化/性能精简/结束纪律/全局变量延迟一秒——B 段强制规则。

### 2.2 用户全流程（人只做评判官）

```
人说构想 → [A 段] 实验设计文档 → 人确认 → [B 段] 候选想定
→ 自动试车（set_time 设时长 → simulation.run → result.read + qa_gate 判读）
→ 不合格自动返修 ≤3 轮 → 人话评判卡 → 人裁决 → 批量变体蒙卡 → 统计对比 → 迭代
```

### 2.3 挂载新模型测试

提示词模板：`提示词-全流程挂载测试-20260914.md`（自包含，直接贴）。硬前提：**模型必须有文件+shell 工具能力**（纯网页聊天模型不行）。评判挂载质量 = 候选想定 + 评判卡 + 返修≤3 轮 + 全程零人工动作；模型卡壳的失败回执是改进 skill 的最好输入。

### 2.4 knowledge.md 铁律

1. 开工先读尾部 15 条；2. 新坑四段式入库，编号 grep 最大+1；3. 与 skill 冲突时以知识库为准并报冲突；4. 桥工具文档不全时以 knowledge.md 为准。

### 3.2 任务生命周期

```
TASKS.md 取任务 → 派工程师（带追因结论+文件行号+测试范式+真机验证脚本的工单）
→ 实现+自测 → 送审理（独立实跑，不只读 diff）→ 通过=收编提交 / REJECT=返修
→ 同任务 ~4 轮不收敛=熔断（改专修通道或监理直办，不阻塞其他任务）
→ 闭合判据=一手实证（复跑/真机/哈希对账），"执行端报过"不算过（K57）
```

- 高危件"过审≠闭合"，闭合=真机验证（LAB-18 先例）。
