# 地狱景观：分布式低成本无人蜂群对抗大型海上舰队实验想定

文档版本 2；设计修订 2。这是设计文档；平台构建与运行验证另行记录。文档完整性检查不证明功能已实现；正文中的待实现建议不等于配置已经写回。

## 一、实验目标与想定背景

**主题**：红方大型海上舰队体系穿越狭窄海域，蓝方以“地狱景观”式分布式低成本无人系统实施消耗、饱和与突防。

**目的**：量化蓝方巡飞弹蜂群、无人艇屏护和防区外发射器对红方编队防空资源、舰艇完好率与通行时间的综合影响，形成可复用的实验设计。

**想定设定**：2026-06-01 08:00Z起，持续7200秒；西太平洋某海峡及以东海域；海面风3级、能见度良好、无中立商船。红方编队以18节南向穿越，蓝方在航道东侧预设伏击区与岸基发射阵地。

**关键问题**：
1. 4个发射阵地共108枚Harop分波次攻击，能否耗尽红方编队近程防空弹药并形成突防？
2. 红方VLS防空弹消耗与舰艇毁伤的交换比是多少？
3. 蓝方LUSV与Typhon阵地在红方反击下的存活时间有多长？
4. 红方是否被迫改变航路、延迟通过或分散编队？

**说明**：坐标、兵力数量、速度与初始状态均为本次设计选择，不是情报结论；平台尚未构建，也未运行推演。

**过程设计**：
1. T+0红方开始穿越，蓝方无人艇屏护任务同时运行，保持被动探测。
2. T+300 Altius蜂群前出，建立目标指示链，为岸基与海上发射器提供舰位更新。
3. T+600第一波Harop发射，优先攻击南昌舰（防空核心）与福建舰；首波以消耗红方近程防空弹药为主。
4. T+900 LUSV与Typhon进入防区外打击待命；一旦红方舰艇受损（E4），立即对航母与防空核心舰实施导弹突击。
5. T+1800红方转入反击，南昌舰与昆明舰临时转出，使用舰舰导弹和主炮清除进入伏击区的蓝方无人艇；任务结束后归建。
6. 后续波次由Harop阵地按剩余弹药继续实施，直至T+5400或发射力量被毁。

**控制说明**：红方反无人艇打击为独占任务，转出期间不再承担原巡逻任务；这是有意的指挥取舍，便于观察“反击窗口”对编队防空的削弱。任务类型采用平台原生的patrol/strike；桥接层当前仅实现这两类，其他子类需在原生编辑器中手工映射。

## 七、手工构建步骤与核对方法

1. **选库**：使用DB3K_517.db3（sha256见交接章），不要混用其他库的同名ID。
2. **建方**：创建红方、蓝方两个阵营，设置敌对关系；按第三章设置阵营武器控制与EMCON。
3. **建单位**：按第二章的库内ID逐个创建；Type 055、Type 052D、Type 054A、Harop阵地、Typhon阵地存在多条同名记录，本设计固定使用表中ID，不要用名称自动匹配。

8. **建事件**：先建时间触发事件（E1、E2、E5、E8），再建条件事件（E3、E4、E6、E7）。条件事件若桥接层不支持，转到原生编辑器添加UnitEntersArea、UnitDamaged、UnitRemainsInArea等触发器，或安排专人按核对方法手工判定。

**运行后记录**：至少保存事件日志、单位状态时序、武器发射日志和人工爆点记录；报告时区分“设计已登记”“平台已构建”“运行已验证”。
