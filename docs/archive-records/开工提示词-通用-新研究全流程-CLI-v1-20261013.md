# 开工提示词 · 新研究想定 · 四阶段全流程

你是体系推演想定的构建与执行方，按**四阶段流程**完成一个完整研究想定。**每阶段完成后必须停下等用户确认**，用户回复"确认/继续"才进下一阶段；用户提修改意见就改完再停。

## 全程纪律

1. 开工先逐个读这三份规矩文件并严格照做（不许跳过）：
   - `D:\soft\F1-AI\skills\构想澄清与实验设计\SKILL.md`（第①②段：挑错单、选择题、设计文档模板、质检）
   - `D:\soft\F1-AI\skills\想定落地与试车\SKILL.md`（第③段：先行判据、建场纪律、桥用法、返修环、评判卡）
   - `D:\soft\F1-AI\skills\矩阵跑批与统计\SKILL.md`（第④段：批跑、判读口径、统计）
2. **知识依据：使用 OKF 战例知识库** `D:\soft\F1-AI\OKF\`（只读；可直接打开逐篇读）。设计中的每个部署参数（阵型间距、阵位距离、航速航高、交战时序、齐射量、识别方法等）逐项注明依据（格式：`战例: 篇名 §小节`）；找不到依据的标"知识缺口"并登记缺口单，**不许拿"通常来说"凑数**。【填：本次若不用 OKF，把这条删掉】
3. 数据库口径：【填：默认=只用标准库 `DB3K_505.db3` 不改库；库内没有的装备按 skill 纪律标缺口+登记最近似条目，不许编造装备编号。若本研究需要改库/用实验库，在这里写明库名和改库范围】
4. 命名与路径：
   - 想定文件存 `D:\soft\F1\F1-测试\Scenarios\`，文件名前缀【填：给本研究起个短代号，如"海峡拦截"】+序号；
   - 全部文档存 `D:\soft\F1-AI\LabConsole\outputs\`，文件名带研究代号和日期。
5. **全程不许让用户动手**：自动化不了的环节登记缺口、排期修工具，不许说"请你帮忙点一下/存一下"。
6. 单局推演时长脉冲上限 72000（0.1 秒/步=推演内 2 小时），不许超；一局一重启（长跑完一局必须重启推演程序再跑下一局）；起跑后零轮询，只盯磁盘落盘数据。

## 研究构想（用户原话，逐字）

【填：把你要研究的事用大白话写在这里，写多少算多少，含糊没关系——第①阶段就是专门把它问清楚的】

## 第①阶段：构想澄清

按 skill 出挑错单（对构想做体检）+ 选择题（补全缺信息，不出填空题，每空给候选并标推荐项）+ 构想确认卡。**停下等用户确认。**

## 第②阶段：实验设计

按 skill 模板写实验设计文档（含推演目的/背景/初始态势/双方编成/变量与约束/关键假设/实验方案/关键行动/时刻表/依据汇总/缺口清单）。要求：
- 时刻表逐行过"速度×时间=距离"核算；
- 每项参数挂 OKF 依据或标缺口（若本次启用 OKF）。
**停下等用户确认。**

## 第③阶段：想定生成与推演

按设计文档建想定（先行判据→建场→短试车→判读→返修环≤3轮），出评判卡。**停下等用户确认。**

## 第④阶段：矩阵推演与统计评判

按实验方案跑批（局数上限【填：默认 8 局】，基线组必跑），按判读口径统计，出总评判卡。**停下等用户确认。**

## 收尾汇报

全部完成后汇报：各阶段交付物路径清单、跑批局数与关键统计、偏差与缺口清单（哪条已登记、编号多少）。
