## 1. 这个应用是什么

demo-ui 是一个四段式演示+实操面板（React 前端 + Node 代理），对应体系推演的四个阶段：

| 段落 | 干什么 | 注入的规矩文件 |
|---|---|---|
| ① 构想澄清 | 用户说想法，AI 挑错补全 | 构想澄清与实验设计 |
| ② 实验设计 | 出实验设计文档 | 构想澄清与实验设计 |
| ③ 想定生成与推演 | 建想定、跑推演、（含改库确认门） | 想定落地与试车 + 数据库修改与管理 |
| ④ 统计 | 蒙卡批跑结果统计 | 矩阵跑批与统计 |

**正在进行的改造（v1.0 方案）**：让面板里的 AI 从"只会聊天"变成"懂规矩、能动手"——自动读规矩文件、经 proxy 调桥 9477 工具真建想定/跑推演/读数据。用户体验目标：大白话下任务，零复制粘贴。

## 4. 架构与安全设计（不许破坏的）

```
用户 → 四段对话框 → proxy（127.0.0.1:7177）
  ① 规矩注入：按段落把 SKILL 全文拼进 system 发给模型（proxy/.env 可换模型，默认 deepseek-chat）
  ② 工具循环：AI 声明调工具 → proxy 转发桥 9477（令牌只在服务端）→ 结果回喂 → 循环到完成；流水 SSE 推前端
  ③ 护栏：simulation.run 起跑后乐观锁冻结一切状态查询（先锁再起跑，失败回滚），导出稳定才解冻；拒绝重复起跑/分段续跑
  ④ 白名单分级：只读/建模/推演类放行（推演受护栏），改库类必须过确认门，白名单外一律拒绝
```

- **桥令牌只在 proxy 服务端**，前端代码禁止出现（验收曾 grep 实证）。
- **④段边界钉死**：只许触发白名单内封装好的批跑/统计脚本+读结果文件，不开任意命令执行。
- **演示模式（剧本）零回归**：剧本不接工具通道，与实战对话数据隔离。

## 6. 遗留问题与已定口径

1. **参考点缺口（M4 顺带项，owner 已拍板）**：桥面没有"新建参考点"工具，巡逻类任务程序化建不起来。定的路线：**走 template.execute 登记"新建参考点"Lua 模板，不改引擎源码、不重新编译**。若评估发现模板通道承载不了，停下报统筹重新定夺。
2. **改库确认门形态（owner 定的，不许改）**：无明入口；③段对话识别改库意图 → AI 风险提示+影响面（先 lookup 台账）→ 来回澄清需求与验证方式 → 用户明确"确认修改"（**只认用户消息原文，AI 转述不算**）→ proxy 才放行 dbtool，确认原文写审计。未确认物理拒绝。
3. **字段级修改通道**：面板 AI 走一次性 SQL 脚本（dbtool 是管理原语层不改字段，GUI 查看器 AI 用不了），九步实证路径见数据库规矩 §七，参考脚本 `LabConsole\outputs\dbtool-501work\edit_gj11_step.py`（只读复用）。
