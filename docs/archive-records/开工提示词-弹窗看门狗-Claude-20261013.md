# 开工提示词：推演程序弹窗看门狗（给 Claude Code）

> 2026-10-13 Kimi 出。问题台账 Q-003（P0，一周档任务：演示现场不能出现弹窗卡死）。
> 这是**独立小工具，不改引擎、不改桥、不占编译窗口**——纯外部进程，随时可上。

## 背景（两次实证）

- 10-10 三人测试：F1 白色弹窗阻塞流程，无法自动检测，需人工点掉（纪要问题清单 #8）；
- 10-12 无OKF 组新机实测：锚点绑定库缺失→"切换数据库"模态确认框卡死无人值守跑批，owner 手动点"是"才继续（问题与解决记录 §2）。

## 要干什么

写一个独立看门狗程序 `D:\soft\F1-AI\LabConsole\tools\popup_watchdog\`（Python，pywin32 或 UI Automation——先摸本机可用的库再定）：

1. **检测**：每 2~5 秒枚举 F1.exe 的窗口树，发现模态对话框（非主窗口的顶层窗口）即记录：窗口标题、按钮文本、截图（留 `logs\popup-<时间戳>.png`）、出现时刻；
2. **分级处置**：
   - **白名单自动点**：配置文件里登记"标题匹配模式 → 点哪个按钮"（首条白名单："切换数据库"类确认框 → 按 `<资源根>\DB\SwitchDBFileWhenError.txt` 指向的库点"是"——点之前把弹窗文本全文落盘）；
   - **非白名单**：不点！截图+报警（写报警文件 + 如有 proxy 则推一条消息），等人处置——**看门狗宁可漏报不许乱点**；
3. **看门狗自身纪律**：只发 UI 消息，不杀进程、不动文件；自身崩溃不影响 F1；启停有日志；
4. **测试**：用模拟弹窗（自己写个弹窗小程序）做正负例单测——白名单命中自动点、非白名单只报警不点、F1 不在时看门狗安静待命。
