## 2. 当时的工作方式（从过程文档还原）

七月的会话不是"让 AI 一次性写想定"，而是**人机在真引擎上闭环迭代**：

1. **接口先行**：先验证了推演引擎自带的 LuaServer TCP 接口（7777 端口），用 Python 客户端直连运行中的引擎发 Lua；为证明"真调进了游戏"，让引擎把"母平台-1"改名为"母平台-1【LUA已调通】"并弹 SpecialMessage
2. **改法**：Lua 脚本在 `lua_patches\` 里改 → `patch_event_lua.py` 写回想定 XML 的 `EventAction_LuaScript` → GUI 另存 .scen；或运行时 `dofile` 热注入立即验证
3. **验收**：接口计时（os.clock 打点）、EventExport CSV 对照、地图肉眼观察
4. **每轮留痕**：每完成一轮就把"现象→根因→改动→验收数据"追加进 `执行记录.txt`

## 3. 想定一步步做出来的全过程（Step 0→18，2026-07-15 20:02 ~ 07-21 22:00）

> 以下内容转写自 `执行记录.txt` 与 `工作备忘`，是当时的逐轮记录。

### 起点（Step 0-1，7-15 晚）
- 接手现成想定 `打击lucas-3-7-cusor.scen`（7-14 21:02 已存在）：红方 1 个母平台放约 100 架小无人机（雷达 5 + 光电 25 + 对陆 70），侦察五区"上二下三"、打击六区"上三下三"；蓝方 RP-1~4 任务区内约 50 辆 LUCAS 发射车，按"静置→开火→静置→机动→装填(删车重建)→机动"周期运行
- 第一个任务其实是**效率优化**：盘点出最大浪费是接线错误——"每次识别发射车都触发整份蓝方-02 全量裁挂架（50 车×挂架）"

### 第一阶段：性能根治（Step 2-6，7-15 20:12 前后）
- 拆掉"识别→全量裁挂架"接线；蓝方-01 改 v4.0.0-lean（STATIC 未到期不 GetUnit、生成时一次性裁挂架）；红方脚本 GUID 计数替代全侧扫描
- **验收：蓝方 Tick 134.9ms → 1.1ms（约 120 倍）**，抵近 Tick 40ms → 19.8ms
- 踩坑：热注入误调 `LauncherCtrl_Init()` 导致 42→36 辆车被 RELOAD 删掉，改为 `_LC.ready` 时跳过 Init

### 第二阶段：航路行为精细化（Step 7-9，7-15 20:35~21:25）
- **光电乱飞问题**：用户截图反馈小无人机"航向涣散、叠在一起"。接口实查发现光电飞出任务区西界（lon 120.69~120.88，区西界 120.97）；根因是单航点飞完不重规划 + 抵近瞄准点 0.85×距离回拉会甩出区界
- 修复 v4.1.0-route：责任区 3+1 闭环巡逻、采样点强制落在"区矩形∩任务多边形"、空航路强制重规划
- 用户再反馈"不要一直更新航路、同区路径重复率高"→ v4.2.0-route 改为**开放随机 4 点航段**（飞完才规划下一段、guid+时钟播种使同区各机路径互不相同、飞行中不打断）
- v4.3.0-zone-wcs：光电按侦察区指派（不跨区抢机）+ 红方空中武器 WCS=Hold（限制开火，勿自动拦 lucas）

### 第三阶段：对陆打击有效性（Step 10-11，7-15 21:40~22:00）
- 用户反馈"对陆几乎无效"。根因：打击只靠 UnitDetected 触发、每轮仅 1 发、接触 GUID 暂时消失会被永久拉黑
- 红方-03 v2.1.0-fire：独立对陆周期（~5s×最多 4 发）、取消永久停打、允许跨区借机；裁挂架恢复但节流 120s
- 入区卡顿性能包：接触缓存 TTL=12s、光电 MAX_NEW_ASSIGN=2、查伤 ≥10s 节流

### 第四阶段：红方改任务制（Step 12-13，7-15 22:15~22:35）
- 用户提出新思路："少用 Lua 改航路，探测→巡逻任务、对陆→对地打击任务，识别后把目标挂进打击任务"
- 另存新想定（不动原文件）：建 5 个巡逻任务 `侦察巡逻-区N` + 6 个打击任务 `对地打击-区N`，释放无人机时 `AssignUnitToMission`，UnitDetected 时 `AssignUnitAsTarget`
- 对陆机"先进区巡逻再切打击"（MissionCtrl v1.1.0-ingress）：增加 `对陆进区-区N` 巡逻任务，切换时机做 near（距区中心≤35nm）vs enter（进多边形）双模式对比实验

### 第五阶段：统计与终局（Step 14-15，7-20 21:15~21:25）
- 蓝方-01 v4.2.0-stats：**LUCAS 发射计数**（登记武器 4142）+ **想定结束条件**（发射车≤6 或全部损伤≥70% → 打印报告 + `ScenEdit_EndScenario`）
- 此时用户自改了 3-8 版想定，Cursor 接手 `打击lucas-3-8.xml` 并备份后注入新脚本

### 第六阶段：i16→i18 定型（Step 16-18，7-20 22:30 ~ 7-21 22:00）
- Step 16（i16，7-20 22:43）：修"后期有接触无打击机"——目标固定挂接触所在打击区、打手调过去、关键字补"发射车/Shahed"、跨区借上限 6。**同时立下交付命名约定**：`打击lucas-3-8-i{NN}-{时间戳}.xml`
- Step 17（**i17，7-21 21:57，即目标想定**）：加入**入区分段概率损耗**（AttritionCtrl 1.0.0-slice + MissionCtrl v1.3.0-attrition）——首机入区起算，每 60s 对区内存活机按角色独立掷骰 Kill：雷达 0.04 / 光电 0.05 / 对陆 0.08，每段最多 5 架；用概率损耗**代替/近似防空火力**（此版不加防空单元）
- Step 18（i18，7-21 22:00）：从用户手改加防空的 .scen 复制出"测防空"对照想定（真防空导弹，用于与概率损耗版对比）

## 4. 最终想定（i17 attrition）的规模统计

对 `打击lucas-3-8-i17-20260721-2157-attrition.xml`（125 KB）实测解析：

- **5 个 SimEvent**：蓝方-01-发射车周期（RegularTime 1秒 bootstrap）、红方-02-发射小无人机（Time 一次）、红方-03-对陆打击（UnitDetected）、蓝方-01-启动查伤（UnitDamaged）、红方-03-单次对陆打击
- **8 个 Lua 动作脚本**，内嵌合计约 108 KB 脚本：
  - 红方-02 主脚本 47.6 KB（内含 MissionCtrl 任务制 + AttritionCtrl 分段损耗，出现 67 / 38 处）
  - 蓝方-01 发射车生成与周期 30.9 KB（LauncherCtrl，71 处）
  - 红方-01 全局配置 2.1 KB，其余为薄封装/接线小脚本
- 开局磁盘上只有 1 个 ActiveUnit（母平台-1）；**50 辆发射车与 100 架无人机全部由事件 Lua 在运行中生成**
- 运行期由脚本再注册 tick：1s 启动、~5s 释放、~15s 对陆、~30s 发射车周期/光电/航路
