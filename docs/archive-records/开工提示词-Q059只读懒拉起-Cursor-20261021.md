# 开工提示词：Q-059 只读懒拉起——①②段查装备不再要求槽先活着

> 派单：Kimi（监理）2026-10-21 ｜ 施工：Cursor ｜ 级别：P1（owner 拍板方案 A）
> **纯 proxy（JS）改动，不碰 C#/桥/.env/真槽；改完不要重启 proxy（监理统一重启）。**

## 一、背景与 owner 钦定语义

owner 定的槽位生命周期语义：**"用的时候再拉起；面板开/纯聊天不起；跑几个任务起几个"**。

现状缺口：改动类工具（mutating）首次调用已懒拉起（guard.mjs:368/:477，Q-054 实现），但**只读桥调用不拉起**——①②段查装备库（db3k.*）在槽进程全死时直接吃连接失败。①段构想澄清=查装备选型为主，槽全关时基本残废。

**本单任务**：只读桥调用也懒拉起——目标槽进程不在时先拉起再放行。

## 二、改动范围（proxy only）

| 位置 | 改什么 |
|---|---|
| `guard.mjs` 只读路径（:435-437 绑定槽只读、:459-467 未绑定只读） | 放行前确保目标槽进程活着：死了先 `ensureSlotStarted(slot.id)`（幂等，已运行 rc=2 无开销——但注意**不要每次只读都 shell 调 supervisor**，见下"性能约束"） |
| 或 `bridge.mjs` 转发层（二选一，你判断哪层更干净） | 只读转发遇 ECONNREFUSED/桥 down → ensureSlotStarted 后**重试一次**，仍失败按现有错误口径返回 |

**硬约束**：

1. **running 红线不动**：相位 running 的槽只读本来就冻结（A4），本单不得改变；ensureSlotStarted 只许对 idle/无持有者槽。
2. **生产 0 号永不拉起**（现有 ensureSlotStarted(0) 空操作语义保持）。
3. **性能约束**：只读调用是高频路径，不许每次都 fork supervisor 进程。建议方案：进程存活状态做短 TTL 缓存（如 5-10 秒内复用上次探测结果），或采用"转发失败才拉起重试"的被动式（首选——零额外开销于健康路径）。
4. **看护不开**：本单只改拉起逻辑，不启动任何 watch/patrol 常驻（owner 已明令看护默认关）。
5. 排队/租约/防呆（Q-016 槽 DB 注入等）语义一律不动。

## 三、验收标准

1. 新增/扩展测试（挂 test:all 清单**末尾**）：
   - 只读调用遇目标槽进程死 → 触发 ensureSlotStarted（mock 注入断言）且放行/重试一次；
   - running 槽只读 → 仍冻结，**不**触发拉起；
   - 生产槽（id=0）只读 → 不触发拉起；
   - 健康路径（槽活着）→ 零额外 supervisor 调用（被动式天然满足，或 TTL 缓存断言调用次数）；
   - 既有 guard/slotdb/bridge-slots 断言不回归。
2. `npm run test:all` 分半合跑全绿（现基线 305/305；整单命令零输出退出 1 是已知 runner 怪病，分两半跑即可，报告注明）。
3. `git status` 只许碰：guard.mjs 和/或 bridge.mjs、新测试、package.json。
4. 完工报告：改法选择（guard 主动 vs bridge 被动）及理由、测试清单、存疑。
