# 需求记录：控制台支持并行多想定作业

- 提出时间：2026-10-09
- 提出人：owner
- 状态：待讨论（owner 明确要求"记一下，晚点讨论，这个需要加上"）

## 需求原话背景

owner 用两个 Claude Code 窗口同时跑"有 OKF / 无 OKF"对比想定实验时提出：
演示时希望能像命令行双窗口一样，**用控制台同时开两个网页、各自独立做一个想定**。

## 现状限制（为什么现在做不到）

1. **F1 推演程序是单实例单想定**：一台 F1 同一时刻只装载一个想定，第二个想定加载会把第一个顶掉。
2. **AI 桥是单端口 9477**：只绑 127.0.0.1，所有 AI 窗口/面板共用这一个桥入口，没有会话隔离——两个客户端的指令会交叉落到同一个想定上。
3. **控制台面板当前是会话单通道**：对话框没有"想定作业槽位"概念，无法把不同对话路由到不同 F1 实例。

## 可行路线（初步评估，待讨论细化）

| 方案 | 原理 | 优点 | 代价/风险 |
|---|---|---|---|
| A. 多 F1 实例 + 多桥 | 起两份 F1，桥端口用环境变量 `F1_AI_BRIDGE_PORT` 区分（该变量已存在），控制台每个"作业页"绑定一个实例 | 真并行、隔离彻底 | 内存翻倍（单实例约 2GB 级）、要管实例生命周期；F1 是否允许同机双开需实测 |
| B. 单实例 + 作业队列 | 控制台接收多个想定任务但串行执行，网页上只做"排队看进度" | 改动小 | 不是真并行，演示效果打折 |
| C. 单实例 + 会话锁 | 同一时刻只许一个作业页下发指令，其余只读 | 最安全 | 同样不是真并行 |

倾向：若 F1 同机双开可行，走 A；否则 B 作为兜底。需先做"F1 同机双开"可行性实测。
