# F1-AI 迁移部署手册（到新机 D:\ZXY\soft\F1-AI）

2026-10-10 · Kimi 整理 · 用途：在第二台电脑上完整复制「F1-AI + 网页控制台」整套环境，缓解双机打架与蒙特卡洛跑批占机问题。

---

## 一、整套东西的组成（五层）

```
① F1 推演引擎程序     D:\soft\F1-AI\F1\            ← 隔离运行包（F1.exe 及全部依赖 dll）
② F1 数据根           D:\soft\F1\F1-测试\          ← 数据库 DB\、想定 Scenarios\、配置 Config\、导出 EventExport\、Lua 桥
③ AI 面板             D:\soft\F1-AI\demo-ui\       ← 网页源码 + proxy\（AI 直连服务，Node）
④ F1-BS 网页栈        D:\F1BS-run\                 ← EMQX + Redis + Java 后端 + nginx（8085 托管控制台与面板）
⑤ 工作区知识资产      D:\soft\F1-AI\ 根下           ← LabConsole、skills 规矩库、OKF、想定库、全部交接/裁决/方案文档
```

关键连接关系：

- ①和②靠 `F1\WritableRoot.txt` 一个文本文件连起来，里面就一行数据根路径（现在是 `D:\soft\F1\F1-测试`）；
- 桥（9477 端口）随 F1.exe 启动，但必须用 `start-F1-with-bridge.bat` 拉起才会带桥（脚本先从 `LabConsole\workorders\.bridge-token` 读令牌再启动）；
- ③的 proxy（7177 端口）是面板和 AI 模型之间的中转，需要一个大模型 API Key；
- ④只在需要「完整网页控制台/F1-BS 后端」时才要；只用面板 AI 直连功能时，起 nginx + proxy 两件就够。

## 四、路径改写清单（搬完后逐个改）

新机根目录变为 `D:\ZXY\soft\F1-AI`，所有写死的绝对路径要跟着改：

1. **`F1\WritableRoot.txt`** —— 改成新机数据根，如 `D:\ZXY\soft\F1\F1-测试`；
2. **`start-F1-with-bridge.bat`** —— 令牌文件路径、F1.exe 路径两处；
3. **`F1-测试\Config\EventExportExtra.ini`** —— `ExportFolder` 改成新机导出目录；
4. **`demo-ui\proxy\`** —— 检查 `server.mjs`/`tools\` 里的写死路径（桥地址 127.0.0.1:9477 不用改；工作区路径要改）；API Key 重新配；
5. **`D:\F1BS-run\` 若也改盘符** —— nginx `conf\nginx.conf` 的 html 根、Java 后端启动脚本 `run-java.bat`、一键启动 bat 里的五处路径；
6. **LabConsole 里的工具脚本** —— 引用 `D:\soft\F1-AI` 或 `D:\soft\F1` 的地方全局替换。

## 五、首次点火顺序（每步验证后再下一步）

1. 双击改好路径的 `start-F1-with-bridge.bat` → 45 秒后访问 `http://127.0.0.1:9477/invoke` 无令牌应返 401 = 桥活了；
2. F1 界面手动载入一个测试想定、切一次库，确认引擎功能正常；
3. `cd demo-ui && npm install && npm run proxy` → `http://127.0.0.1:7177/health` 返回 `{"ok":true,"hasKey":true}`；
4. （完整控制台）跑一键启动 bat，四端口 1883/6379/9205/8085 全在听 → 开 `http://127.0.0.1:8085/demo/`；
5. 面板发一句大白话测试 AI 直连 → 走通即迁移完成。

## 七、注意

- 桥令牌 `.bridge-token` 随 LabConsole 一起搬，新机不用重新生成；若泄露风险介意，删掉它重启 F1 会生成新的（但本机所有引用要同步换）。
- 两台机器不要同时跑同一个共享盘上的 F1 数据根——数据库和想定都是单写者文件，会打架。各用各的本地副本。
- 蒙特卡洛跑批期间该机的 F1 实例独占，别在它上面同时做想定编辑。
