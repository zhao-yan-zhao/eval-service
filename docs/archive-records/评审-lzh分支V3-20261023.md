## 一、这版是什么

一套完整的**①②段（构想澄清/实验设计）后端子系统**，本地主线完全没有（本地 design/knowledge 文件数=0，他分支 89 个）。核心组件：

- **模式状态机**（design-mode-contract）：把①②段对话分成十种模式（探索/解释/推荐/待决/整版委托/修复/编辑/确认/导出/文档维护），每种模式限定 AI 能写什么——"解释阶段不许改配置""候选未经选择不自动采用"这类规矩**从提示词纪律变成了代码状态机**；
- **文档工作区**（design-document-workspace，402 行）：设计文档不是自由文本，而是"已确认配置的投影"——带哈希绑定，配置变了文档自动标记"已过时"，从机制上防"文档与配置两张皮"；
- **交付审计**（design-delivery-audit）：交付前机器核对"内容完整性/配置已确认/桥可执行"三项；
- **候选登记统一入口**（design.recommend）：AI 提候选必须带证据 ID（evidenceIds），程序持久化编号——**举证从纪律变成接口强制**；
- **证据恢复**（design.evidence）：AI 可按 ID 取回自己查过的原始数据，治"长对话后忘了自己查过什么"；
- **知识检索通道**（knowledge.search/get）：sha256 锁定防资料漂移、1MB 读取预算、目录越界防护、分层检索（装备/平台/经验/战例/判据）——**这就是我们一直缺的 okf.search（Q-015），他造出来了**；
- **意图路由**（intent）：AI 声明"本轮真实意图"，程序核对来源后更新权限；
- 配套：SKILL.md 改 V3（主入口瘦身+五份方法卡 references/ 按需经 design.method 工具读取）、60+ 测试文件随行。

## 二、三个必须先知道的结构事实

1. **分叉点是 10-14**。他之后我们的所有工作（池化、虚报拦截系列、Q-016~Q-058、关的界面合并、③段想定文件铁律、scenario.list、relations/mounts）他分支里**都没有**。两边改了同一批文件（prompts.js、tools.mjs、若干测试、前端 liveProvider/DocView）。**整体 merge 不可行，只能择件。**
2. **运行时未接线**。他分支的 server.mjs 对 design/knowledge 零引用——这套引擎目前只活在测试里（60+ 测试文件全绿不奇怪，因为测的是引擎本体）。接进真实请求流是一个正式工程（要与我们现有的池化、钩子、四段路由共存），不是拷文件能解决的。
3. **SKILL.md 的自包含纪律冲突**。他把方法细节拆到 references/ 五份卡片、经工具按需读取（省 token、治手册肥胖——方向和我们定的瘦身一致），但这违反 _index.md 的"自包含、禁止见 XX 文件"纪律。纪律要不要为此修订，需 owner 裁决。
