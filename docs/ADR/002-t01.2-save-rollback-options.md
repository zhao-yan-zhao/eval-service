## 方案 1 — 文件级：导出 XML → 改一处 →（可选）只验证备份回滚文件

**怎么做**  
用已验证的 `-R/-C` 导出 XML；改一个无害字段（例如标题 `TEST` → `TEST-T012`）；  
「回滚」= 用改前复制的 `.scen` 覆盖工作副本；再用 `-R/-C` 看标题是否恢复。  
**本方案若不去压回 .scen，则「保存」只等于改了 XML，不能证明 F1 保存引擎。**

**好处**：快、少踩注册/挂起；和 T01.1 同一路径。  
**坏处**：**几乎证明不了** TASKS 里的无对话框 `SaveScenario`。  
**风险**：容易让人误以为「保存已通」。  
**推荐度**：不推荐作为 T01.2 主方案（顶多当对照实验）。

## 方案 2 — 推荐：`poc/` 小工具调用 F1-Core 保存（不改 Console 源码）

**怎么做**  
1. 工作副本复制三份 attempt；每份先记 **基线 hash**  
2. 新建 `poc/T01.2/` 控制台小程序（或脚本+现有 DLL）：加载工作副本 → 用**写死的一条**受控改动（例如改场景标题，或微调某个单位坐标 0.001 度）→ 调用 Core 的 `LoadSave.SaveScenario` / 等价无 UI 保存写回**同一工作副本路径**  
3. 再 `-R/-C` 或再次加载，确认摘要变了（fingerprint/hash 变）  
4. 用基线文件覆盖工作副本 = 回滚；再加载，hash/标题回到基线  
5. 以上整段连续做 3 次；原始 `TEST-MINI.scen` 始终只读核对 hash  

**好处**：最贴近 T01.2 / E04「无 UI 保存」；不改 F1-Console / 生产业务代码结构。  
**坏处**：poc 要处理 GIS/`WritableRoot`、依赖 DLL；可能再次遇到进程挂起，需超时强杀。  
**风险**：Core 初始化比纯 `-C` 重；若保存失败要如实记阻塞，不能降级成「只改 XML 也算过」。  
**推荐度**：**推荐**。
