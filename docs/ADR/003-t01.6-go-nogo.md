## ③ 线程信息模型（源码 + 实测）

### F1 产品路径（源码）

```text
BackgroundWorker BW_Core_Pulse.DoWork
  → Run1Turn → Advance1Pulse   （后台/非 UI 线程）
  → onAdvance1Pulsed
       → BW_Core_Pulse.ReportProgress(0)   （封送到 UI）
  → ProgressChanged → 刷新界面控件         （UI 线程）
```

依据：`Command_Core/ClientCore.cs`（`BW_Core_Pulse_DoWork`）、`Command/Client.cs`（`onAdvance1Pulsed` → `ReportProgress`；`bW_Core_Pulse_ProgressChanged`）。

### 本轮 PoC 实测（headless 脉冲进程）

| 回调 / 位置 | ManagedThreadId |
|---|---|
| `Advance1Pulse` 调用方 | 1（该进程主线程；无 WinForms 泵） |
| `TimeAdvanced` | 1（与调用方同线程） |
| `onAdvance1Pulsed` | 1（与调用方同线程；**未**自动封送） |
| 心跳 UI 进程 | 独立进程 UI 线程（`formal-beats.txt.meta.txt`） |

### 界面更新要求（硬约束）

1. **脉冲不得堵在 UI 线程**（真实 F1 走 `BW_Core_Pulse`；助手驱动应对齐）。
2. **禁止**在脉冲线程直接碰 WinForms 控件；必须 `ReportProgress` / `BeginInvoke` / 等价封送。
3. `TimeAdvanced` / `onAdvance1Pulsed` 默认在**调用方线程**触发；若要改 UI，调用方须自行封送。

## ④ 结论

| 问题 | 答案 |
|---|---|
| 100 脉冲下心跳连续丢失 >2s？ | **否**（max 264ms） |
| M3「跑推演时界面不卡死」PoC 闸门？ | **通过** |
| **Go / No-Go** | **Go**（建议进入阶段二；实现须后台脉冲 + UI 封送） |

### 已知局限（不挡 Go，写入能力矩阵「路径」）

- 同进程「WinForms STA + F1-Core 加载」PoC（`T016UiHeartbeatPoc`）曾 NRE（`GetPersonnelCargoValues`）；正式测量改用**双进程**隔离。产品嵌入应复用 F1 既有初始化顺序，勿在未初始化完成时抢 UI 泵。
- 本轮未在真实 `F1.exe` 内嵌助手面板上测心跳（面板尚未做）；测的是「脉冲负载并行下 STA 消息泵可维持 ≤2s」+ 源码线程契约。
