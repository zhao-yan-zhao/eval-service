# 双引擎想定交接与态势同步 v1 修改记录

日期：2026-10-19  
范围：AI 控制引擎 `D:\F1-AI\F1`、AI 面板/代理、F1 B/S 显示引擎 `D:\F1BS-run\F1`

## 一、目标与边界

本版采用“双引擎、单运行权威”的交接模式：AI 控制引擎负责根据实验设计生成并保存想定；操作员在阶段 3 点击独立的“交接至显示引擎”按钮后，代理把已保存的 `.scen` 原子复制到显示引擎想定目录，启动 F1 B/S 显示引擎，再把运行标识、MQTT 地址和想定名交给嵌入页面。交接完成后，战场态势显示以 B/S 显示引擎为权威。

本版不修改两个 F1 引擎二进制，不尝试让两个引擎同时执行同一场推演，也不做帧级双向状态复制。

## 二、关键流程

1. 阶段 3 的 AI 必须以带 `path` 的 `scenario.save` 明确另存最终 `.scen`。
2. 代理记录任务、轮次、源路径、文件大小、修改时间和 SHA-256。
3. 操作员点击“交接至显示引擎”时，服务端执行交接但不推进阶段；“确认本段完成”只负责阶段推进，两项操作互不绑定。
4. 交接服务从 `D:\F1-AI\F1\WritableRoot.txt` 自动读取当前引擎写入根（本机为 `D:\F1\Scenarios`），同时兼容历史候选目录 `D:\F1-AI\F1-测试\Scenarios`，并要求扩展名为 `.scen`。
5. 文件先复制为临时文件，校验源/目标 SHA-256 一致后再原子改名到 `D:\F1BS-run\F1\Scenarios`。
6. 调用 `http://127.0.0.1:9205/deduction/scenarioSchema/startEngine?runMode=0` 启动显示引擎。
7. 生成包含 `runGuid`、`mqttIp`、`mqttPort`、`scenarioName`、`handoffId` 的 B/S 编辑器深链。
8. B/S 页面处于 `mode=attach` 时，覆盖本标签页旧会话并附着指定引擎，禁止再次调用 `startEngine`。
9. B/S 页面通过 `postMessage` 回报“引擎已接管、MQTT 已连接、Lua 通道已连接、想定已加载”等状态；AI 面板校验来源与 `runGuid` 后显示。
10. 任何交接失败都会写失败清单并保持当前显示状态，不会误报交接成功；阶段确认仍可独立处理。
11. 嵌入的 B/S 页面不再覆盖透明点击层，鼠标、滚轮和键盘事件可直接进入显示窗口；仍保留“打开完整界面”入口。

## 八、已知限制

- v1 是文件级交接，不会把交接后 AI 引擎中的继续修改实时同步到已运行的 B/S 引擎；如需继续修改，须重新保存并再次交接。
- B/S 返回“想定已加载”后才标记态势已同步；页面 HTTP 可达不等于实况接入。
- 目前不自动关闭旧的 B/S 引擎实例；重复交接会创建新版本和新运行实例，便于审计但需后续增加实例回收策略。
